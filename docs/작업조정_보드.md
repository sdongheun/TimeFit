# TimeFit 작업 조정 보드

> 모든 작업 세션이 읽는 **현재 상태·의존성 색인**이다. 상세 지시·구현 기록을 이 파일에 복제하지 않는다.
>
> 상태 기준일: 2026-08-25

## 운영 방식

| 상황 | 기록 위치 | 기록할 내용 |
| --- | --- | --- |
| 여러 역할이 순서·입출력 계약을 공유 | 이 보드 | 작업 ID, 담당, 상태, 선행 조건, 완료 산출물 링크, 결정 필요 사항 |
| 통합·결정과 하나의 역할만 소통 | 역할 고유 작업기록 | 상세 명령, 구현·검증 결과, 다음 인계 |
| 정책 충돌·사용자 결정 | 제품 기준 문서와 통합·결정 기록 | 결정 ID, 이전 방식·문제·교체 방식·이유·상태 |

- 이 보드는 작업 지시 본문을 담지 않는다. 상세 내용은 역할 문서의 해당 작업 ID로 연결한다.
- 완료한 항목은 요약 한 줄과 산출물 링크만 남긴다. 과거 완료 기록을 삭제하거나 다른 역할 문서로 대량 이관하지 않는다.
- 새 역할 고유 작업기록은 그 역할에 첫 직접 명령이 생길 때만 만든다. 빈 문서를 미리 늘리지 않는다.
- 한 작업은 한 역할만 수정한다. 다른 역할의 변경이 필요하면 이 보드에 `대기`와 필요한 공개 계약을 적는다.
- 통합·결정의 수락 검토는 `수락/보완 필요`만 말하고 끝내지 않는다. 수락이면 즉시 다음 작업의 ID·담당·선행 조건·사용자 결정 필요 여부를 함께 제시한다. 보완이 필요하면 새 suffix 작업을 만들지 않고 가능한 한 현재 활성 작업의 완료 기준에 흡수한다.

## 실행 우선순위와 게이트

- 추천 결과의 시간·운영시간·경로 정확성, 사용자 데이터·비용의 실제 손상, 보안 우회는 해당 기능의 **출시/활성화 차단**으로 다룬다.
- 활성화 전용 보완은 원칙적으로 추천 엔진의 순수 계산, 고정 fixture, UIUX의 화면·체감 개선을 멈추게 하지 않는다. 단, 보완 전제에 의존하는 런타임 전환만 보류한다.
- 각 세션은 먼저 고정 입력으로 동작하는 최소 구현과 회귀 테스트를 끝내고, 드문 장애·운영 자동화·관찰 보완은 별도 작업 ID와 활성화 조건으로 분리한다. 새 예외를 한 작업에 계속 누적하지 않는다.
- 통합·결정은 발견 위험의 영향 범위(추천 정확성 / 사용자 데이터·비용 / 외부 API 활성화 / 후속 개선)를 기록하고, 핵심 추천·UX 작업을 불필요하게 대기시키지 않는다.

## 작업 명령 완결성 원칙

- 통합·결정은 작업을 지시할 때 구현 범위만 적지 않는다. 정상 경로, 가장 비용·정확성·보안 영향이 큰 실패 경로, fallback/재시도 상한, cache·상태 전이, 외부 의존 실패, 공개 계약과 변경 금지 경계를 **같은 작업 ID의 완료 기준**에 함께 쓴다.
- 행동을 보장해야 하는 작업은 source 문자열 검사만 완료 근거로 삼지 않는다. 고정 fixture에서 실제 공개 entry를 실행하고 입력·반환값·부수효과 횟수(요청, cache write, lease, 저장 등)를 검증하도록 지시한다. 불가피하게 source 계약만 가능한 부분은 지시 단계에서 명시하고, 활성화 조건과 분리한다.
- 다음 작업에서야 발견될 수 있는 미정 사항은 “후속 보완”으로 막연히 남기지 않는다. 구현 전 확인 가능한 반례라면 현재 작업의 필수 fixture에 넣고, 계정 승인·배포·실기기처럼 지금 확인할 수 없는 항목만 별도 활성화 게이트로 남긴다.
- 작업자는 완료 기록에 변경 파일, 변경하지 않은 공개 경계, 실행한 검증과 결과, 남은 활성화 조건을 남긴다. 통합·결정은 이 네 항목과 최초 완료 기준을 대조한 뒤에만 수락한다.

## 보드 작성과 세션 시작

### 보드 작성자 경계

`docs/작업조정_보드.md`는 여러 역할의 상태를 한 표에 모으므로 **통합·결정 세션만 수정하는 단일 작성자 파일**이다. 데이터·추천 엔진·외부 API·UIUX·DB·QA 세션은 이 보드를 읽어 자신의 작업 ID와 상세 문서를 찾지만, 상태·링크·최근 완료 요약을 직접 고치지 않는다.

각 작업 세션은 자기 역할의 상세 작업기록에만 변경 파일, 유지 경계, 테스트 결과, 다음 결정·위험·재현 조건을 남긴다. 완료 사실은 통합·결정에 인계하고, 통합·결정이 상세 기록을 검토한 뒤 보드 상태를 한 번 갱신한다. 긴급 차단 사항도 보드를 직접 고치지 않고 작업기록의 인계와 함께 알린다.

새 작업 세션은 아래 순서로 읽고, 보드만 읽은 뒤 구현을 시작하지 않는다.

1. 루트 `AGENTS.md`와 [문서 안내](README.md)를 읽는다.
2. 이 보드에서 자기 역할의 `진행 예정` 또는 `진행 중` 작업 ID를 찾는다.
3. 해당 행의 **상세 작업기록 링크**와 역할 기준 문서를 읽는다.
4. 자기 소유 경로와 완료 기준이 맞을 때만 구현한다. 링크가 없거나 담당이 불명확하면 수정하지 않고 통합·결정에 인계한다.

통합·결정 세션이 다른 세션에 보내는 최소 지시는 다음 형식을 쓴다: `docs/작업조정_보드.md를 읽고, [작업 ID]의 상세 작업기록과 역할 기준 문서를 확인한 뒤 자기 소유 경로와 상세 작업기록만 수정하라. 보드는 수정하지 말고 완료 인계를 상세 작업기록에 남겨라.`
