- 제품 정책의 실제 경로 주변 생활권 범위를 전부 평가한 `route_verified_measurement` fixture는 아직 없다. 현재 500m 실경로 결과는 `route_verified_diagnostic_slice`로만 보존하며, 제품 공급량·0개율·보강 우선순위의 근거로 사용할 수 없다.
- 500m 장소쌍 스냅샷의 수집 당시 메타데이터에는 과거 `정책 반경` 표현이 남아 있다. 응답 좌표·시간은 유효한 고정 fixture이나, 다음 실제 경로 범위 수집 전에 메타데이터 생성 경로를 진단 slice 용어로 통일해야 한다.

### 범위 밖의 기존 변경

- `docs/03_product/`, `docs/README.md`, `docs/테스트.md`의 기존 변경은 통합·결정 역할 소유로 보고 읽기만 했으며 수정하지 않았다.
- `docs/테스트.md`의 `DATA-19~24` 상태는 아직 `미착수`이나, 데이터 계약 테스트 `test/evidence-profile-classification.test.mjs`가 해당 계약을 16개 검사로 이미 검증한다. 통합·결정 역할이 이 증거를 확인한 뒤 요구사항 상태만 갱신해야 하며, 데이터 세션이 상태 문서를 직접 바꾸지 않는다.
- 제품 문서는 실제 경로 주변 생활권을 현행 후보 성격으로, 일부 기존 UI·테스트 문서는 기본 1km·최대 8km 구현 기록으로 남긴다. 이는 구현 전환 상태의 충돌이므로, 데이터 세션은 어느 쪽도 공급량 측정의 정책 범위로 임의 채택하지 않는다.
- UI(`src/ui/`), 추천 엔진(`src/engine/`), 외부 API 어댑터, Supabase migration은 건드리지 않았다.
