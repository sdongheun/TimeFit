## 0. 한 장 결론 (먼저 읽기)

1. **14개 테이블 = 여행 1건을 중심으로 방사형**으로 연결(여행객→여행→방문지→이동/활동/소비/사진).
2. 시간-적합에 직접 쓰는 **핵심 2테이블**: `tn_visit_area_info`(체류·좌표·순서), `tn_move_his`(도착시각·이동수단).
3. ⭐ **시간-적합 수식 검증(Phase B)은 가능하다** — 여행별 방문 순서 + 구간 도착시각으로 **실제 타임라인 재구성 가능(인접쌍의 90.5%)**.
4. ⚠️ **그러나 모든 시각이 30분 단위로 반올림**(도착시각 100%가 :00/:30, 체류도 30분 버킷)돼 있다. → **분(分) 단위 정밀 이동시간 검증은 불가**. 재구성 이동시간의 **50%가 0 이하**로 나옴(반올림 상쇄). **Phase B는 개별 구간 대조가 아니라 "집계·분포·총량" 검증으로 설계해야 한다.**

## 2. 조인 구조 (여행 1건 재구성 방법)

```
tn_traveller_master ─(TRAVELER_ID)─ tn_travel ─(TRAVEL_ID)─┬─ tn_visit_area_info  (방문지 N개, VISIT_ORDER 순)
                                                            ├─ tn_move_his         (구간 N개)
                                                            ├─ tn_activity_his
                                                            └─ tn_*_consume_his / photo / companion
```

**⭐ 핵심 복합키:** `TRAVEL_ID | VISIT_AREA_ID`
- `VISIT_AREA_ID`는 **여행 내 순번**이라 여행자 간 충돌 → 반드시 `TRAVEL_ID` 동반.
- 도착시각 조인: `tn_move_his`의 `(TRAVEL_ID, END_VISIT_AREA_ID)` → `END_DT_MIN`을 방문지에 붙임.
- (이 버그를 과거 `build_dwell.mjs`에서 자기검증 테스트가 잡음 — 단독 조인 1,877 → 복합키 30,048.)

## 4. ⭐ 시간-적합 검증(Phase B) 실현성 판정

### 이동시간 재구성 방법 (START_DT 없이)
```
구간이동(i→i+1) = 도착_(i+1) − 도착_i − 체류_i
   도착_x : tn_move_his.END_DT_MIN  (복합키로 방문지에 붙임)
   체류_i : tn_visit_area_info.RESIDENCE_TIME_MIN
```

### 프로브 결과 (`probe_chain.mjs`, train)
| 지표 | 값 |
|---|---|
| 방문 ≥2인 여행 | 2,560 / 2,560 (전부) |
| 총 인접 방문쌍 | 26,832 |
| **도착+체류로 이동시간 재구성 가능** | 24,270 (**90.5%**) |
| 그중 이동시간 **양수(0~600분)** | 13,484 (**50.3%**) |
| 양끝 좌표 보유(거리 대조 가능) | 18,890 (70.4%) |

### ⚠️ 양자화(30분 반올림)의 영향 — 결정적
- **도착시각 100%가 :00 또는 :30** (51.9% / 48.1%). 체류시간도 30분 버킷.
- → 재구성 이동시간 = (30분 반올림된 도착 간격) − (30분 반올림된 체류). **절반이 0 이하**로 튐(짧은 이동이 반올림에 먹힘).
- **결론: 개별 구간을 TMAP/haversine과 1:1 대조하는 검증은 불가.** 노이즈(±30분)가 신호(도보 5~20분)보다 큼.

### 그래서 Phase B는 이렇게 설계한다 (집계·분포·총량)
1. **Q1 이동(집계)**: 개별 대조 대신 **거리 구간(bin)별 실측 이동시간 중앙값** vs haversine 추정 — 다수 표본으로 반올림 상쇄(대수의 법칙). 양수 구간만 사용.
2. **Q2 체류(분포)**: 카테고리별 실측 분포가 우리 중앙값을 뒷받침하나 + cat3 세분화 이득.
3. **Q3 버퍼**: **여행 하루 총량**(Σ실측 이동+체류)의 분포로, 우리 공식 총합 대비 초과율 → 10~15% 버퍼가 p몇을 커버.
4. **Q4 코스 실현성**: 실제 다구간 코스(정답)를 우리 엔진 총량이 체계적으로 과소/과대 추정하는지(bias) — 반올림은 여행 단위 합산에서 상당부분 상쇄.

> 핵심 전환: 이 데이터는 **"이 구간 몇 분?"의 정밀 검증기가 아니라, "우리 공식이 현실의 총량·분포를 편향 없이 맞추나"의 타당성 검증기**다. 그 목적엔 충분하다.
