# AI-Hub 카테고리별 체류시간 분포

> 상태: **근거 데이터**. 현재 추천 화면의 체류시간 정책은 [추천로직](../03_product/추천로직.md)을 따른다.
>
> 생성 기준: `data/aihub_donbu/training`, `validation`의 `tn_visit_area_info`를 `scripts/build_dwell.mjs`와 같은 필터로 집계한 2026-08-23 결과.

## 1. 이 문서가 답하는 것

현재 자투리 활동 카탈로그의 권장 체류 `30분`이 임의의 숫자인지 확인할 수 있도록, AI-Hub 원본에서 활동 대응 카테고리별 체류시간 분포를 기록한다.

이 표의 `건수`는 **고유 사용자 수가 아니라 방문 기록 수**다. 한 여행자가 여러 장소를 방문하면 각각 한 건으로 집계되므로, “30분 이용자가 몇 명”이 아니라 “30분으로 기록된 방문이 몇 건”으로 해석해야 한다.

## 2. 집계 범위와 필터

- 원천: AI-Hub 국내여행로그 동부권, training + validation.
- 전체 방문 레코드: `32,930건`.
- 집계 사용 레코드: `21,752건`.
- 제외: 집·친구/친지집·사무실·숙소 코드, 체류시간 `0분 이하` 또는 `1,440분 초과` 레코드.
- 카페: AI-Hub 코드 `11`(식당/카페 통합) 중 장소명에 `카페`, `커피`, `베이커리`, `제과`, `디저트`, `빵`, `브런치`, `로스터리` 등의 키워드가 있는 방문 기록을 분리했다. 따라서 카페 수치는 완전한 업종 분류가 아니라 재현 가능한 이름 기반 분리 결과다.

## 4. 해석과 정책 경계

1. 다섯 원천 카테고리 모두 `30분`이 최빈값이다. 따라서 권장 체류를 30분으로 통일하는 데에는 원본 데이터 근거가 있다.
2. 자연관광지·상업지구·문화시설·카페는 중앙값이 60분이다. 이는 장시간 체류 기록도 적지 않다는 뜻이지, 자투리 앱이 60분을 반드시 배정해야 한다는 뜻은 아니다.
3. 현재의 `최소 20분 / 권장 30분 / 최대 60분`, 문화시설 최대 `120분`은 다음을 결합한 **제품 정책**이다.
   - 권장 30분: 위 최빈값 근거.
   - 최소 20분과 최대 상한: 1~2시간 자투리 활동 범위를 위한 서비스 정책. AI-Hub에서 직접 추출한 값이 아니다.
4. 이 데이터는 동부권 여행로그의 방문 기록이며, 부산 시민 전체 또는 장소별 실제 운영시간·대기시간을 보장하지 않는다. 따라서 운영시간과 실제 이동시간은 별도 게이트로 계속 검증해야 한다.

## 5. 재현 방법

기본 통계는 아래 명령으로 다시 생성할 수 있다.

```bash
node scripts/build_dwell.mjs
```

현재 분포 표는 위 스크립트와 동일한 CSV 파서, 제외 규칙, 카페 이름 분리 규칙을 사용해 산출했다. 분류 키워드나 제외 규칙을 바꾸면 이 문서의 표와 함께 `카테고리별_체류시간.json` 및 추천 정책 근거를 다시 검토해야 한다.
