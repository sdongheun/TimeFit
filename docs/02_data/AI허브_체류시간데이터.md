> **표본:** 동부권 모집 여행자 2,880명(전국 ~1.6만), **20~40대 85%·여 58% 편중** → 절대값보다 상대비·카테고리 폴백.

**최신성(2024-12) 결론**: 체류시간·혼잡패턴은 저속변화 행동상수라 baseline으로 **적합**. 진짜 약점은 최신성이 아니라 ① 휘발형 POI(음식점·카페) 폐업(2024 폐업률 18.2%) → TourAPI 라이브 검증 후 노출 ② 표본편향·롱테일 → 카테고리 폴백·4권역 union. (멀티에이전트 `data-staleness-check` A2·A3 근거)

## 2. 핵심 테이블 `tn_visit_area_info` (1행=1 POI 방문 이벤트)

```
TRAVELER_ID → TRAVEL_ID → VISIT_AREA_ID (방문지정보) ★핵심
   └ 이동/소비/활동/사진/GPS (TRAVEL_ID·VISIT_AREA_ID 조인) + POI Master(좌표·명)
```

| 목적 | 필드 | 신뢰도 |
|---|---|---|
| 방문지명 | `VISIT_AREA_NM` | ★확인 |
| 좌표 | `X_COORD`/`Y_COORD` | ★명 / ☆좌표계(WGS84 vs TM) |
| 카테고리 | `VISIT_AREA_TYPE_CD` | ★확인 |
| **체류시간(분)** | `RESIDENCE_TIME_MIN` | ★동/서/제, ☆수도권 |
| 방문 시작/종료 일자 | `VISIT_START_YMD`/`VISIT_END_YMD` | ★확인 |
| 방문 시작/종료 **시각** | `VISIT_START_HMS`/`_AT`/`_DTM` 류 | ☆**추정·핵심검증점** |
| 만족도(1~5) | `DGSTFN` | ★교차확인 |
| 재방문/추천의향 | `REVISIT_INTENTION`/`RCMDTN_INTENTION` | ☆추정 |

## 4. 추출 파이프라인 (구현 예정)

```
[1] 다운로드  내국인 인증 → 4권역 신청·승인 → 분할압축 병합 → tn_visit_area_info 추출
[2] 파싱      권역 union(권역컬럼 추가), VISIT_AREA_ID 정규화
[3] 매핑      VISIT_AREA_TYPE_CD(+TC_CODEB) → TimeFit 카테고리 lookup
[4] 클리닝    RESIDENCE_TIME_MIN 이상치 제거(0분/숙박 초장시간 캡), 좌표 NaN 제거,
              시각차(END−START) vs 직접필드 불일치 플래그
[5] POI 정규화 VISIT_AREA_NM+좌표 클러스터링 → 고유 POI_ID
[6] 체류 집계  카테고리/POI별 count·mean·median·p25·p75
[7] 요일×시간대 YMD→요일/계절, 시각(or 사진/GPS)→hour bucket → 혼잡배수 매트릭스
[8] 산출      category_dwell.json / poi_dwell.json / congestion_matrix.json
```

## 12. 부산 매칭 검증 — TourAPI `areaBasedList2` ↔ AI-Hub 체류시간 (`scripts/match_busan.mjs`)

> 부산 필터: AI-Hub 주소 '부산' / TourAPI `areaCode=6`. 매칭: 정규화 이름 일치 OR 좌표 근접(<150m).

**모수**
- **TourAPI 부산 829건** (관광지 170 · 음식점 370 · 숙박 80 · 쇼핑 58 · 문화시설 50 · 레포츠 39 · 축제 39 · 여행코스 23)
- **AI-Hub 부산: 방문 4,288건 → 고유 POI 1,826개** (체류시간 보유)

**양방향 매칭 결과**
| 방향 | 매칭 | 의미 |
|---|---|---|
| ① AI-Hub 체류 POI → TourAPI | 1,826 중 **1,149 (62.9%)** | 측정한 부산 체류 POI의 63%가 TourAPI에도 존재 |
| ② TourAPI 부산 POI → AI-Hub 체류 | 829 중 **486 (58.6%)** | **TourAPI 후보의 58.6%는 직접 측정 체류시간, 41.4%는 카테고리 폴백** |

(이름 일치 118 / 좌표<150m 1,142 → 좌표 매칭이 주력. 이름은 지점명·표기차로 낮음)

**핵심 해석**
- 표본 4,000명짜리 데이터인데도 **TourAPI 부산 후보의 약 60%에 직접 실측 체류시간**을 붙일 수 있다 — 여행자가 유명 POI에 집중하고, 그게 곧 앱이 추천할 POI라 겹침이 크다.
- 상위 매칭 = 부산역·광안리·해운대·국제시장·전포카페거리·흰여울문화마을 등 **앱이 추천할 핵심 명소와 정확히 일치**.
- 나머지 ~40%는 카테고리 폴백(§9 테이블)으로 자연 처리 → **하이브리드(POI 직접 + 카테고리 폴백)가 부산에서 실증됨.**
- 동부권 단독 결과 → **4권역 union + 이름매칭 보강 시 커버리지 상승** 여지.

**산출물**: `data/aihub_donbu/busan_match.json`
