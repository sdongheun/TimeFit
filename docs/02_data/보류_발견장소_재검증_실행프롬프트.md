# TimeFit 보류 발견 장소 재검증 실행 프롬프트

> 대상 역할: **데이터 정제 세션**
>
> 목적: 기존 `hold` 중 “활동 유형 또는 짧은 방문 적합성을 공식 문구만으로 확정할 수 없다”는 이유로 보류된 약 140개를 재검토한다. 관광·자연·거리·문화 장소를 무조건 제외하지 않고, 짧은 시간의 완결된 활동으로 설명 가능한 장소를 근거와 함께 `representative_standard` 또는 `conditional_more`로 분류한다.
>
> 상태: **재검증 지시**. 장소 수 확대가 목표가 아니며, 기존 `hold`를 일괄 승격하지 않는다.

## 배경: 이번 재검토가 필요한 이유

현재 `hold`에는 음식점·숙박·교통·의료·주차, 예약 필수·장기 이용 시설처럼 추천 대상에서 제외하는 것이 타당한 장소가 있다. 그러나 그와 별도로 **“활동 유형이나 짧은 방문 적합성을 공식 근거로 판정할 수 없다”**는 사유만으로 보류된 약 140개가 있다.

이 보류군에는 아래와 같은 장소가 포함된다.

| 기존 분류 | 예상 수 | 예시 |
| --- | ---: | --- |
| 자연관광지 | 87 | 회동수원지, 가덕도 등대, 금련산·황령산·장산, 해운대, 산복도로, 사찰·계곡, 체험마을 |
| 문화시설 | 28 | 누리마루 APEC하우스, 국립부산과학관, 임시수도기념관, 부산타워, 기념관·전시관·공연장 |
| 상업지구 | 24 | 전포공구길, 부산대학교 앞, IKEA 동부산점, 밀락더마켓, 면세점, 공구·자재 상가 |
| 레저/스포츠 | 1 | 문탠로드 |

제품 의도상 전망·산책·거리 탐색·짧은 전시 관람처럼 사용자가 남는 시간에 들를 수 있는 장소는 후보가 될 수 있다. 따라서 이번 재검토의 질문은 **“공식 원천이 짧은 방문을 직접 표현하지 않았는가”가 아니라, “이 장소를 20~60분의 완결된 활동으로 정직하고 안전하게 설명·시간 검증할 수 있는가”**다.

사용자가 현장에서 최종 판단할 수 있다는 점은 `conditional_more` 탐색의 근거가 될 수 있다. 하지만 대표 추천은 엔진이 1~3곳 코스를 정해 주는 기능이므로, 사용자 판단만으로 운영시간·범위·이용 부담이 불명확한 장소를 자동 승격해서는 안 된다.

## 2. 대상 추출과 분류 원칙

대상은 아래 조건을 모두 만족하는 `hold`다.

```text
기존 재검토 행동 또는 hold 사유가
“공식 소개 원문으로 활동 유형과 짧은 방문 완결성을 사람 검토한다”에 해당
그리고 음식 중심 장소, 숙박, 교통, 의료, 주차, 명백한 장기 이용 시설,
동일 장소 중복/권역 내부 시설, 만료 행사가 아님
```

예상 대상은 자연관광지 약 87개, 문화시설 약 28개, 상업지구 약 24개, 레저/스포츠 약 1개다. 수는 시작 시 ID 목록으로 다시 고정하며, 예상 수와 달라지면 차이를 보고한다.

### 2-1. 핵심 해석 규칙

**공식 원천에 “짧게 방문하기 좋다”는 문구가 없다는 사실만으로 `hold`를 유지하지 않는다.** 다음의 검토 근거를 `activity_template` 또는 `area_specific` 근거로 기록할 수 있다.

- 공식 소개·관리 주체 안내에서 확인되는 전망, 산책, 거리 탐색, 전시 관람, 외부 공간 방문 성격
- 장소 범위와 입구·전망점·짧은 산책 구간을 특정한 사람 검토
- 기존 AI-Hub 활동 템플릿과 일치하는 최소·권장 체류 범위

그러나 리뷰 수, 블로그·후기 문구, 소비 추정, AI의 무근거 설명만으로 승격하지 않는다.

### 2-2. 넓은 장소의 처리

`해운대`, 산 전체, 대형 공원, 산복도로, 체험마을처럼 범위가 넓은 이름은 전체를 “20분 방문”으로 취급하지 않는다.

다음 중 하나가 있어야 한다.

1. 기존 공식 장소 좌표가 실제 진입점·전망점·짧은 산책 구간을 의미한다는 근거
2. 별도 대표 지점(입구, 전망대, 해안 산책 시작점)을 공식 원천 ID·좌표와 함께 새 대표 장소로 정의
3. 짧은 방문 범위를 특정할 수 없으면 `hold` 유지

새 대표 지점을 만들 때 기존 권역과 중복 추천되지 않도록 `siteGroupId`·범위 관계를 함께 기록한다.

### 2-3. 시설·상업 장소의 처리

아래는 일반적인 관광/상업 분류만으로 승격하지 않는다.

- 예약 필수, 회차·공연·체험 프로그램 의존 장소
- 입장 마감·휴관일·대기 부담을 구조화할 수 없는 문화시설
- IKEA·대형 복합시설·면세점처럼 최소 체류가 짧다고 설명할 수 없는 대형 시설
- 공구·자재 상가처럼 일반 사용자가 짧은 탐색 활동을 완결할 근거가 없는 장소

반대로 거리·골목·전망 시설·기념관·소규모 전시·공개 산책 공간은 다음 등급 규칙으로 판정한다.

## 3. 등급 판정

| 결과 | 조건 |
| --- | --- |
| `representative_standard` | 장소 동일성, 짧은 활동 설명/체류 템플릿, 운영 가능성이 확인됨. 예약·프로그램 의존이 아니고, 전체가 아닌 짧은 방문 범위가 명확함. |
| `conditional_more` | 동일성·짧은 활동 설명·체류 범위는 충족하지만 운영 가능성만 `unknown`. 더보기 전용이며 대표 후보로 승격하지 않음. |
| `hold` 유지 | 짧은 방문 범위가 불명확, 최소 체류가 긴 시설, 예약/프로그램 의존, 운영시간 충돌·해석 불가, 중복/내부 장소, 활동 완결성 부족. |

`representative_core`로의 승격은 이 작업 범위가 아니다. 장소별 관측 체류 등 더 강한 근거가 새로 확보된 경우만 통합·결정 세션에 제안한다.

## 4. 장소별 필수 기록

모든 대상 ID에 다음을 기록한다.

```text
placeId / 기존 분류·사유 / 장소 범위(point·area·route)
검토한 짧은 활동(예: 전망, 20~30분 산책, 거리 탐색, 전시 일부 관람)
활동·체류 근거와 원문 / 운영 가능성 원천·적용 범위
예약·입장·대기 부담 / siteGroup·내부 장소 관계
새 분류 / 판정 이유 / reviewDueAt / 다음 검토 행동
```

“갈 만하다”, “관광지다”, “사용자가 판단한다”만으로는 판정 근거가 아니다. 사용자 판단은 더보기 탐색의 보조 수단이며, 대표 추천의 시간 안전 조건을 대체하지 않는다.

## 5. 실행 순서

1. 대상 ID 전수 목록과 기존 `hold` 사유를 스냅샷으로 고정한다.
2. 자연관광지 → 문화시설 → 상업지구 → 레저 순으로 검토한다.
3. 먼저 기존 공식 원천·좌표·운영시간 감사·AI-Hub 체류 템플릿을 사용한다. 원천이 이미 있으면 외부 재조회하지 않는다.
4. 기존 원천으로 범위·운영시간을 해소할 수 없는 장소만 공식 관리 주체 원천을 소수 재확인한다. 카카오·블로그는 승격 근거가 아니다.
5. 원천 충돌이나 범위 불명확은 보수적으로 `hold` 또는 `conditional_more`로 남긴다.
6. 검토 원천에서 카탈로그를 재생성하고, 런타임에는 `core/standard/conditional_more`만 들어가는지 검사한다.

## 6. 완료 기준

아래를 모두 만족했을 때만 완료다.

1. 시작 시 고정한 모든 대상 ID가 정확히 하나의 결과(`standard`, `conditional_more`, `hold`)를 받는다.
2. 승격 장소 100%가 짧은 활동 범위와 체류 근거를 가진다. 넓은 장소는 대표 지점 또는 짧은 구간이 명시돼 있다.
3. `standard` 승격 장소 100%가 구조화 가능한 운영 가능성 근거를 가진다.
4. `conditional_more`는 운영 가능성 미확인만이 자동 추천 불가 사유다.
5. 음식·숙박·교통·의료·주차·예약 필수·프로그램 의존·중복/내부 장소가 후보 부족을 이유로 승격되지 않는다.
6. 재생성 뒤 데이터 계약 테스트와 기존 런타임 카탈로그 테스트가 통과한다.
7. 아래 감사 문서를 새로 작성하고, 전후 수와 장소 ID별 판정표, 승격/보류 상위 사유, 생활권·활동 분포 변화를 남긴다.

```text
docs/02_data/보류_발견장소_재검토_감사.md
data/processed/review/보류_발견장소_재검토_결과.json
```

감사 문서는 최소한 `재검토 배경과 질문`, `대상 ID 대조`, `자연/문화/상업/레저별 판정 기준`, `대표적인 승격·조건부·유지 사례`, `전후 분류 수`, `실행 명령·테스트 결과`, `남은 경계 사례와 통합·결정 요청`을 포함한다.

## 7. 인수인계

최종 보고에는 작성한 감사 문서·결과 JSON의 경로, 변경 파일, 승격/조건부/유지 수, 대표적인 경계 사례, 실행한 테스트, 정책·엔진·UI에서 변경하지 않은 경계, 통합·결정 세션의 판단이 필요한 사례를 포함한다.
