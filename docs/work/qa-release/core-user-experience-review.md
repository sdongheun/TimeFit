# QA-UX-CORE-01 — 핵심 추천 UX 체감 확인

## 시작 조건

[2-S — 검증 코스 형태 다양성 회복](../recommendation-engine/verified-course-shape-diversity.md)이 수락되고, 해당 코드를 포함한 새 iOS internal build가 설치된 뒤에만 실행한다.

## 목적

고정 fixture의 안전성 검증과 별개로, 사용자가 실제로 앱을 쓸 때 “남는 시간에 갈 만한 서로 다른 선택지를 발견했다”고 느끼는지 확인한다. 이 작업은 호출량 부하 시험이나 모든 장소의 정답 검사가 아니다.

## 진행 방법

아래 네 흐름을 실제 사용자처럼 각각 한 번만 실행한다. 개발용 진단 패널 수치·원시 API 오류·cache 삭제·동일 입력 반복은 사용하지 않는다.

| ID | 흐름 | 확인할 UX |
| --- | --- | --- |
| UX-CORE-01 | 서면역 복귀, 짧은 시간(약 50~70분) | 짧은 시간에 1곳만 나와도 이유와 시간표가 납득되는가 |
| UX-CORE-02 | 사상역 → 서면역, 약 100~130분 | 최소 두 가지 다른 선택지가 보이고, 1·2곳 코스의 차이를 한눈에 이해하는가 |
| UX-CORE-03 | 부산역 → 남포역, 약 100~130분 | 거리·문화·쇼핑 등 장소 성격이 일방적으로 반복되지 않고, 코스 확인과 카카오맵 장소 확인이 자연스러운가 |
| UX-CORE-04 | 센텀시티역 → 해운대역, 약 100~130분 | 대중교통 포함 이동과 도보 포함 여부, 남는 시간, 코스 확인 뒤 첫 길찾기 행동이 이해되는가 |

각 흐름에서 첫 결과 뒤 `다른 검증 코스 더 보기`는 한 번만 눌러도 된다. 단, 처음 결과만으로 선택할 수 있으면 누르지 않는다. 카카오맵 외부 전환 뒤에는 앱 복귀와 다음 행동이 자연스러운지만 본다.

## 기록할 것

각 ID에 다음 네 항목만 남긴다.

1. 입력 시간·출발/도착과 대표·대안의 장소 수
2. 실제로 비교 가능한 선택지가 있었는지와 장소/활동 반복 체감
3. 이해하기 어려웠던 화면 문구·시간표·이동수단 표기·다음 행동
4. 코스 확인·카카오맵 이동·앱 복귀 중 끊긴 행동

## 판정

- **수락**: 시간표·길찾기 흐름이 이해되고, 120분 안팎 두 생활권 이상에서 단일 장소 변형이 아닌 비교 가능한 선택지가 보인다.
- **부분 수락**: 안전성은 문제없지만, 코스 카드 설명·교통 표기·행동 유도가 불명확하다. 이 경우 UIUX 보완만 지시한다.
- **엔진 재검토**: fixture에서는 가능한 다장소 코스가 실제 UX 흐름에서 지속적으로 사라지거나, 서로 다른 장소를 보아도 실질적인 선택지가 없다는 관찰이 두 생활권 이상 반복된다.
- **중단**: 시간표 모순, 중복 장소, 조건부 자동 승격, Route Proxy 연결 오류, 앱 멈춤이 나오면 즉시 중단하고 재현 조건만 남긴다.

이 작업은 장소 수를 늘리거나 2·3곳을 강제하는 결정 근거가 아니다. 사용자 체감과 안전 오류를 분리하는 출시 전 핵심 UX 확인이다.

## 2026-09-02 — QA-UX-CORE-01 진행 기록

### UX-CORE-01 — 서면역 복귀, 짧은 시간

- 입력: 서면역 복귀, 15:00→16:00 전후의 약 60분, 도착 전 여유 10분. 새 2-S 포함 iOS internal build에서 1회 실행했다. 개발용 진단 panel·cache 삭제·동일 입력 재실행은 사용하지 않았다.
- 결과: 대표 1개와 대안 2개가 표시됐고, 세 코스 모두 장소 1곳 구성으로 관찰됐다.
- 사용자 체감: 근처에 추가 추천이 가능해 보이는 장소가 있는데도 첫 결과의 대안은 1~2개에 그쳐 선택 폭이 얇게 느껴졌다.
- 판정 보류: 이 한 생활권·한 실행만으로 실제 후보·경로·운영시간 탈락 또는 엔진 결함을 단정하지 않는다. 시간표 모순, 중복 장소, 조건부 자동 승격, 연결 오류, 앱 멈춤은 이번 관찰에서 보고되지 않았다. UX-CORE-02~04에서 비교 가능한 선택지 체감이 반복되는지 확인한다.

### UX-CORE-02 — 사상역→서면역

- 입력: 사상역→서면역, 15:00→17:00 전후의 약 120분, 도착 전 여유 10분. 같은 새 internal build에서 1회 실행했다.
- 결과: 대표 `부산 수학문화관` 1개, 대안 `커피스가모 인 서면`·`사상문화원` 각 1개가 표시됐으며, 사용자는 모두 1곳 코스로 관찰했다. 따라서 이 실행에서는 1곳/2곳 코스 차이를 화면에서 비교할 수 없었다.
- 사용자 체감: 이전 사용에서도 같은 세 장소가 반복돼, 새로운 선택지를 발견한다는 느낌이 약하고 UX가 좋지 않다고 보고했다.
- 중간 판정: UX-CORE-01·02 두 생활권에서 모두 대표 1+대안 2개의 1곳 코스만 표시되고 선택 폭이 얇다는 체감이 반복됐다. 이는 엔진 재검토 기준에 닿을 수 있는 신호이나, 현재 QA에는 원시 route/diagnostics를 사용하지 않는 제한이 있으므로 탈락 원인을 추정하지 않는다. 시간표 모순, 중복 장소, 조건부 자동 승격, 연결 오류, 앱 멈춤은 보고되지 않았다.

### UX-CORE-03 — 부산역→남포역

- 입력: 부산역→남포역, 15:00→17:00 전후의 약 120분, 도착 전 여유 10분으로 1회 실행했다.
- 결과: 대표 `백구당` 1개, 대안 `40계단`·`갤러리 플레이리스트` 각 1개가 표시됐고, 사용자는 세 코스가 모두 1곳 구성이라고 관찰했다. 빵집/거리/문화 공간으로 장소 성격이 일방적으로 반복되지는 않았다.
- 행동 흐름: 장소의 카카오맵 확인을 1회 실행했고, 외부 카카오맵 전환과 앱 복귀는 자연스럽게 동작했다.
- 해석 경계: 같은 고정 입력에서 같은 결과가 반복되는 것은 결정적 추천의 기대 동작일 수 있으므로 그 사실만으로 결함으로 보지 않는다. 다만 UX-CORE-01·02에서 보고된 ‘선택 폭이 얇고 새 발견이 약함’과 결합해, 고정 입력 내 비교 가능한 검증 코스의 체감 부족은 다음 엔진 검토 대상으로 남긴다.

### UX-CORE-04 — 센텀시티역→해운대역

- 입력: 센텀시티역→해운대역, 15:00→17:00 전후의 약 120분, 도착 전 여유 10분으로 1회 실행했다.
- 결과: 대표 `해운대 선물가게` 1개, 대안 `고래서이뻐`·`머그디저트랩` 각 1개가 표시됐고, 사용자는 세 코스가 모두 1곳 구성이라고 관찰했다.
- 행동 흐름: 대표에서 코스 확인 뒤 코스 시작하기와 첫 길찾기를 1회 수행했다. 외부 길찾기 전환과 앱 복귀는 자연스러웠다.

## 2026-09-02 — QA-UX-CORE-01 완료 인계

### 1. 변경 파일과 목적

- 이 문서: 새 2-S 포함 iOS internal build에서 실행한 UX-CORE-01~04의 사용자 체감·행동 흐름·판정을 기록했다.

### 2. 유지한 공개 계약·정책 경계

- 추천 엔진, 후보 데이터, UIUX 구현, Route Proxy/API, DB, 제품 정책 및 작업 조정 보드는 수정하지 않았다.
- 각 UX 흐름은 1회만 실행했으며, 진단 panel·원시 API 오류·cache 삭제·동일 입력 재시도를 사용하지 않았다.
- 같은 고정 입력의 동일 결과는 재현성일 수 있으므로, 그 사실만으로 무작위성 또는 추천 오류를 요구하지 않는다.

### 3. 테스트와 실기기 결과

- 새 build 설치 전 `npx tsx --test test/course-v1-pagination.test.ts test/course-v1-limited-integration.test.ts` 50/50 및 `npm run test:typecheck`를 통과했다. 새 iOS internal build 설치·실행도 완료했다.
- UX-CORE-01: 서면 짧은 시간에서 대표 1+대안 2, 모두 1곳 코스. 근처 후보가 더 있을 듯한데 선택 폭이 얇다는 체감이 보고됐다.
- UX-CORE-02: 사상→서면에서 대표 `부산 수학문화관`, 대안 `커피스가모 인 서면`·`사상문화원`, 모두 1곳 코스. 이전 사용에서도 같은 세 장소가 반복돼 발견 체감이 약하다고 보고됐다.
- UX-CORE-03: 부산역→남포에서 대표 `백구당`, 대안 `40계단`·`갤러리 플레이리스트`, 모두 1곳 코스. 장소 성격은 일방적으로 반복되지 않았고 카카오맵 확인·앱 복귀는 정상이다.
- UX-CORE-04: 센텀시티역→해운대역에서 대표 `해운대 선물가게`, 대안 `고래서이뻐`·`머그디저트랩`, 모두 1곳 코스. 코스 확인·첫 길찾기·외부 전환·복귀는 정상이다.
- 네 흐름에서 시간표 모순, 같은 장소 중복, 조건부 자동 승격, Route Proxy 연결 오류, 앱 멈춤은 보고되지 않았다. 사용자는 네 생활권 모두에서 추천 장소 다양성과 선택 폭이 부족하다고 평가했다.

### 4. 다음 세션의 결정 필요 사항·위험·재현 조건

- **엔진 재검토 인계:** 2-S의 고정 fixture는 1·2곳 교차 검증 기회를 보장하지만, 이번 실제 UX 네 생활권에서는 다장소 검증 코스가 한 번도 표시되지 않았고, 사용자는 1곳 코스의 제한된 반복 선택지를 의미 있는 발견으로 느끼지 못했다. 이는 작업 문서의 ‘두 생활권 이상에서 실질적 선택지 부족 반복’ 기준을 충족하는 사용자 체감 신호다. 엔진 소유자는 원시 진단을 일반 UX에 섞지 말고, 별도 고정 receipt와 제한된 실경로 관찰에서 후보·queue·route/시간 탈락을 분리해 검토해야 한다.
- **UIUX 후속 판단:** 코스 확인·첫 길찾기·카카오맵 복귀는 통과했다. 다만 이전 SUP-04에서 관찰된 혼합 이동의 `대중교통` 단일 표기는 이번 UX-CORE-04 응답에서 재평가되지 않았으므로, 도보 포함 여부 표기 개선 필요성은 별도 UIUX 검토 항목으로 유지한다.
- QA는 장소 수를 목표로 늘리거나 2·3곳 코스를 강제하지 않는다. 실제 경로·운영시간을 통과하지 못하는 다장소 코스는 계속 정직하게 제외해야 한다.
