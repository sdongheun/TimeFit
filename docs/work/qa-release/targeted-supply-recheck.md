# QA-SUPPLY-01 — 생활권 대표 후보 보강 실기기 재확인

## 시작 조건

[DATA-SUPPLY-01](../data-curation/targeted-representative-supply.md)이 수락되고, 새 internal build 또는 데이터가 포함된 개발 build가 준비된 뒤에만 실행한다. 데이터 작업과 병렬로 실행하지 않는다.

## 목적

보강 전 사용자 관찰과 같은 입력을 한 번씩만 실행해, 대표·대안 공급이 늘었는지와 공급 부족 원인이 데이터인지 엔진 선별인지 분리한다. 실제 provider를 반복 호출해 결과를 모으는 부하 테스트가 아니다.

## 고정 시나리오

| ID | 출발 / 도착 | 권장 고정 조건 | 기록할 것 |
| --- | --- | --- | --- |
| SUP-01 | 서면역 → 서면역 복귀 | 낮 시간, 50분 또는 120분, 여유 10분 | 대표·대안 수, 고유 장소, 1/2/3곳 수, 빈 상태 사유 |
| SUP-02 | 사상역 → 서면역 | 낮 시간, 약 120분, 여유 10분 | 사상/이동 축 장소 포함 여부, 과도한 우회 여부 |
| SUP-03 | 부산역 → 남포역 | 낮 시간, 약 120분, 여유 10분 | 시장·거리·문화 등 활동 다양성, 각 코스의 실제 시간표 |
| SUP-04 | 센텀시티역 → 해운대역 | 낮 시간, 약 120분, 여유 10분 | 동부산 생활권 후보·대안 수, 과도한 이동 여부 |

시간은 실제 사용 가능한 범위에서 고정하되, 실제 기기 시각과 조건부 시장 노출 창을 혼동하지 않는다. 조건부 카드는 검증 대안 수에 포함하지 않는다.

## 판정

- **개선 관찰**: 기존보다 고유 대표/대안 장소가 늘었거나, 동일 장소 변형이 아닌 시간 적합 코스가 추가됐다.
- **정직한 부족**: `후보 부족`, `운영 종료`, `시간 초과`, `경로 확인 불가` 중 화면/진단 근거가 일치한다.
- **엔진 선별 의심**: 구조화 후보가 충분한 생활권인데도 공간 선별·큐 단계에서 대부분 빠지고, 실제 route attempt가 적어 대안이 부족하다.
- **결함**: 시간표 모순, 중복 장소, 조건부 후보 자동 승격, route proxy/transport 오류, 앱 멈춤.

## 기록 형식

각 시나리오에 다음만 기록한다.

1. 입력과 build 식별
2. 대표·대안 코스 수와 코스별 장소명/장소 수
3. 고유 장소 수와 같은 장소 반복 여부
4. 이동·체류·남는 시간 중 납득되지 않는 값
5. diagnostics의 탈락 이유 요약 또는 화면 빈 상태 문구

한 시나리오에서 결함이 나오면 즉시 중단하고 재현 조건만 남긴다. cache 삭제, 동일 조건 반복 실행, provider 한도 조작은 금지한다.

## 다음 결정

네 시나리오 후에도 구조화 후보가 충분한데 대안이 적다는 증거가 두 생활권 이상에서 반복될 때만, 추천 엔진에 “거리·카테고리·생활권을 섞는 사전 후보 다양화” 한 작업을 지시한다. 그렇지 않으면 데이터 보강 결과를 수락하고 UI/진행 UX 마무리로 이동한다.

- SUP-01의 최초 Route Proxy/CAPTCHA/anonymous Auth 연결 실패는 재시도 성공만으로 해소됐다고 결론내리지 않는다. 별도 API/Auth 진단에서 비밀 없는 오류 범주와 재현 조건을 확인해야 한다.
- 네 시나리오에서 시간표 모순·장소 중복·조건부 자동 승격·앱 멈춤은 보고되지 않았다. 단, 사용자가 이동·체류·남는 시간 수치를 모두 제공한 것은 아니므로 각 경로의 우회 품질까지 보증하지 않는다.
