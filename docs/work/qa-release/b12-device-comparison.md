# RD-B12 — internal B12 실기기 비교 게이트

## 선행 조건

`2-N`, `U-1-REC-02` 수락 뒤 만든 새 internal build만 사용한다. B12는 여전히 production 전환 후보가 아니다.

## 정확히 두 번 실행

| ID | 입력 | A8 기준 관찰 | 기록 |
| --- | --- | --- | --- |
| RD-B12-01 | 서면역 부산1호선, 복귀, 개발 테스트 15:00→17:00, 여유 10분 | 엔진/화면 3/3, N1 3개 검증 | policy label, 엔진/화면 코스, N1/N2/W/T 수치, 새 경로·adapter·재사용, 안전성 |
| RD-B12-02 | 사상역 2호선→서면역 2호선, 개발 테스트 15:00→17:00, 여유 10분 | 엔진/화면 2/2, N1 2개 뒤 8회 소진, N2 0 시도 | 위와 동일, 특히 N2 시도와 1·2곳 결과 |

각 입력은 `이 시간에 할 일 찾기`를 한 번만 누른다. 같은 입력 재시도·새 추천·cache 삭제·설정 변경을 하지 않는다. CAPTCHA가 필요하면 정상 흐름에서 한 번만 완료한다.

## 중단·판정

- policy label이 B12가 아니거나 표시되지 않으면 `구성 검증 실패`로 종료한다.
- `route_proxy_transport_failed`, 앱 멈춤, 시간표 모순, 잘못된 출발/도착, 중복 장소면 즉시 중단한다.
- cache/session reuse가 있으면 새 provider attempt를 A8과 수치 비교하지 않고, 재사용·tier 결과를 함께 기록한다.
- 결과 수가 같아도 구조화된 time/no-route/운영 사유가 납득 가능하면 실패로 단정하지 않는다.

[`real-device-recommendation.md`](real-device-recommendation.md)에는 화면상 policy label·판정·수치·오류만 기록한다. URL·좌표·token/JWT·cache key·식별자·비밀값은 기록하지 않는다.

## 실행 기록 — 2026-08-30

### RD-B12-01 — 구성 검증 실패

- 입력: `서면역 부산1호선` 명시 선택, 복귀, 개발 테스트 15:00→17:00, 도착 전 여유 10분. 추천 실행은 1회만 수행했다.
- 관찰: diagnostics policy label이 요구값 `B12`가 아니라 `A8`으로 표시됐다.
- 함께 표시된 안전 수치: 엔진/화면 코스 3/3, 새 경로 확인 8, adapter 호출 7, 재사용 0. N1 후보/시도/검증은 3/3/3, N2는 3/0/0, W는 1/1/0, T는 816/0/0이며 결과 탈락은 `경로 확인 불가` 1건으로 표시됐다.
- 판정: **구성 검증 실패**. B12 internal build가 아니므로 B12 대비 관찰로 사용하지 않는다.
- 중단: 명세에 따라 같은 입력 재시도, RD-B12-02, cache 삭제, production 전환과 RD-06 실행을 하지 않았다. 앱을 종료했다.

### 다음 조치

`EXPO_PUBLIC_RECOMMENDATION_DIAGNOSTICS=true`와 `EXPO_PUBLIC_RECOMMENDATION_INTERNAL_B12=true`가 모두 번들된 **새 internal build**를 설치한 뒤에만 RD-B12-01부터 다시 시작할 수 있다. 기존 설치본에서 환경값만 바꾸거나 A8 결과를 B12 결과로 취급하면 안 된다.

### RD-B12-01 — B12 internal build 실행

- 구성: 새 internal build diagnostics에 `내부 정책: B12`가 표시되어 구성 검증을 통과했다. 앞선 A8 구성 실패 실행은 이 B12 실행 횟수에 포함하지 않는다.
- 입력: `서면역 부산1호선` 명시 선택, 복귀, 개발 테스트 15:00→17:00, 도착 전 여유 10분. 새 B12 build에서 추천 실행은 1회다.
- 결과: 엔진/화면 코스 3/3. source/조건 통과/공간/사전 제외 후보는 190/155/18/35다.
- 진단: 새 경로 확인 12, adapter 호출 21, 재사용 22. N1 후보/시도/검증/새 경로는 3/3/3/3, N2는 3/2/0/2(경로 확인 불가 2), W는 1/0/0/0(N1 검증 대기 1), T는 816/17/0/5(새 경로 확인 상한 1, 경로 확인 불가 17)로 표시됐다. 결과 탈락은 `경로 확인 불가` 19건이다.
- 판정: **B12 관찰 성공.** 엔진/화면 코스 수는 A8 기준선과 같고, N2 시도 2회가 관찰됐다. 재사용 22건이므로 새 provider 호출량을 A8 관찰과 직접 비교하지 않는다. 시간표 모순·중복 장소·transport 실패는 이 캡처에서 관찰되지 않았다.

### RD-B12-02 — B12 internal build 실행

- 구성·입력: diagnostics의 `내부 정책: B12`를 확인한 상태에서 `사상역 2호선` → `서면역 2호선`, 개발 테스트 15:00→17:00, 도착 전 여유 10분을 한 번 실행했다.
- 결과: 엔진/화면 코스 3/3. source/조건 통과/공간/사전 제외 후보는 190/155/18/35다.
- 진단: 새 경로 확인 12, adapter 호출 9, 재사용 2. N1 후보/시도/검증/새 경로는 3/3/3/5, N2는 3/2/0/2(경로 확인 불가 2), W는 1/0/0/0(N1 검증 대기 1), T는 816/1/0/1(새 경로 확인 상한 1, 경로 확인 불가 1)로 표시됐다. 결과 탈락은 `경로 확인 불가` 3건이다.
- 판정: **B12 관찰 성공.** A8 기준선의 엔진/화면 2/2 및 N2 시도 0과 달리 이번 B12 관찰에서는 3/3 및 N2 시도 2가 나타났다. 다만 재사용 2건과 실제 provider 상태가 있으므로 원인·우열·production 전환으로 해석하지 않는다. 화면상 transport 실패·시간표 모순·출발/도착 오류·중복 장소는 보고되지 않았다.

### B12 게이트 종합

- B12 label이 두 고정 입력에서 모두 확인됐고, 각 입력은 B12 build에서 한 번씩만 실행했다.
- 두 실행 모두 N2 시도 2회가 표시됐다. 이는 사상 입력에서 N2 시도가 0이던 A8 관찰과 다르지만, 실제 호출 재사용과 provider 변동을 분리하지 않았으므로 **internal 관찰**일 뿐이다.
- 안전 failure enum은 구조화된 `경로 확인 불가`뿐이었다. production A8·attempt 상한·tier 순서·cache 정책은 이 결과만으로 변경하지 않는다.
