# QA-EXPLORE-01 — 대표 코스·장소 탐색 결과 검증

## 시작 조건

DATA-AREA-01, 2-P, U-EXPLORE-01이 모두 수락된 뒤 시작한다. 이 작업은 `test/`, fixture, QA 문서와 실기기 검증 기록만 수정한다. 정책·엔진 코드·카탈로그·UI·보드는 수정하지 않는다.

## 검증 목표

“대표 코스의 정확성”과 “장소 발견성”을 서로 희생시키지 않는지 확인한다. 목록이 많다는 이유로 Kakao 호출량을 늘리거나, 권역형 장소를 실제 영업 보장으로 과장해서는 안 된다.

## 고정 자동 검증

1. 대표 1개 + 탐색 12개 이상, 대표 1개 + 탐색 0개, 대표 0개 + 탐색 있음, 대표 0개 + 탐색 0개의 결과 상태를 fixture로 실행한다.
2. 탐색 목록의 첫 렌더·더 보기·끝까지 스크롤은 route adapter/provider 호출 0회, place/siteGroup 중복 0, 조건부/시설 무시간 후보 노출 0을 검증한다.
3. 현재 자동 탐색 자격을 가진 `area_access` **야외 권역** 카드(다대포 해수욕장, 암남공원/송도해안볼레길)는 20분 탐색 문구만 보이며 실제 시간표·`검증됨`은 선택 전 0건임을 검증한다. 시장·거리·골목은 현재 `conditional`이므로 이 작업에서 자동 탐색 카드 출현을 기대하거나 fixture의 성공 사례로 쓰지 않는다.
4. 선택 성공/route 실패/time 실패/access-window 실패를 실행한다. 성공은 1곳 실제 시간 여정으로 이동하고, 실패는 대표·목록·스크롤 위치를 보존하며 자동 다음 후보 요청 0회다.
5. 기존 A8 production·B12 internal attempt/adapter cache receipt와 2-O 체류 fixture를 다시 실행해, 탐색 목록만으로 새 provider attempt가 생기지 않는지 확인한다.
6. 6개 생활권(서면, 사상, 부산역, 해운대, 광안리, 동래 등 실제 fixture에 있는 대표 좌표) × 45/78/120/180분 × 복귀/도착지 중 데이터가 있는 조합을 고정한다. 이는 대표·탐색 공급량과 사유 분포를 보는 표본이며, 각 생활권에서 `area_access` 카드가 나와야 한다는 요구가 아니다. 성공률 수치만으로 합격시키지 말고 `대표 없음`, `검증 코스 없음`, `탐색 후보 있음/없음`의 reason 분포와 유형 분포를 표로 남긴다.

## 실기기 최소 시나리오

- 서면 왕복 78분: 대표와 탐색 목록의 표시 상태를 확인하고, 더 보기가 route 요청을 하지 않음을 확인한다. 시장·거리 자동 탐색 카드를 기대하지 않는다.
- 다대포 해수욕장 또는 암남공원/송도해안볼레길 왕복 78~120분: 현재 자동 탐색 가능한 야외 권역 카드의 20분 문구·카카오맵 링크·선택 실패/성공 처리를 확인한다.
- 시설형 시간 경계: 구조화 운영시간 없는 시설이 탐색 카드에 섞이지 않음.
- 하나의 탐색 장소를 선택하고, 네트워크 오류 또는 no-route fixture에서 대표·목록이 유지됨.

실기기에서 외부 API 호출량은 소수로 기록한다. 반복 실험은 fixture로 하고 운영 Kakao를 반복 호출하지 않는다.

## 완료 기준과 인계

자동 테스트 결과, provider attempt/adapter call 관찰값, 실기기 캡처/재현 조건, 아직 정확 코스에 승격하지 않은 `area_access` 수를 기록한다. 기준을 못 채우면 실패 종류별로 데이터/엔진/UI 소유자에게만 인계하며, QA가 직접 코드를 바꾸지 않는다. 보드는 수정하지 않는다.

## 정합성 보완 — 2026-08-31

이전 실기기 예시는 해운대·광안리의 야외 권역과 서면 시장/거리 카드가 자동 탐색에 나타나는 것처럼 적혀 있었다. DATA-AREA-01의 현행 계약은 자동 `area_access`를 다대포 해수욕장과 암남공원/송도해안볼레길 두 공개 야외 권역으로만 한정하며, 시장·거리·골목은 근거 부족으로 `conditional`이다. 따라서 실기기 성공 예시를 실제 두 권역으로 교체했고, 여섯 생활권 표본은 권역 카드 보장 요구가 아닌 공급량·사유 분포 검증으로 명시했다. 이 변경은 데이터 수나 발견 자격을 바꾸지 않는다.

### 차단 관찰 — 권역 카드의 카카오맵 링크

- **판정: QA-EXPLORE-01 완료 보류.** 상세 문서의 실기기 시나리오는 현재 자동 area_access 카드에서 “20분 문구·카카오맵 링크·선택 처리”를 요구한다.
- 현행 탐색 카드 화면은 `선택해 확인` 행동만 제공하며 카카오맵 링크를 제공하지 않는다. UI 계약 문서의 “기존 지도/카카오맵 링크 유지” 문구와 QA 상세의 권역 카드 링크 요구가, 실제 결과 화면에서는 충족되지 않는다.
- 이 상태에서 다대포/송도 권역 카드를 선택하면 실제 route 호출만 추가하고 링크 검증은 할 수 없으므로 실행하지 않았다. 네트워크/no-route 실패 보존과 시설형 미노출은 고정 fixture로 통과했으며, 실기기 추가 실행은 UI 계약 정정 또는 링크 구현 뒤의 새 internal build에서만 한다.
