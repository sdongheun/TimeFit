# DEC-COMPLETION-RECORD-01 — 후기와 분리한 코스 완료 기록

> 상태: **수락 — 정책·DB repository·UI 연결·제한 QA 완료**  
> 확정일: 2026-09-04  
> 부모 결정: 2026-09-04 UIUX 시간 흐름 정리의 `코스 마치기 → 기록 탭 생성`

## 1. 확정 결론

- 사용자가 진행 화면의 **`코스 마치기`를 명시적으로 누른 시점**에 후기 작성 여부와 관계없이 완료 기록을 한 번 생성한다.
- 장소 카드 선택, 코스 보기, 코스 시작, 카카오맵 길찾기 실행·복귀만으로는 완료 기록을 만들지 않는다.
- 비로그인 사용자도 자신의 기기에서 기록을 볼 수 있도록 완료 기록은 우선 로컬에 보관한다. 이 기록을 anonymous Auth나 Supabase 사용자 행과 연결하지 않는다.
- 후기와 완료 기록은 서로 다른 사실이다. 후기는 만족도·메모이고 선택 사항이며, 완료 기록 생성을 막거나 대신하지 않는다.
- Live Activity의 활성 진행 복구 상태와 완료 이력도 서로 다른 저장소다. 활성 진행은 App Group에 한 건만 두고, 완료 이력은 별도의 versioned repository에 누적한다.
- 사용자가 도착·출발을 모두 확인하지 않아 실제 체류시간이 없으면 `actualDwellMin`은 `null`이다. 이 완료는 장소 수·카테고리 활동에는 포함하지만, 완료 활동 시간 합계나 체류 개인화 표본에는 포함하지 않는다. 계획 체류시간을 실제 체류시간으로 합성하지 않는다.

## 2. 이전 방식 → 문제 → 교체 방식

| 상태 | 내용 |
| --- | --- |
| 이전 방식 | `placeFeedback` 저장이 사실상 완료 확인 역할을 맡고, 기록 탭도 이번 달 후기만 집계했다. |
| 발생한 문제 | 후기를 남기지 않은 정상 완료가 기록에서 사라지고, 현재 V1 진행 화면의 `코스 마치기`는 메모리 상태만 초기화한다. 계획 체류시간과 실제 체류시간의 의미도 섞일 수 있다. |
| 교체 방식 | `코스 마치기`가 후기와 독립적인 `CourseCompletionRecordV1`을 생성한다. 후기는 선택적으로 별도 저장한다. |
| 교체 이유 | 완료 여부, 만족도, 사용자 확인 체류를 각각 독립된 사실로 보존해야 기록·개인화·오류 복구를 안전하게 확장할 수 있다. |
| 현재 상태 | 정책 확정, 로컬 repository와 `U-COMPLETION-HISTORY-01`의 기본 명시 완료·기록 탭 연결 구현 및 `QA-COMPLETION-HISTORY-01` 자동·비로그인 iOS 제한 검증 완료. App Group/실제 체류는 `U-LIVE-ACTIVITY-01` 후속이다. |

## 3. 데이터 경계

완료 기록이 보존할 최소 스냅샷은 다음과 같다.

- schema version
- 같은 진행을 재시도해도 변하지 않는 opaque `courseRunId`
- 완료 이벤트 ID와 완료 시각
- 1곳 또는 2곳의 순서 있는 장소 ID·표시명·category·nullable subCategory
- 각 장소의 계획 체류분과, 사용자 확인이 있을 때만 nullable 실제 체류분

다음 값은 로컬 완료 이력에 넣지 않는다.

- 출발지·도착지 좌표나 주소
- route geometry, provider receipt, 외부 URL
- Supabase user ID, anonymous user ID, 토큰, API key
- GPS 추정 도착·출발 시각

## 5. 완료와 집계 의미

- 같은 `courseRunId`의 빠른 연타·재시도·앱 복구는 완료 한 건으로 멱등 처리한다.
- 한 코스의 장소 수는 1 또는 2다. 같은 장소를 다른 날 다시 완료하면 별도 활동으로 센다.
- 이번 달 카테고리 비율과 완료 장소 수는 명시 완료 기록의 장소 항목을 기준으로 한다.
- `완료 활동 시간`은 유효한 실제 체류분만 합한다. 측정되지 않은 완료가 모두라면 `0분 활동`이라고 단정하지 말고 `체류시간 미측정` 상태를 표현한다.
- 과거 `placeFeedback` 데이터는 삭제하거나 임의 rating으로 새 기록을 만들지 않는다. 호환 read model에서 과거 완료 활동으로 계속 읽되 새 완료 저장과 같은 key에 덮어쓰지 않는다. 기존 `actualDwellMin`은 실제 시각 측정이 아니라 계획 체류에 사용자의 빠듯/보통/여유 응답을 곱한 값이므로, 새 `실제 체류시간`이나 개인화 표본으로 승격하지 않고 미측정으로 투영한다.

## 6. 의도적으로 보류한 것

- Supabase 완료 기록 동기화와 계정 간 기기 동기화
- 로그인 전 로컬 완료 기록의 계정 병합
- 후기 V2와 completion ID 연결
- GPS 자동 완료, background location, 계획 체류의 실제값 대체
- 기록 탭의 최종 시각 디자인

이 항목은 이번 repository 구현에 끼워 넣지 않고 UI·개인화 후속 결정으로 다룬다.
