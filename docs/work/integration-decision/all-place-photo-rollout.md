# DEC-PLACE-PHOTO-ALL-01 — 저장된 장소 사진 203개 전면 표시

상태: **DATA 완료 / 변경된 UIUX 구현 전**  
확정일: 2026-09-16

## 결정

런타임 장소 369곳 중 저장된 사진 후보 203개를 주변 둘러보기·추천 계열의 장소 카드와 상세에서 표시한다. 지도에서는 사진을 사용하지 않고 일반 장소 마커만 표시한다.

- 기존 검증 사진: 부산 명소 85개 + 부산 맛집 16개 = 101개
- 신규 운영자 승인 사진: 부산 쇼핑 29개 + TourAPI 73개 = 102개
- 사진 후보가 없는 장소: 166개, 기존 기본 이미지 유지

사진 유무는 추천 자격·순서·운영시간·체류시간·개인화에 영향을 주지 않는다. 사진 로딩 실패와 timeout은 카드·상세의 기본 이미지로 닫히며 지도 마커에는 처음부터 사진 URL을 전달하지 않는다.

## 교체 이력

이전 방식 → 부산 명소·맛집 101개만 `verified` 이용허락으로 공개하고 부산 쇼핑·TourAPI 102개는 기본 이미지로 대체했다.

발생한 문제/관찰 → 저장 후보 102개도 장소 식별에 도움이 되지만, 지도 사진 마커와 `cover`·둥근 모서리는 원본의 일부를 가릴 수 있다.

교체한 방식 → DATA는 102개를 기존 `verified`와 구분되는 `operator_approved` 표시 상태로 추가했다. UI에서는 지도 사진 마커를 폐기하고, 주변 둘러보기·추천 계열의 카드와 상세 사진을 모서리 마스킹 없이 `contain`으로 축소해 원본 전체가 보이게 한다. 기존 101개의 검증 근거는 변경하지 않는다.

교체 이유 → 장소 식별성과 사진 보유 장소의 기본 이미지 비율을 개선한다.

상태 → **DATA 구현 완료, UIUX/QA 구현 전**.

## UI 표시 정책 교체 (2026-09-16)

이전 확정의 `추천 지도/주변 지도는 기존 사진 마커 유지`는 **철회**한다.

- 주변 둘러보기 지도, 장소 상세 지도, 추천 지도, 코스 확인 지도에서 이미지 마커를 사용하지 않는다.
- 지도는 기존 일반 장소 핀·선택 강조·장소명·cluster를 유지한다. 현재 위치/GPS 마커를 새로 도입하지 않는다.
- 주변 둘러보기 목록·상세와 추천 결과·함께 갈 장소·선택 tray·코스 요약/상세의 실제 사진은 `resizeMode="contain"` 또는 동등한 `object-fit: contain`으로 표시한다.
- 실제 사진과 사진 frame에는 `borderRadius`와 원형/둥근 마스킹을 적용하지 않는다. 바깥 카드 자체의 둥근 모서리는 유지할 수 있지만 사진 영역을 잘라서는 안 된다.
- 사진은 원본 종횡비를 유지한 채 가용 영역 안에서 축소한다. 확대 crop, 강제 정사각형 변형, 색상 필터, 합성은 하지 않는다.
- 서로 다른 원본 비율 때문에 남는 영역은 중립 배경으로 채운다. 사진을 늘려 빈 공간을 없애지 않는다.
- 사진 없음·오류·12초 timeout은 기존 카테고리 fallback을 사용한다.

## 사실 기록 경계

- 새 102개를 `verified`, `이용허락범위 제한 없음`, `modificationAllowed=true`로 허위 기록하지 않는다.
- 부산 쇼핑 29개는 현재 서비스 이용조건을 개별 검증하지 않은 상태를 보존한다.
- TourAPI 73개는 HTTPS 도달성 검증은 완료됐지만 사진별 공공누리 유형 연결은 없는 상태를 보존한다.
- `operator_approved`는 앱 운영자의 표시 결정이며 저작권자의 개별 이용허락 검증을 뜻하지 않는다.
- 기존 101개의 권리자·출처·라이선스 metadata와 상세 출처 표시는 유지한다.
- 새 102개도 실제 공급 원천과 사진 URL을 표시 metadata에 보존하며, 출처를 다른 기관으로 바꾸거나 권리자를 추정하지 않는다.

## 구현 순서와 작업 명령

### 1. 데이터 정제 — DATA-PLACE-PHOTO-ALL-01

`AGENTS.md`와 이 문서를 읽고 진행한다.

1. `사진_이용허락_허용목록.json`의 기존 101개 `verified` 행을 그대로 보존한다.
2. 부산 쇼핑 29개와 TourAPI 73개를 정확한 `contentId/source/sourceId/imageUrl`로 연결한다.
3. 새 행은 `operator_approved`로 명시하고, 확인하지 않은 권리자·라이선스·변경 허용 값을 생성하지 않는다.
4. `build_public_api_photo_permissions.mjs`, `runtime_image_permission.mjs`, `build_runtime_poi_catalog.mjs`의 계약을 총 203개 표시/166개 fallback으로 갱신한다.
5. TourAPI HTTPS 검증 결과만 URL 도달성 근거로 사용하고 이용허락 검증으로 승격하지 않는다.
6. 추천·분류·운영시간·체류·개인화 필드는 변경하지 않는다.
7. 변경 파일, 불변 계약, 실행 테스트, 남은 위험을 인수인계한다.

### 2. UIUX — U-PLACE-PHOTO-ALL-01-R1

DATA-PLACE-PHOTO-ALL-01 완료 결과와 `docs/work/data-curation/all-place-photo-rollout.md`를 읽고 진행한다. 기존 U 명령의 지도 사진 마커 유지와 `cover` 표시는 이번 R1로 대체하며 복원하지 않는다.

1. `approvedPlacePhoto`가 `verified` 101개와 `operator_approved` 102개를 구분해 총 203개를 소비하게 한다. `operator_approved`에는 확인되지 않은 라이선스 이름·링크·변경 허용 문구를 합성하지 않는다.
2. `NearbyBrowseMap`, `KakaoRouteMap` 및 모든 public 호출부에서 사진 URL 전달과 이미지 마커 렌더링을 제거한다. 장소 상세·추천·코스 확인을 포함한 모든 지도는 일반 장소 핀, 선택 강조, label, cluster만 유지한다.
3. 지도만을 위해 존재하는 `photoMarkerFields`, `usePhotoMarkers`, `.photo-marker` 코드가 더는 public/호환 경로에서 필요하지 않으면 의존성을 확인한 뒤 함께 제거한다. 다른 지도 계약과 route geometry는 변경하지 않는다.
4. `PlacePhoto`는 실제 사진을 `resizeMode="contain"`으로 표시하고 원본 종횡비를 유지한다. 사진과 사진 frame의 `borderRadius`·원형 clip·`cover`를 제거한다. 바깥 카드 border radius는 유지하되 사진을 clip하지 않도록 padding/overflow 계층을 분리한다.
5. 주변 둘러보기 목록·상세, 추천 대표/대안 카드, 함께 갈 장소, 선택 tray, 코스 요약/세로 상세에서 같은 무자르기 계약을 사용한다. 화면별로 다시 `cover`를 주입하지 않는다.
6. 고정 썸네일 영역에서는 사진을 늘리지 않고 중앙 정렬하며 남는 공간은 `C.panel2` 등 기존 중립색으로 표시한다. 세로·가로·정사각형 fixture에서 사진 전체 네 변이 보이는 것을 검증한다.
7. 실패·timeout·비HTTPS·ID/URL 연결 불일치는 카드·상세에서 기본 이미지로 전환한다. 지도는 사진 실패 여부와 무관하게 일반 마커를 유지한다.
8. 사진 표시가 카드 선택, 상세 진입, 길찾기, 추천 상태, 추천 순서, 접근성 행동을 바꾸지 않게 한다.
9. 기존 101개 출처/이용조건 표시는 유지한다. 신규 102개는 DATA가 제공한 실제 attribution만 표시하고 확인되지 않은 링크 버튼은 만들지 않는다.
10. 다른 미완료 UI 변경을 되돌리거나 전체 파일을 재포맷하지 않는다.

실패 우선 테스트를 추가한 뒤 최소 `npm run test:typecheck`, `npm run test:ui`, `npm test`와 iOS 번들 검증을 실행하고, 변경 파일·불변 계약·테스트 결과·실기기 확인 항목을 인수인계한다.

## 수락 조건

- 카드·상세에서 사진 203개가 표시 가능하고 166개는 기본 이미지다.
- 모든 지도에서 사진 마커는 0개이며 일반 장소 마커·선택·cluster 동작은 유지된다.
- 사진은 원본 비율의 `contain` 축소로 전체가 보이고 사진/frame에 둥근 clip이 없다.
- 기존 101개의 검증 metadata가 훼손되지 않는다.
- 신규 102개는 검증 완료로 오인되지 않는다.
- 사진 실패가 추천·상세·길찾기 흐름을 막지 않는다.
- 추천 및 개인화 결과는 사진 변경 전후 동일하다.
