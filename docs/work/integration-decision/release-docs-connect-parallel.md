2. 공개 HTML/Markdown을 이용자용 본문으로 다듬는다. clean cold start, legacy artifact, plan/쿼터, 테스트 성공, 조사 메모 같은 내부 용어는 내부 사실표로 옮기고 이용자가 알아야 하는 수집·목적·전송·보유·삭제를 쉬운 표현으로 남긴다. 미확인 사실 자체를 감춰 완결된 문서로 가장하지 않는다. 반영 미완료 필드는 내부 대응표에 명시하고 게시 대기를 유지한다.
3. DOCS-06의 남은 쟁점을 재조사 목록으로 복제하지 않는다. 기존 DB/API NOTICE와 공식 근거로 이미 닫을 수 있는 필드만 닫고, 끝내 확인되지 않는 항목은 ‘정확한 질문 / 이미 확인한 사실 / 답변할 기관·공급자 / 영향받는 문단 / 답변 전 가능한 작업’의 최소 묶음으로 정리한다. 신규 사실·변동 법규 판단이 필요할 때만 최신 공식 출처를 확인한다. 위탁·제3자 제공·국외 이전을 단정하거나 공급자 기간을 만들지 않는다. 문의를 대신 발송하지 않는다.
4. 위치 문의 답변은 별도 수신 대기다. 답변이 공급자 로그/국외 이전까지 해결한다고 가정하지 않는다. 도착하면 다루는 범위만 반영하고 제품 변경이 필요하면 통합에 인계한다. 사용자에게 같은 계정 화면 확인을 다시 시키지 않는다.
5. app-store-submission.md의 설명·부제·키워드·선택 프로모션·저작권을 필드별 복사 가능한 블록으로 준비한다. 과장/미구현 기능 없이 현행 최대180분·2곳/부산/동의 개인화를 유지한다. 문안은 초안이므로 사용자가 저장하며 선택할 수 있게 하고 이미 승인된 문구로 허위 승격하지 않는다. 실제 입력 완료 보고만 checklist에 반영한다.
6. 공개 URL3개→privacy-policy/terms-of-service version1.0→DB→UI 연결표는 준비하되 실제 URL을 만들거나 예정 주소를 확정값으로 넣지 않는다. Kakao 플랫폼 설정 미등록은 사용 상품에서 요구되는지 확인할 항목이지 무조건 장애로 단정하지 않는다. 설정 변경은 별도 담당/승인으로 남긴다.
7. validator·문구 정합성·상대 링크·hash·diff check를 검증한다. 구조 PASS와 법적 적합성을 구분한다. 앱 테스트·C·Archive·기존 계정 재조사0. 문서에 비밀번호/키/토큰/개인 전화번호 수집0.

## 사용자 — Connect 병렬 입력

- 생성된 기존 앱에서 무료·대한민국 설정과 저장 결과 확인.
- DOCS-07이 제공하는 설명·부제·키워드·저작권을 검토해 저장. 선택 프로모션은 생략해도 이번 작업의 차단이 아니다.
- 아직 공개되지 않은 URL을 입력하지 않는다. App Privacy 최종 게시·연령/암호화 추측 답변·심사 제출·빌드 업로드는 이번 작업에서 하지 않는다.
- 완료한 필드명과 성공/미완료만 전달한다. 로그인 정보·비밀값은 전달하지 않는다. UI 메뉴가 다르면 해당 화면의 비밀값 없는 질문만 받는다.
