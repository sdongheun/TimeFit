2026-09-09. DOCS-05 로컬 산출 검토 후속. **RELEASE-DOCS-05-R1**과 **U-RELEASE-ICON-01**은 병렬 가능. 실제 게시/registry/계정 생성·삭제/Connect 설정·업로드·제출은 포함하지 않는다. AGE-01 구현·회귀 완료는 재사용한다.

## RELEASE-DOCS-05-R1 — 출시 문서 세션

읽기: AGENTS.md, docs/README.md, release-user-decisions.md, DOCS-05 최신 인계, publish/privacy-policy.md와 public-site/privacy/index.html, 기존 공급자 사실표의 관련 절만. 과거 전수 조사 금지.

소유: docs/05_release/만. 목적은 문서 충돌1건 수정과 게시 차단 목록의 정확한 축소다.

1. 현재 원본83줄/HTML60줄의 ‘만14세 미만은 비로그인 기본 기능만 이용할 수 있습니다’를 제거한다. 확정한 것은 가입 대상 만14세 이상·신규 가입 자기확인뿐이다. 제거를 반대로 ‘14세 미만 앱 이용 전면 금지’로 바꾸지 않는다. 비로그인 정책·앱 차단·부모 동의 기능을 임의 추가하지 않는다.
2. 두 공개본에는 가입 대상/자기확인/실제 연령 인증 아님만 일치시킨다. AGE-01 구현 완료·실기기 대기는 내부 인계에서 구분한다. 이전 표현→미확정 정책 승격 발견→확정 가입 범위로 축소→결정 충돌 방지→현행 상태를 인계에 기록한다.
3. 공급자 미확정 국가·법인·보유기간을 전부 동일한 출시 차단으로 취급하지 않는다. 기존 코드·계약·대시보드 근거를 재사용해 항목별 **대상 처리/필수 고지 해당 여부와 공식 근거/이미 확인된 사실/부족한 정확한 필드/확보할 출처·담당** 표를 작성한다. ‘미확인’ 문구만 넣었으므로 고지가 완료됐다고 하지 않는다. 필수 여부를 판단 못하면 미판정으로 남기며 추정 PASS 금지. 법적 판단·변동 정보는 최신 공식 자료만 확인한다.
4. 앱이 요청을 보낸다는 사실, 공급자의 자기 목적 처리, 운영자 위탁/국외 이전을 근거 없이 동일시하지 않는다. 서울 DB=모든 처리 국내, TTL=물리삭제, 법인 소재지=처리국가 추정 금지. 앱/웹의 실제 Cloudflare 사용도 구분한다. 이미 답한 사용자 이름/메일/가격/연령 결정을 재질문하지 않는다.
5. 남는 운영 증거는 기존 설정 화면에서 필요한 항목만 특정한다. 공개자료로 답할 수 있는 내용은 이번 작업에서 닫고, 사용자 계정 접근이 필요한 경우 화면/필드만 한 번에 요청한다. 신규 로그 인프라·백업·전체 supplier 감사 프로젝트로 확장하지 않는다. 위치 문의 답변은 그 답변이 실제 다루는 항목에만 사용하고 공급자 보유 사실까지 해결됐다고 하지 않는다.
6. Markdown/HTML/내부 gate가 모순되지 않게 갱신하고 기존 validate-public-site.mjs 실행,3페이지 내용·링크 확인, hash 재계산. validator PASS는 파일 구조 검증이지 법적 완결성 검증이 아님을 유지한다. 실제 게시일은 게시 시 확정한다. 추가 검증이 필요하면 미확정 비로그인 허용 표현이 다시 들어오지 않는 제한 문서 회귀만 보완한다.
7. 기존 스토어 설명·키워드·심사 메모는 확정값 기준으로 재사용해 준비 가능하다. 게시/실제 계정 검증 전 완료 주장은 제거하며 새 홍보 기능·스크린샷 촬영을 이번 문서 작업의 차단으로 만들지 않는다.

결과: release-document-session.md에 DOCS-05-R1 네 항목 인계와 **실제 게시를 막는 항목만** 한 묶음으로 남긴다. 위치 답변 대기를 반복 조사로 채우지 않는다. 문서만이면 앱 테스트/Archive 반복0. 최종 게시 승인은 기존 DOCS-05 범위 유지.

## U-RELEASE-ICON-01 — UIUX·빌드 세션

읽기: AGENTS.md, docs/README.md, release-user-decisions.md ICON/AUTO 결정, app.json 및 release-build-final.md의 public 빌드 경계. 다른 UI 수정은 하지 않는다.

소유: 별도 최종 아이콘 asset·app.json의 icon 경로·해당 생성 iOS asset·아이콘 검증 테스트·UIUX 인계. 문서 세션과 소유 경로가 겹치지 않는다.

1. 입력은 `output/imagegen/jjaturi-icon-blue-v1.png`(앞선 확인1254×1254, alpha 없음)이다. 먼저 직접 보고 실제 크기/색상모드/alpha 확인. 시계·파란 조각/강조선·흰 배경은 사용자 승인 방향이다. 원본 JPEG 및 생성 시안을 덮어쓰지 않는다. 새 이미지 생성·재디자인·텍스트·모서리 마스크·그림자 추가 금지.
2. 이 작업에서는 사용자가 승인한 시안의 **결정론적 리사이즈·포맷 정규화**만 허용한다. 기존 이미지 도구(sips 등)로 별도 `assets/jjaturi-icon-blue.png`를1024×1024 PNG·불투명·sRGB로 준비한다. 원형/둥근 사각형으로 자르지 않고 비율 유지. 파일이 이미 있으면 출처를 확인해 다른 사용자 asset을 덮어쓰지 않는다. 생성 도구를 다시 호출할 필요 없음.
3. app.json의 icon을 새 asset으로 연결한다. name/slug/scheme/Bundle ID/Team/App Group/버전·빌드 번호·권한·테마 변경 금지. 사용하지 않는 asset 전수 삭제/정리 금지. iOS에 별도 icon override가 있으면 실제 소비 경로만 맞춘다.
4. 변경 전 기존 icon 참조/잘못된 크기·alpha를 구분하는 실패 fixture를 만들고 변경 후 통과시킨다. 파일 존재·PNG/정사각/1024/불투명·config 경로 및 기존 public 설정 보존을 검사. npm run test:typecheck, npm run test:ui, npm test 실행.
5. 기존 public wrapper의 prebuild(비clean)와 iOS export/asset 검증을 이용해 네이티브 생성 asset에 반영되는지 확인한다. 생성 변경 diff를 확인하고 unrelated 변경을 임의 복구하지 않는다. 새 Distribution Archive·서명 자격 생성·설치·업로드는 아직 하지 않는다. 의미 없는 여러 번 prebuild/빌드 반복 금지.
6. 원본·최종 asset 경로와 hash/규격, Expo/iOS 소비 경로, 자동 검증 및 남은 실기기 아이콘 확인을 인계한다. 홈 화면 실제 아이콘과 Store 표시 확인은 최종 후보에 합친다. asset 변환 성공을 App Store 검증 완료로 기록하지 않는다.
