# DEC-PROFILE-SETTINGS-01 — 간결한 내정보

상태: **사용자 확정·구현 전**, 2026-09-05. 이번 변경은 요구사항 정리이며 제품 코드를 수정하지 않는다.

## 관계와 변경 이력

- 부모 결정: 출시 UIUX의 내정보/권한 정리. 관계: 기존 UX-19·DB-11 인증 구분과 Live Activity 동의 정책의 **보완**.
- 이전 권한 항목 위주 화면/로컬 기록 관리 추가 제안 → 비로그인 설정 접근 차단 및 기록 탭 중복 우려 → 내 프로필·권한 및 맞춤 추천·앱 안내의 세 영역 → 적은 항목으로 계정과 설정을 찾도록 단순화 → **현행 결정·구현 전**.
- 내정보 진입 자체의 로그인 강제와 내정보의 방문 기록 관리 중복 배치는 **철회**. 프로필 사진 업로드·새 통계·즐겨찾기는 이번 범위에서 제외한다.

## 확정 화면과 행동

1. **내 프로필**: 비로그인은 로그인 안내를 누를 때만 로그인 화면으로 이동한다. 일반 로그인은 닉네임과 프로필 관리 진입을 표시한다. 닉네임이 없으면 `닉네임 설정하기`; 이메일을 닉네임 대신 크게 노출하지 않는다. 프로필 관리 안쪽에 닉네임 수정, 로그아웃, 계정 삭제를 둔다. 첫 화면에 파괴적 행동을 나열하지 않는다.
2. **권한 및 맞춤 추천**: 위치·알림은 실제 상태와 설정 변경 행동을 제공한다. OS 권한을 앱 내부 가짜 토글로 표현하지 않는다. 별도 체류 기록 수집 동의만 앱이 관리하는 토글로 제공하며 재동의 가능하다. Live Activity 상태/연결은 해당 기능 구현 시 추가한다. 미구현 개인화를 사용 가능하다고 홍보하거나 작동하는 듯한 토글을 두지 않는다.
3. **앱 안내**: 개인정보 처리방침(필요한 위치정보 안내 포함), 문의하기, 앱 버전을 작게 배치한다. 실제 정책 URL·문의 채널이 없으면 임의 주소를 만들지 않고 구현 인계의 미결정 사항으로 남긴다.
4. **진입**: 내정보 탭은 로그인 없이도 접근한다. 메인 오른쪽 위 작은 프로필 버튼은 비로그인 시 로그인, 로그인 시 내정보로 연결한다. 지도·검색·코스 화면에는 일괄 추가하지 않는다. 기존 다크/파란 테마·safe area·일반 버튼 눌림 표현을 유지하고 햅틱은 추가하지 않는다.
5. **복귀와 상태**: 로그인 완료·취소 모두 호출한 화면으로 복귀하며 진행 코스/선택 장소를 지우지 않는다. 인증 loading 중 비로그인으로 단정해 잘못 이동하지 않는다. Route Proxy anonymous session은 일반 로그인으로 표시하지 않으며 UI를 위해 강제 sign-out하지 않는다.
6. **기록 경계**: 방문 기록 조회·삭제는 기록 탭 소관이다. 이번 결정은 삭제 기능이 이미 구현됐다는 뜻이 아니다. 구현 전 repository 범위와 실제 기능을 확인한다. 개인화 초기화는 방문 기록 삭제와 별개로 추후 맞춤 추천 설정에 연결하고 삭제 대상을 안내한다. 로그인 시 guest 기록 자동 병합·업로드, 로그인에 의한 자동 수집 동의는 금지한다.

## 검증 기준

- null/anonymous/account/loading 각각의 계정 영역과 메인 버튼 목적지, 닉네임 없음, 로그인 완료/취소 복귀를 fixture로 검증한다.
- 비로그인도 권한·앱 안내 접근 가능; 계정 관리 진입만 인증 필요. 프로필 진입·로그인 복귀에 추천 재호출/코스 초기화/동의 변경이 없어야 한다.
- 권한 거절·미결정·허용·지원 안 됨과 설정 복귀 후 상태 갱신을 구분한다. 실제 OS 권한 변경을 fixture 통과만으로 확정하지 않는다.
- 기록 관리 중복 없음, 준비 안 된 링크/동의 기능의 가짜 성공 없음, 작은 화면·큰 글씨·VoiceOver에서 주요 행동 접근을 확인한다.

## 구현 전 확인/인수인계

UIUX는 기존 Auth/Profile/로그인 화면을 먼저 확인하고 재사용한다. DB 소유 닉네임 저장·계정 삭제·개인화 초기화의 공개 계약이 없으면 임의 UI 저장으로 대신하지 않는다. 정책 URL·문의 채널·닉네임 검증 규칙은 기존 계약 확인 후 부족한 부분만 사용자에게 묻는다. Live Activity 전에 기본 계정/권한 정보 구조를 정리하고, 체류 동의/native 연결은 해당 작업과 함께 진행한다.
