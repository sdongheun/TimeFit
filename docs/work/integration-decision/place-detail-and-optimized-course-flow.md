# DEC-PLACE-COURSE-FLOW-01 — 장소 상세 선택과 최적 순서 코스 진행

> 상태: **제품 흐름·완료 UI 시나리오 최종 승인·구현 작업 활성화**  
> 결정일: 2026-09-05  
> 소유: 통합·결정

## 1. 결정 목적

추천 카드 tap, 장소 선택, 최대 2곳 조립, 최종 코스 검토와 진행이 서로 다른 의미를 가져야 한다. 사용자는 장소를 담기 전에 현재 위치와 장소의 관계·장소 정보를 확인할 수 있어야 하고, 두 장소를 고른 순서가 실제 방문 순서로 오해되어서도 안 된다.

## 2. 변경 이력

| --- | --- | --- | --- | --- |

## 3. 확정 상태 모델

```text
A0 추천 목록
  └─ 카드 tap → B 장소 상세
       ├─ 닫기 → A0 원상 복귀
       └─ 선택하기 → A1 첫 장소 선택 상태

A1 선택 tray + 첫 장소와 함께 가능한 후보
  ├─ A의 × → A0 원본 목록·더보기·스크롤 복원
  ├─ 코스 보기 → C-review 1곳 최종 코스
  └─ B 후보 카드 tap → B 장소 상세
       ├─ 닫기 → A1 유지
       └─ 선택하기 → A2 두 장소 선택 상태

A2 선택 tray + 코스 보기
  ├─ 두 번째 장소 × → A1
  ├─ 첫 장소 × → A0
  └─ 코스 보기 → C-review 엔진 최적 순서의 2곳 최종 코스

C-review 같은 코스 화면의 검토 상태
  └─ 코스 시작하기 → C-active 같은 화면의 진행 상태

C-active
  └─ 현재 최적 순서 구간 길찾기 → travel/stay 반복 → 명시 코스 마치기
```

`A0/A1/A2`는 같은 Results 화면 인스턴스와 recommendation session을 사용한다. `B`만 계층형 장소 상세 화면이다. 상세에서 선택하면 새 Results 화면을 만들지 않고 기존 Results로 돌아와 상태만 갱신한다.

## 4. 전체 지도형 장소 상세 B

1. 지도는 safe area 아래부터 화면 전체를 사용한다. 상단에는 닫기/뒤로가기와 최소한의 장소 제목 control을 floating으로 둔다.
2. 첫 장소 상세는 선택 후보 marker와 **이미 허용된 실제 기기 현재 위치**를 함께 표시하고 두 점이 보이도록 viewport를 맞춘다. 두 번째 후보 상세는 여기에 이미 선택한 첫 장소 marker를 추가해 관련 지점들의 공간 관계를 보여 주되 아직 확정되지 않은 방문 순서 번호나 근사 경로선은 그리지 않는다.
3. 사용자가 추천 입력의 출발지를 현재 위치와 다르게 설정했다면 `현재 위치`와 `설정한 출발지`를 서로 다른 marker·label로 함께 표시한다. 추천 가능성은 설정 출발지 기준이며, 실제 현재 위치를 추천 입력으로 몰래 바꾸지 않는다.
4. 장소 상세 진입만으로 새 위치 권한 prompt를 띄우지 않는다. 이미 허용된 위치 snapshot만 사용하며, 권한 거절·미결정·GPS 실패는 상세 진입을 막지 않는다. 이때 설정 출발지를 대체 기준으로 표시하고 `현재 위치를 확인하지 못했어요`를 짧게 알린다.
5. 하단 floating sheet에는 장소명, 사진, category/subCategory, 근거가 있는 한 줄 설명, 운영시간 또는 `운영시간 확인 필요`, 주소, 카카오맵 장소 보기, 명시 선택 CTA를 둔다. 첫 장소는 `이 장소 선택하기`, pair 후보는 `함께 선택하기`로 구분한다. 접힘/확장 두 높이는 허용하되 CTA는 safe area 위에서 가려지지 않는다.
6. 설명·운영시간은 런타임 카탈로그와 사전 정제된 TourAPI 근거만 사용한다. 데이터가 없으면 문구를 합성하지 않고 `상세 설명 없음` 또는 `운영시간 확인 필요`로 표시한다. 상세를 열 때마다 Kakao/TourAPI/Route Proxy를 새로 호출하지 않는다.
7. `카카오맵에서 장소 보기`는 정보 확인 행동이다. 선택·코스 시작·이동 시작·체류 시작으로 기록하지 않는다.

## 5. 선택과 복원

- 상세 B의 `선택하기`가 성공하면 B는 pop되고 기존 A 화면의 상태가 `A0→A1` 또는 `A1→A2`로 바뀐다. 별도 C 화면이나 중복 Results stack을 만들지 않는다.
- 첫 장소 A 확정 뒤에만 pair 후보 계산을 시작한다. 상세를 열거나 닫는 행동은 pair API·추천 continuation·route attempt를 증가시키지 않는다.
- A의 `×`는 선택 전 장소 ID·순서·더보기·continuation·종료 상태·스크롤을 새 route 호출 없이 복원한다. 화면에 새로고침처럼 보이는 전체 재실행을 하지 않는다.
- B의 `×`는 A와 pair 후보 목록을 유지하고 B만 제거한다.
- 선택 tray의 나열 순서는 선택 상태 표현일 뿐 방문 번호가 아니다. 최종 방문 번호는 코스 화면에서만 엔진 최적 순서로 표시한다.

## 6. 경로 최적화와 최종 코스

- 1곳은 `O→A→D`, 2곳은 `O→A→B→D`와 `O→B→A→D`를 exact route·운영시간·각 최소 체류·도착 여유로 비교한다.
- 두 순서가 모두 유효하면 총 검증 이동시간이 짧은 순서를 사용한다. 동률은 기존 계약대로 첫 선택 A 우선을 유지한다. 하나만 유효하면 그 순서를 사용하고 둘 다 실패하면 2곳 코스로 확정하지 않는다.
- 최종 코스 화면의 지도 marker 번호, 세로 카드, 구간, 카카오 길찾기 출발·도착은 모두 같은 최적화 snapshot 순서를 사용한다. UI가 거리로 다시 정렬하거나 선택 순서로 덮어쓰지 않는다.
- 기존 검증 geometry와 endpoint walk 보충 결과를 재사용한다. 화면 진입·상태 전환만으로 추천, transit 또는 route 최적화를 다시 호출하지 않는다.

## 7. 하나의 코스 화면: 검토와 진행

- `C-review`는 전체 지도, 최적 방문 순서, 구간 수단·분, 장소 정보와 `코스 시작하기`를 보여 준다. 길찾기 실행과 체류 측정을 시작하지 않는다.
- `코스 시작하기` 뒤 navigation으로 중복 진행 화면을 새로 만드는 대신 같은 화면을 `C-active`로 전환한다. 지도·최적 순서·snapshot identity는 유지하고 현재 상태와 행동 영역만 갱신한다.
- `C-active`에서는 **현재 다음 구간**의 카카오 길찾기만 primary로 활성화한다. 미래 구간은 순서 확인용으로 보이되 비활성화하고, 완료 구간은 완료 상태로 표시한다.
- 현재 구간 handoff가 성공해야 진행 상태가 전이한다. 실패하면 같은 단계와 재시도 행동을 유지한다. 사용자가 미래 구간을 눌러 순서를 건너뛰는 MVP 동작은 제공하지 않는다.
- 외부 카카오맵 복귀, Home의 진행 중 카드, 앱 안 navigation 재진입은 같은 `courseRunId`와 마지막 확정 단계로 이 화면을 복원한다.
- Live Activity의 도착·출발 확인과 App Group 강제 종료 복구는 `DEC-LIVE-DWELL-01` 후속이다. 이번 구조 작업은 해당 hook을 보존하되 예상 시각으로 체류를 합성하지 않는다.

## 8. 변경하지 않는 경계

- 최대 120분, 도착 여유, 최소 20분, one-stop 첫 8회/명시 더보기 8회
- pair B 기본 3·누적 6·session 최대 36 attempt, exact seed/cache/terminal 규칙
- 조건부 시장·거리의 실제 기기 시각 `10:00 ≤ t < 18:00` 분리
- 최대 2곳, 3곳·자유 장바구니·사용자 수동 순서 편집 금지
- Kakao route provider와 app→HTTPS→browser handoff
- GPS 자동 도착/이탈, background location, 상세 진입 live API 호출 금지

## 9. 구현 시작 게이트

2026-09-05 사용자가 아래 `완료 UI 시나리오`를 최종 승인했다. 역할별 소유 경계를 나눠 구현 명령을 활성화하고, 과거 `카드 tap 즉시 선택` fixture를 새 정책으로 교체한다. 엔진의 exact 순서·API 호출량·DB 저장 계약은 새 결함 근거 없이 수정하지 않는다.

## 10. 완료 UI 시나리오 — 최종 확인안

1. 사용자는 시간·출발·도착을 설정하고 추천을 실행한다.
2. Results A0에는 검증 one-stop 대표·대안과 필요한 경우 `다른 장소 더 보기`가 보인다.
3. 장소 카드 tap은 선택하지 않고 전체 지도형 상세 B를 연다. 이미 허용된 현재 위치와 장소가 보이고, 설정 출발지가 다르면 세 점을 구분한다. 상세 진입 자체는 위치 권한을 새로 요청하지 않는다.
4. 하단 sheet에서 장소 정보·운영시간 상태·주소를 확인한다. 닫으면 A0의 목록·스크롤·호출량이 그대로다.
5. `선택하기`를 누르면 기존 A로 돌아오고 A1의 compact 선택 tray, A만으로 코스를 보는 fixed CTA, exact pair 후보 loading/목록이 나타난다.
6. pair 후보 카드도 같은 B 상세에서 확인한다. 지도에는 현재 위치·선택 A·후보 B를 구분해 표시하되 아직 방문 순서를 부여하지 않는다. 닫으면 A1, `함께 선택하기`를 누르면 A2가 된다. A/B의 `×`는 정의된 이전 상태로 복원한다.
7. `코스 보기`를 누르면 선택 순서가 아니라 엔진이 고른 최적 순서로 지도 번호·세로 카드·모든 구간이 일치한 C-review가 열린다.
8. `코스 시작하기`를 누르면 같은 코스 화면이 C-active로 바뀌고 현재 첫 구간의 카카오 길찾기만 활성화된다.
9. 이번 구조 작업에서는 각 외부 길찾기 성공과 기존 진행 행동에 따라 완료·현재·미래 구간 상태가 순서대로 바뀌고 미래 구간은 건너뛸 수 없다. 이후 `DEC-LIVE-DWELL-01`이 구현되면 같은 상태 화면에 명시 도착·출발 확인을 연결하며, 이 구조 작업이 예상 시각이나 GPS로 체류를 먼저 합성하지 않는다.
10. 마지막 도착 뒤 `코스 마치기`를 누르면 완료 기록이 한 번 생성되고 active course가 제거되며 기록 탭에서 확인된다.
