1. API NOTICE·DOCS-06 사용자 계정 사실을 재사용한다. Local/Maps JS/REST routing/외부 카카오맵 열기의 코드 소비 경계·키 종류·WebView origin/baseUrl·URL scheme을 각각 확인한다. 키 원문을 출력하지 않는다.
2. 최신 공식 상품별 플랫폼 등록 요건과 대조해 현재 방식에서 iOS Bundle ID 등록이 필수인지, JS host 등록만 관련되는지, REST 상품별 추가 조건이 있는지 결론낸다. Native SDK를 쓰지 않는데 iOS 앱이라는 이유만으로 native 등록을 강제하지 않는다. WebView 가상 host와 외부 브라우저 host를 혼동하지 않는다.
3. 사용자 확인된 도메인 목록과 실제 public 빌드 소비 host를 대조한다. 소스에 값이 있다는 사실만으로 런타임 origin까지 확정하지 않는다. 기존 public artifact/fixture를 재사용하고 미증명 항목은 정확히 표시한다. 카카오 길찾기 실기기 성공이 모든 API 설정을 증명한다고 하지 않는다.
4. 결과 표: 기능/사용 상품/필수 등록/현재 근거/일치·불일치·미확인/필요 조치. 조치가 없으면 명확히 완료로 닫는다. 설정이 필요하면 사용자가 입력할 정확한 비밀값 없는 값·메뉴·영향만 인계하고 직접 변경하지 않는다. 전체 법률/사진/공급자 로그 조사는 반복하지 않는다.
5. 기존 관련 격리 계약 테스트만 실행한다. 실제 지도/경로/검색 호출0. 전체 앱 게이트는 QA 결과 재사용.

## U-RELEASE-CAPTURE-PREP-01 — UIUX·빌드 세션

소유: `docs/work/uiux/release-capture-preparation.md`와 격리 캡처 fixture/출력만. App.tsx/nav/app.json/native project 및 제품 화면 변경 금지.

1. SIGNING-PREP-03·ICON-01·DOCS-08 screenshot 목록을 재사용한다. 이미 확인한 키체인/서명 절차를 다시 조사하지 않는다. 현재 main/extension version/build/Team/Bundle/App Group/아이콘과 Connect 사용자 보고의 일치 여부만 읽기 전용으로 확인한다. 아직 업로드한 build가 없다는 추정으로 번호를 변경하지 않는다.
2. 기존 fixture·설치된 Simulator 목록을 읽어 6.9형 촬영용 기기·해상도, 6개 화면을 만드는 고정 시각/부산 장소/가상 기록 입력, 촬영 순서와 명령을 확정한다. 출발/도착/선택 2곳·완료 상태를 기록해 재현 가능하게 한다. 새 하네스 프레임워크·제품 UI 변경은 하지 않는다.
3. 기존 격리 하네스만으로 후보 캡처 생성이 가능하면 비밀값 없는 고정 fixture로 생성해 직접 시각 검토한다. 네트워크 차단/fixture 경계 없이 지도나 운영 기록을 호출하지 않는다. 현 상태에서 촬영 불가능하면 정확히 필요한 입력만 남긴다. 가짜 지도/미구현 UI를 그려 Store 화면으로 만들지 않는다. 캡처는 준비 후보이며 최종 앱 UI와 대조 후에만 제출본으로 사용한다.
4. 실제 최종 Archive/서명/export/업로드/실기기 설치는 이번에 하지 않는다. 최종 링크 연결 후 기존 public wrapper로 만들 후보의 입력 체크리스트만 인계한다. 기존 Distribution0 근거는 확인일을 붙이고 새로운 자격 생성 승인을 받은 것으로 쓰지 않는다.
5. 캡처 후보가 있으면 규격·노출 개인정보·internal 도구 노출·실제 UI 일치 검토를 남긴다. 없으면 촬영 준비 완료와 실제 촬영 미완료를 구분한다. 제품 미변경이면 앱 전체 테스트는 QA 단일 결과를 사용한다.
