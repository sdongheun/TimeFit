# DEC-ONE-STOP-MORE-01 — 출시 1곳 추천의 요청형 이어보기

## 상태

2026-09-02 사용자 확정. 현행 정책이며 `2-V`, `U-ONE-MORE-01`, `QA-ONE-MORE-01`을 모두 통합 수락했다. 요청형 이어보기의 자동 구현·검증은 완료됐고 native 체감은 출시 후보 최종 smoke에 합친다.

## 이전 방식 → 관찰된 문제 → 교체 방식 → 이유

- **이전 방식:** 출시 one-stop entry는 최대 18개 공간 후보 중 신규 provider attempt 최대 8회로 대표 1개와 대안 최대 3개만 만들고 continuation을 반환하지 않았다.
- **관찰된 문제:** `QA-RELEASE-ONESTOP-01`에서 대표 성공은 7/8이었지만 실제 화면의 선택지는 입력별 0~3개였다. `U-COURSE-CARD-DETAIL-01`은 카드와 상세 표현만 바꿨으므로 장소 선택 폭은 늘지 않았다. 특히 총 3개가 보이는 경우는 UI가 네 번째를 숨긴 것이 아니라 첫 8회 안에서 실제 검증된 결과가 3개였다는 뜻이다.
- **교체 방식:** 첫 화면의 최대 8회·대표 1개+첫 대안 최대 3개는 유지한다. 미검증 single 후보가 남아 있을 때만 결과 하단에 `다른 장소 더 보기`를 표시한다. 사용자가 누를 때마다 같은 추천 세션의 다음 후보를 신규 provider attempt 최대 8회로 검증하고, 통과한 서로 다른 one-stop 코스 최대 3개를 기존 목록 뒤에 누적한다. 후보가 남는 동안 반복할 수 있으며 화면 총량에는 별도 고정 상한을 두지 않는다.
- **교체 이유:** 첫 결과의 속도와 기본 호출량을 유지하면서, 더 많은 선택지를 원하는 사용자에게만 실제 경로 검증 비용을 사용한다. 최초 요청을 무조건 16회로 늘리는 것보다 불필요한 호출과 대기시간이 적다.

## 확정 계약

1. 첫 계산은 기존 release one-stop 정책대로 신규 provider attempt 최대 8회이며 자동 8→16 보충을 하지 않는다.
2. 더보기 한 번은 다음 미검증 single 후보만 신규 provider attempt 최대 8회로 확인하고 새 검증 코스 최대 3개를 반환한다.
3. 첫 대표는 교체하지 않는다. 기존 대안의 순서도 바꾸지 않고 새 결과만 아래에 붙인다.
4. 같은 장소, 이미 검증된 장소, 실제 경로·운영시간·최소 체류·도착 여유에서 탈락한 장소를 다시 결과로 넣지 않는다. 로컬 페이지 예산 때문에 검증을 끝내지 못한 후보는 영구 탈락으로 기록하지 않는다.
5. cache hit와 같은 세션의 동일 구간 재사용은 신규 provider attempt가 아니다. Kakao 실패를 TMAP·ODsay·근사시간으로 대체하지 않는다.
6. 후보 큐가 남아 있을 때만 버튼을 보인다. 후보 소진, 실제 provider 불가/한도, continuation 재수화 실패는 서로 다른 종료 상태로 표시하고 기존 카드는 유지한다.
7. continuation은 single 후보 ID, cursor, 후보 집합 signature, 검증·탈락 상태와 opaque receipt key 같은 직렬화 가능한 안전 참조만 가진다. 좌표 정밀값, 사용자 ID, API key, provider/함수 객체를 넣거나 서버에 추천 세션·후보 큐를 저장하지 않는다.
8. UI는 같은 결과 화면 메모리에 보관한 최초 `CourseV1LimitedInput`과 continuation을 결합한다. 비직렬 객체를 navigation params에 넣지 않는다. 입력·후보 signature가 달라지면 route 호출 없이 종료한다.
9. 이 결정은 **1곳 추천의 선택 폭만 확장**한다. 2·3곳 조립, candidate-to-candidate receipt, 무경로 탐색 장소의 검증 대안 승격, 조건부 시장의 자동 추천은 계속 보류한다.

## 역할·순서

1. `2-V` 추천 엔진: one-stop 전용 continuation과 페이지 entry를 구현한다.
2. `U-ONE-MORE-01` UIUX: `2-V` 수락 뒤 버튼·누적·로딩·종료 상태를 연결한다.
3. `QA-ONE-MORE-01` QA·출시: 고정 fixture 회귀 뒤 제한된 Simulator/실기기 시나리오로 실제 선택 폭을 확인한다.

기존 `API-PAGE-01`의 사용자 행동당 8회, cache/in-flight reuse 0회, typed provider 종료, 서버 무상태 계약을 그대로 사용한다. `2-V`가 기존 `CourseV1RouteReceiptAdapter`로 이 계약을 지키면 별도 외부 API 구현 작업은 만들지 않는다. 계약 불일치가 테스트로 증명될 때만 외부 API 작업을 연다.
