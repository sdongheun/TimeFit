2. app-store-submission.md·release-gates.md·release-document-session.md에 위 실제 저장 보고를 반영한다. 이전 초안/입력 대기→사용자 저장 확인→현행 입력값→중복 입력 방지 이력. 저작권 표·복사 블록과 설명 본문/글자수를 갱신한다. URL·Privacy·연령·수출규정·심사 계정·build·자동 출시 설정까지 입력 완료로 확대하지 않는다.
3. DOCS-07 기존 질문표를 그대로 재조사하지 않는다. 사용자가 실제 전달할 수 있도록 수신처별 짧은 문의문을 `publish/notice-inquiries.md`(내부용)에 작성한다. 공급자 사실 질문과 국내 법적 분류 질문을 분리한다. 이미 접수한 위치 문의는 재접수하지 말고 답변이 다루지 않은 쟁점만 후속 후보로 둔다. Supabase/Cloudflare에는 공개 자료로 확인되지 않은 정확한 처리 항목·지역·보유 예외만 묻고, Kakao 상품별 적용 역할/처리 안내와 국내 고지 해석은 담당을 구분한다. 문의 채널은 현재 공식 자료로 확인 가능한 것만 링크하고 없는 주소를 만들지 않는다. 문의 발송·계약 동의는 하지 않는다.
4. ‘전문 해석 필요’를 무기한 공통 차단으로 반복하지 않는다. 남는 질문마다 어떤 공개 문단/가입 동의/출시 판단에 영향을 주는지, 기존 근거로 답할 수 없는 이유를 한 줄씩 남긴다. 추정으로 차단을 해제하거나 무관한 미확인 항목을 신규 필수로 올리지 않는다. 현행 기술 사실은 변경하지 않는다.
5. 기존 Pages 게시/RELEASE-LINKS-01 인계를 재사용해 실행 대상을 한 표로 고정한다: 최종 HTML3개·시행일/version·hash·대상7파일·프로젝트/예정 주소·privacy-policy/terms-of-service ID·실제 URL 기록 슬롯·다음 DB/UI 담당. 예정 URL을 실제 URL로 저장하지 않는다. 답변으로 바뀔 문단만 식별하고 전체 문서 재작성 금지.
