# TimeFit 출시 UIUX 통합 체크리스트

> 상태 기준일: **2026-09-05**  
> 관리 역할: **통합·결정 세션 단일 작성자**  
> 목적: 사용자가 확정한 전체 화면 요구를 시간 흐름대로 추적하고, 구현 세션의 완료 주장만으로 체크하지 않는다.

## 체크 규칙

- `[x]`는 코드·자동 회귀와 요구된 수동 확인까지 통합 세션이 검토한 항목이다.
- `[ ]`는 미구현, 구현 중, 사용자 결정 필요 또는 수동 확인이 남은 항목이다. 각 항목 끝의 상태를 함께 읽는다.
- UIUX 세션은 이 파일을 직접 수정하지 않는다. 자기 작업 문서에 완료 인수인계를 남기고, 통합 세션이 코드·테스트·사용자 관찰을 확인한 뒤 체크한다.
- 새 요구는 기존 항목과 `동일/보완/충돌/신규`를 먼저 판정한다. 체크된 요구를 조용히 다시 열거나 다른 의미로 바꾸지 않는다.
- `이번 출시 필수`와 `Live Activity 후속`, `결정 필요`를 구분한다. 후속 항목이 미완료라는 이유로 이미 수락된 화면을 되돌리지 않는다.

## A. 공통 시각·상호작용·전환

- [x] **다크·파란 테마 유지.** 밝은 흰색 테마 전환안은 채택하지 않았다. — 사용자 확정, 현재 화면 확인
- [x] **일반 버튼 눌림 표현.** 버튼·카드 tap은 실제 눌렸다 돌아오는 scale/opacity 애니메이션을 사용한다. — `U-INTERACTION-01` 자동·실기기 수락
- [x] **일반 버튼 햅틱 금지.** CTA·뒤로가기·카드에는 햅틱을 일괄 추가하지 않는다. — `U-INTERACTION-01` 수락
- [x] **시간 wheel 관성·선택 햅틱.** 빠른 스와이프로 여러 칸 이동하고 실제 새 행에 걸릴 때만 selection haptic을 낸다. — 실기기 확인
- [x] **도착 여유 slider 햅틱.** 실제 5분 값이 바뀔 때만 selection haptic을 내고 programmatic/중복 값에는 내지 않는다. — 실기기 확인
- [ ] **메인 흐름 native stack과 상태 전환.** 시간 설정→결과→장소 상세/코스는 iOS 기본 push/back과 edge swipe를 사용하고, 코스 review→active는 같은 화면 상태로 전환해 새 stack을 쌓지 않는다. 기존 native 전환은 수락됐으나 새 상세·단일 코스 화면에서 재검증한다. — 구현 전환 필요
- [ ] **최상위 탭 즉시 전환.** 메인·주변 둘러보기·기록·내정보는 좌우 push 없이 같은 최상위 레벨에서 즉시 전환돼야 한다. — 현재 reset 구현, 탭 재편 뒤 최종 smoke 필요
- [ ] **설정/확정 CTA의 하단 배치 원칙.** 모든 버튼을 무조건 하단 고정하지 않고, 긴 화면에서 다음 행동이 사라지는 화면만 safe-area 위 fixed CTA를 사용한다. — 사용자 제안 `고려`, 화면별 확정 필요

## H. 최상위 탭과 내정보

최신 결정: [DEC-PROFILE-SETTINGS-01](profile-settings.md). 내정보는 **내 프로필 / 권한 및 맞춤 추천 / 앱 안내**만 기본 구성으로 둔다. 로그인 없이 진입 가능하며 메인 우상단 계정 버튼은 로그인 상태별 분기한다. 로그아웃·계정 삭제는 프로필 관리 안쪽, 방문 기록 조회·삭제는 기록 탭이다. 체류 동의·개인화 초기화는 별도 계약으로 연결한다. 상태: 사용자 확정·구현 전.

- [ ] 닉네임 표시/수정·프로필 관리 안쪽 로그아웃/계정 삭제 연결(기존 DB 계약 먼저 확인).
- [ ] 개인정보 안내·문의하기·버전의 간결한 앱 안내 영역(실제 링크/채널 확인).

- [x] **일반 로그인과 Route Proxy 익명 세션 분리.** 익명 Supabase session은 네트워크 인증용으로 유지하되 내정보·계정 저장·개인화에서는 비로그인으로 표시·처리한다. 자동 fixture와 로그아웃→비로그인 추천→내정보 수동 확인을 통과했다. — `U-RUNTIME-GUARD-01`, `QA-RUNTIME-GUARD-01` 수락
- [ ] **기록 탭의 로컬 기록 삭제 확인.** 내정보 중복 배치는 철회한다. guest/account와 독립된 기록은 자동 병합하지 않는다. 기록 탭의 실제 삭제 구현과 completion/legacy 삭제 범위를 먼저 확인하며 부분 삭제를 전체 삭제처럼 제공하지 않는다. — 별도 DB 계약 확인 필요
- [ ] **`내 코스` 제거·`주변 둘러보기` 전환.** 단순 탭 이름 변경이 아니라 현재 위치 기준 후보·운영시간·경로 호출·빈 상태 계약이 필요하므로 별도 제품/엔진/API 범위를 먼저 확정한다. — 미구현, 구조 UI 작업과 분리
- [ ] **주변 둘러보기의 사용자 가치.** 약속 경로용 추천과 혼동하지 않게 현재 위치 인근 장소 탐색임을 명시하고, 시간 안 코스로 검증되지 않은 장소를 검증 추천처럼 표시하지 않는다. — 결정/fixture 필요
- [ ] **내정보 체류 기록 토글.** 앱이 직접 제어하는 것은 `맞춤 추천을 위한 체류 기록` 동의뿐이며 끄기·재활성·초기화를 제공한다. — DB-DWELL/U-LIVE-ACTIVITY
- [ ] **시스템 권한 상태 행.** 위치·알림·Live Activity는 가짜 앱 토글이 아니라 현재 상태와 `설정에서 변경` 행동으로 표시한다. — UI/native 작업 필요
- [ ] **필수 개인정보·계정 행동 유지.** `권한 설정만` 남기는 방식은 채택하지 않는다. 개인정보 처리방침, 위치정보 안내, 계정 삭제 등 실제 수집·App Store 정책에 필요한 항목은 유지해야 한다. — 출시 정보 구조 확인 필요

- [ ] 작은/큰 iPhone 및 Dynamic Type에서 CTA 가림·텍스트 잘림·safe-area 확인.

- [ ] production build에서 개발 시각·QA launcher·추천 진단·CAPTCHA 진단이 노출되지 않는지 확인.
- [ ] 위치 거절/GPS 실패/네트워크 실패/카카오맵 미설치에서도 사용자가 돌아가거나 재시도할 수 있는지 확인.
- [ ] 비로그인 핵심 흐름과 로그인+체류 동의 흐름을 각각 한 번 확인하되 자동 fixture를 실기기에서 반복하지 않는다.
