# DATA-PLACE-PHOTO-RECHECK-01 — 보류 사진 사용 근거 재검토

상태: 2026-09-08 승인·조사/근거 기반 반영 전. 담당 데이터 정제. U-MAIN-COURSE-POLISH-01과 병렬 가능.

## 목적·결정

보류 약70여개 사진을 다시 조사해 추천 카드·지도 마커에서 합법적으로 사용할 수 있는 범위를 확정한다. 과거73개라는 수는 현재 집계가 아니다. 공모전 TourAPI 사용 필수나 공공기관 호스트라는 사실만으로 개별 사진의 모든 이용을 허락받았다고 결론내리지 않는다.

기존 미확인 사진 보류 → 재조사 요청 → 출처별 최신 공식 조건과 사진별 적용 근거 확인 후 허용 범위만 반영 → 사진 활용 확대와 권리 경계 유지 → 승인·구현 전. 근거 없는 허용/기본 이미지 정책 철회는 아니다.

## 실행

1. AGENTS.md, docs/README.md, 데이터 역할 README 및 연결된 최신 사진 허용목록·감사/빌드 기록을 읽는다. 과거 전체 기록 대신 최신 근거를 추적한다. 현재 보류 사진/장소/원천 ID/URL 기준으로 중복 제거 후 정확한 대상 수를 확정한다. 다른 세부분류 작업은 재실행하지 않는다.
2. TourAPI·부산 공공데이터의 공식 이용조건·권리 표시·개별 저작물 예외를 웹에서 확인한다. 링크·확인일·적용 범위를 사진/원천 ID와 연결한다. API 응답 사진과 별도 사진 서비스 라이선스를 혼동하지 않는다. 앱 현재 코드의 카드 cover/원형 마커 crop/출처 표시 방식은 읽기 전용으로 조사한다.
3. 원본 표시, 비율 유지 축소, 카드 자르기, 원형 마스킹, 출처 표시·링크 조건을 구분한다. 상업 이용/변경 조건도 확인한다. 각 사진을 카드 가능·원형 마커 가능·조건부 가능·미확인/불가로 판정하고 미확인과 명시 금지를 구별한다.
4. 현재 공개 계약으로 안전하게 표현 가능한 허용 사진만 allowlist와 기존 결정적 빌드로 반영한다. 사진 관련 필드 이외 등급·좌표·운영시간·카테고리·추천 적격성은 바꾸지 않는다. 조건을 표현할 필드/출처 UI가 없으면 먼저 인계하고 무조건 허용으로 축약하지 않는다. 미확인은 기본 이미지 유지.
5. 공식 근거를 못 찾으면 반복 호출로 작업을 무한 연장하지 말고 부족 근거·문의 필요 항목·최종 보류 수를 명시한다. 실제 API 검증은 필요한 소수만 호출량을 기록하고 키를 로그/문서/fixture에 남기지 않는다. 권리자 문의 발송·유료 구매는 별도 승인이다.

## 소유 경계·검증

data/·데이터 빌드·src/data 카탈로그는 데이터 세션만 편집한다. UI/지도/공유 타입/엔진/API/DB 수정 금지. UI 세션과 파일 소유 충돌 시 멈추고 인계한다. UI가 기존 계약을 사용하므로 새 데이터 연결은 조사 결과 뒤 통합 검토한다.

관련 이미지 권리 gate·기본 이미지 fallback·빌드 재현성·사진 외 보호 필드 불변 검증을 실행한다. 런타임 데이터 변경 시 typecheck/test:ui/npm test도 실행한다. 운영 DB 쓰기/배포/commit/push는 하지 않는다.

이 문서에 변경 파일과 목적, 유지 계약, 테스트·API 호출 수, 사진별 근거표 위치, 카드/지도 각각 허용 수·보류 수·UI 인계와 결정 필요 사항을 남긴다. URL이 열린다는 사실을 권리 증거로 쓰지 않는다.
