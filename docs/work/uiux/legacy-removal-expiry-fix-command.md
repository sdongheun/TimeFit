# U-LEGACY-SCREENS-REMOVE-01 — D 반환 만료 검사 보완

작성일: 2026-09-13. 담당: UIUX. 상태: 구현 전. 기존 제거 작업의 D 차단점 보완이며 추가 정리 작업이 아니다.

기준: [D 검증 결과](../qa-release/legacy-four-screen-removal-verification.md), [순차 작업 명령](../qa-release/legacy-four-screen-removal-command.md).

## 1. 재현부터 확인

`node --test test/ui/qa-current-course-expiry.test.mjs`를 실행한다. 현재 정상 대조2 PASS/정확 마감 및 직후4 FAIL이다. 유효한 수동 proof가 있는 CourseConfirm review를 열어 둔 채 시간이 지나면 기존 시작 CTA가 새 run을 만드는 것이 문제다. 과거 화면 삭제가 원인이라고 단정하지 않는다.

## 2. 허용 수정

- 현재 신규 코스 시작과 기존 코스의 명시 교체 직전에 원본 마감 시각을 확인한다. 기준은 session의 원본 nowIso와 remainingMin으로 결정되는 절대 시각이다. 기존 날짜/시간 계산 모듈을 확인해 재사용하고 현재 시각부터 남은 시간을 다시 부여하지 않는다.
- 현재 시각이 마감과 같거나 이후면 신규 run 생성·기존 run 취소/교체·학습 시작·외부 길찾기 같은 부수효과 전에 거절한다. 유효하지 않은 시간 입력도 안전하게 거절한다.
- 화면 렌더 때만 검사하지 않는다. 오래 열어둔 화면의 기존 handler도 클릭 시각으로 검사한다.
- 기존 코스 교체 확인창을 띄운 뒤 시간이 지날 수 있으므로 **교체 승인 콜백 실행 직전에도 재검사**한다. 최초 검사 통과만으로 교체를 허용하지 않는다.
- 날짜 경계를 보존한다. 자정 넘김이나 기기 현재 날짜를 붙이는 방식으로 원본 마감을 바꾸지 않는다. 고정 clock을 주입할 수 있는 순수 판정/포트 경계를 사용하고 임의 지연으로 해결하지 않는다.
- 만료 시 사용자에게 `설정한 시간이 지났어요. 시간을 다시 설정해 주세요.`와 같은 짧은 안내 및 기존 시간 설정 화면으로 돌아가는 행동을 제공한다. 확인만으로 기존 진행 코스나 저장 기록을 삭제하지 않는다.
- 기존 진행 코스의 단순 이어가기와 새 코스 시작/교체를 구분한다. 이번 신규 시작 guard를 이유로 이미 진행 중인 run을 종료·삭제하거나 기존 Live Activity 동작을 막지 않는다. 기존 진행의 만료/종료 정책은 변경하지 않는다.

## 3. 수정하지 않는 범위

과거 네 화면 복원, DB/migration/기존 데이터, 저장소 DTO, GPS, 추천 시간 상한180분·최대2곳, 체류 학습 정책, 일반 기록 삭제 및 추가 리팩터링은 금지한다. 현재 UIUX 소유 화면/시작 controller·관련 테스트만 최소 변경한다. 공유 API 시그니처를 바꾸면 QA에 정확한 변경을 인계한다.

## 4. 테스트와 완료 조건

1. QA 만료6건의 기대값은 변경하지 않고 전부 통과시킨다. QA 소유 파일을 직접 완화하지 않는다.
2. UIUX 소유 테스트로 아래 경계를 추가한다:
   - 원본 마감 직전 시작 허용 / 정확 마감·직후 거절.
   - 교체창을 마감 전에 열고 마감 이후 승인: 기존 run/진행 보존, 새 run·취소·길찾기 호출0.
   - 유효 시간 내 교체는 기존 동작 유지, 연타는 중복 실행0.
   - 기존 코스 이어가기 보존, 잘못된 원본 시간 입력은 부수효과0.
   - 만료 안내의 재설정 행동이 현재 네비게이션으로 연결되고 기존 기록을 지우지 않음.
3. 제거 검증과 보존 회귀, 타입 검사, 전체 UI/기본 테스트, git diff --check를 실행한다. 테스트 실패는 제품 결함/QA 인계 필요/환경 문제로 구분한다.
4. public iOS 번들 `node scripts/release-build.cjs export`를 확인한다. 외부 API/운영 DB 호출이나 실기기 성공을 fixture 결과로 주장하지 않는다.
5. 변경 파일·판정 경계·부수효과 순서·테스트/로그를 기존 `docs/work/uiux/legacy-four-screen-removal.md`에 보완 인계로 기록한다. 이전: proof 있는 review 시작 마감 검사 없음 → 대기 후 만료 시작 재현 → 실행 직전 절대 마감 검사 → 오래된 추천 실행 방지 → 상태를 함께 남긴다.

완료 표시는 **UIUX 만료 보완 완료·QA D 재검증 대기**다. 실패가 남으면 완료로 표시하지 않는다. QA가 최종 diff로 D 전체 게이트를 재실행한 뒤에만 E 실기기 수락으로 진행한다. 커밋·push·배포·DB 정리는 이 명령에 포함하지 않는다.
