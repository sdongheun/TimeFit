# TimeFit 요구사항 결정 트리: 추천 장소 탐색

## TIME-01 · 현재 자투리 시간 모델

- 부모 결정: 없음
- 결정: 출시 UI는 현재 시각에서 시작한다. 미래 시각 입력은 출시 화면에서 제외한다.
- 이유: 이 앱은 미래 일정 계획보다 지금 비는 시간을 활용하는 서비스다.

### TIME-01.1 · 개발 테스트 시각

- 부모 결정: `TIME-01`
- 이 질문으로 이어진 이유: 운영 UI에서 미래 시각을 숨겨도 새벽, 운영시간 경계, 과거·미래 시나리오는 반복 검증해야 한다.
- 결정: 개발 빌드와 자동화 하네스에서는 고정 시각, 출발지 좌표, 도착지·종료 시각을 주입한다. 출시 UI에는 노출하지 않는다.

### TIME-01.2 · 도착지 없음

- 부모 결정: `TIME-01`
- 이 질문으로 이어진 이유: 종료 지점이 없으면 마지막 장소에서 시간을 끝내는 과대 추천이 생긴다.
- 결정: 도착지 미입력은 출발지 복귀 왕복이다. 화면에는 `현재 위치로 돌아오기`로 표시한다.

### TIME-01.3 · 도착지 있음

- 부모 결정: `TIME-01`
- 이 질문으로 이어진 이유: 현재 시각 고정 흐름에서 최소 입력으로 종료 조건을 완성해야 한다.
- 결정: 약속·집·역 등 선택한 장소를 마지막 도착지로 사용하고, 그 종료 시각 안에 도착해야 한다. GPS 실패나 권한 거절 때 직접 입력한 출발지에도 같은 복귀 규칙을 적용한다.

## REC-01 · 실제 경로 기반 탐색

- 부모 결정: 없음
- 이 질문을 하는 이유: 후보 수 부족을 해결하면서도 서면→사상에서 부산역 후보가 섞이는 등 공간 관련성 오류를 제거해야 한다.
- 결정: 기본 탐색은 실제 이동 축 주변 생활권으로 제한하고, 더 넓은 탐색은 명시적 사용자 선택으로만 허용한다.

### REC-01.1 · 확장 상한

- 부모 결정: `REC-01`
- 이 질문으로 이어진 이유: 공간 확장 상한이 없으면 기본 추천의 관련성이 무너진다.
- 결정: 사용자가 슬라이더를 조작한 경우에만 반경을 최대 8km까지 확장한다.

### REC-01.2 · 기준 경로 실패

- 부모 결정: `REC-01`
- 이 질문으로 이어진 이유: 실제 경로 API 실패를 직선 경로로 감추면 추천 근거가 거짓이 된다.
- 결정: 성공한 기준 경로만 사용한다. 세 수단이 모두 실패하면 슬라이더 확장값을 적용하지 않고 양 끝의 기본 1km 생활권만 표시한다.

### REC-01.3 · 자동 확장

- 부모 결정: `REC-01`
- 이 질문으로 이어진 이유: 후보 수 부족을 자동 공간 확장으로 해결하면 사용자가 원하지 않는 먼 장소가 기본 추천에 섞인다.
- 결정: 자동 확장은 하지 않는다. 슬라이더를 사용자가 직접 조작할 때만 확장한다.

### REC-01.4 · 근사와 실제 경로

- 부모 결정: `REC-01`
- 이 질문으로 이어진 이유: 모든 후보의 실제 경로 호출은 무료 API 사용량과 초기 반응성을 훼손한다.
- 결정: 후보 목록은 근사값으로 표시하고, 장소 선택 후 실제 구간 경로로 적합성을 확정한다.
