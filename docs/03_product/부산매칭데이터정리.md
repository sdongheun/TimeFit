# 부산 매칭 데이터 정리 목표

> 작성: 2026-07-23 · 목적: AI-Hub 원본 데이터를 다시 정리해 TimeFit MVP 추천 후보를 부산 매칭 장소로 제한한다.

## 1. 타깃

- **지역:** 부산 전용
- **사용자:** 부산에 출장·여행을 와서 약속 전 시간이 비는 사람, 특히 직장인
- **상황:** 다음 약속 전 자투리 시간에 가볍게 둘러볼 곳을 찾는 상황

## 2. 추천 범위

- 자투리 시간은 **최대 4시간(240분)** 까지만 다룬다.
- 한 코스는 **1~2개 장소**까지만 추천한다.
- 계산 기준은 항상 다음 식이다.

```text
현재 위치 -> 장소 1 -> (장소 2) -> 출발지/약속장소
이동시간 + 체류시간 <= 입력 시간 - 안전버퍼
```

## 3. 장소 원칙

MVP에서는 **웨이팅 리스크가 큰 음식점/카페를 추천 후보에서 제외**한다. 앱의 목적은 맛집 추천이 아니라 남는 시간 활용이다.

우선 포함하는 TourAPI 타입:

| contentTypeId | 의미 | 포함 이유 |
|---|---|---|
| `12` | 관광지 | 자연관광·명소·가볍게 둘러볼 장소 |
| `14` | 문화시설 | 박물관·전시·실내 대안 |
| `28` | 레포츠 | 짧은 체험 가능 후보만 향후 선별 |
| `38` | 쇼핑 | 시장·거리·쇼핑 장소 |

우선 제외하는 TourAPI 타입:

| contentTypeId | 의미 | 제외 이유 |
|---|---|---|
| `39` | 음식점 | 웨이팅·식사시간 변동이 커서 MVP 추천 제외 |
| `32` | 숙박 | 자투리 시간 코스와 무관 |
| `15` | 축제공연행사 | 날짜·운영·혼잡 변수가 커서 후순위 |
| `25` | 여행코스 | 단일 장소가 아니라 코스 콘텐츠라 엔진 후보로 부적합 |

## 4. 데이터 원칙

추천 후보는 **TourAPI 부산 장소이면서 AI-Hub 부산 방문 데이터와 매칭된 장소**만 사용한다.

매칭 기준:

1. 이름 정규화 일치
2. 좌표 거리 150m 이내
3. 둘 다 있으면 `name+coord`, 좌표만 있으면 `coord`, 이름만 있으면 `name`

앱에서 최종적으로 필요한 데이터는 다음 형태다.

```text
src/data/busan_matched_poi.json
```

이 파일은 TourAPI `contentId`를 기준으로 AI-Hub 체류시간을 붙인 부산 추천 후보 마스터다.

## 5. 산출 JSON

`scripts/build_busan_matched_poi.mjs`가 생성한다.

| 파일 | 역할 |
|---|---|
| `data/processed/busan_matched_poi.json` | 작업용 산출물 |
| `data/processed/busan_unmatched_tourapi.json` | 현재 AI-Hub 부산 방문지와 매칭되지 않아 제외된 TourAPI 부산 후보 |
| `src/data/busan_matched_poi.json` | 앱 번들용 복사본 |

필드 예시:

```json
{
  "contentId": "126081",
  "title": "광안리해수욕장",
  "contentTypeId": "12",
  "category": "자연관광지",
  "lat": 35.153,
  "lon": 129.118,
  "aihubName": "광안리해수욕장",
  "matchType": "name+coord",
  "matchDistanceM": 12,
  "dwell": {
    "count": 182,
    "median": 30,
    "p25": 30,
    "p75": 60,
    "mean": 42
  }
}
```

## 6. 다음 구현 순서

1. 부산 매칭 후보 JSON 생성
2. 미매칭 후보 JSON을 검수해 카테고리 폴백 후보로 승격할 장소를 선별
3. 엔진에서 TourAPI 후보를 `busan_matched_poi.json`에 있는 `contentId`만 통과시키기
4. 단일 장소 추천을 먼저 안정화
5. 이후 2개 장소 미니코스로 확장
6. 버스/도보/자차 이동시간을 각각 정확히 분리
