# TimeFit UI/UX 개편 초안

> 상태: 논의 중. 이 문서는 현재 구현을 그대로 유지하겠다는 명세가 아니라, 다음 UI/UX 개편에서 결정할 흐름과 검증 기준을 정리한다.
>
> 참고 이미지 1: iOS 시계 앱의 알람 편집 화면. 시간 선택의 명확한 휠 피커, 취소와 확정의 분리, 한 화면에 한 가지 과업만 두는 방식을 참고한다.

## 1. 제품 목표

TimeFit은 부산에서 약속 전 또는 다음 일정 전의 남는 시간에 들를 장소를 고르고, 이동과 체류를 합쳐 약속에 늦지 않는 개인 코스를 만드는 앱이다.

- 사용자는 먼저 코스를 직접 만들기 시작하고, 추천 후보는 지도 위에서 비교한다.
- 약속 도착 가능성은 최우선 조건이다.
- 장소를 담을수록 남은 시간과 가능한 다음 장소가 즉시 바뀐다.
- 실제 길안내와 장소 상세 확인은 카카오맵에 맡긴다.
- 사용자는 여러 코스를 저장해 비교할 수 있고, 결정한 코스만 길찾기를 시작한다.

## 2. 확정된 정보 구조

하단 플로팅 바는 항상 다음 3개만 제공한다.

| 탭 | 역할 |
| --- | --- |
| 메인 | 새 코스 만들기 진입, 진행 중 코스가 있으면 재개 진입 |
| 내 코스 | 저장한 코스 목록, 삭제, 길찾기 시작 |
| 내 정보 | 권한 상태, 테스트 설정, 이후 사용자화 설정 |

`추천`, `장바구니`, `코스 상세`는 별도 탭이 아니다. 메인에서 새 코스를 만들 때 이어지는 하나의 작업 흐름이다.

## 3. 사용자 흐름

### 3.1 첫 실행

1. 짧은 온보딩에서 "남는 시간 안에 약속 전 코스를 만든다"는 목적과 위치·알림 사용 이유를 설명한다.
2. 위치 권한은 사용자가 `현재 위치 사용`을 처음 누를 때 요청한다. 거절해도 장소 검색과 직접 입력으로 계속 사용할 수 있어야 한다.
3. 알림 권한은 사용자가 첫 코스를 저장하거나 `출발 알림 켜기`를 선택할 때 요청한다. iOS는 거절 후 앱이 같은 시스템 권한 팝업을 다시 띄울 수 없으므로, 최초 실행 직후 일괄 요청하지 않는다.
4. 권한을 거절한 경우 내 정보에서 설정 앱으로 이동하는 안내를 제공한다.

### 3.2 메인에서 코스 만들기까지

`메인` -> `새 코스 만들기` -> `로그인/회원가입` -> `시간·장소·이동수단 입력` -> `장소 후보 지도` -> `장바구니/코스 만들기`

서비스 소개와 예시 코스는 로그인 전에도 볼 수 있지만, 추천 계산·장바구니·저장·길찾기·후기 사용은 로그인 후에만 허용한다. 모든 추천 행동을 계정 기반 개인화 데이터로 연결하기 위한 정책이다.

입력 화면은 알람 편집 화면처럼 하나의 집중된 화면으로 만든다.

- 시작 시각과 종료 시각을 휠 피커로 고른다. 앱은 `종료 - 시작`으로 남은 시간을 계산하며 최대 240분만 허용한다.
- 시작 위치는 `현재 위치` 또는 장소·주소 검색 중 선택한다.
- 다음 일정 장소는 선택 사항이다. 입력하면 해당 장소 도착이 종료 시각의 제약이 되고, 비우면 출발지로 돌아오는 코스로 계산한다.
- 이동수단은 도보, 대중교통, 차량 중 하나를 선택한다.
- 테스트 시각은 일반 입력 화면에 두지 않는다. `내 정보 > 테스트 설정`에서만 켜고, 테스트 활성 상태는 입력 화면에 작은 배지로 표시한다. 실사용 시간과 테스트 시간이 섞이지 않아야 한다.
- 자정을 넘는 코스는 첫 버전에서 허용하지 않는다. 종료 시각은 시작 시각보다 뒤여야 한다.

### 3.3 후보 지도와 장바구니

`장소 후보` 화면은 지도가 배경 전체를 차지하고, 하단 시트가 그 위에 올라오는 구조로 바꾼다.

- 지도: 현재 위치, 다음 일정 장소, 후보 장소 마커와 이름을 표시한다.
- 하단 시트: 접힌 상태에서는 핵심 후보 한두 개만 보이고, 드래그해 확장하면 스크롤 가능한 장소 목록과 상세 근거를 본다.
- 목록의 각 장소에는 카테고리, 이동 시간, 가능한 체류 시간, 운영시간 확인 상태, 카카오맵 확인 링크를 표시한다.
- 상단 제목 오른쪽에는 장바구니 아이콘과 선택 수를 표시한다.
- 장소를 담으면 이동시간과 체류시간을 다시 계산한다. 시간 안에 가능한 후보만 다음 선택 후보로 남기되, 이미 담은 장소와 현재 코스 정보는 항상 보인다.
- 시간 초과 후보를 단순히 숨기는 대신, 현재 요구사항대로 다음 선택 단계에서는 제외한다. 후보를 담기 전의 초기 목록에는 짧게 가능·빠듯함 상태를 구분해 보여줄 수 있다.

### 3.4 코스 만들기와 저장

장바구니 화면과 코스 상세 화면은 하나의 `코스 만들기` 화면으로 합친다.

- 선택 순서를 자동으로 제안하고, 사용자가 위·아래 조정으로 바꿀 수 있다.
- 지도, 방문 순서, 구간별 이동·체류 시간, 약속 도착 여유시간을 한 화면에서 함께 본다.
- `내 코스에 저장`: 저장 완료 토스트를 보여준 뒤 같은 코스 만들기 화면으로 돌아간다. 다른 조합을 이어서 만들 수 있어야 한다.
- `길찾기 시작`: 아직 저장하지 않은 코스도 먼저 자동 저장한 뒤 `내 코스 > 코스 진행` 흐름으로 이동한다. 저장되지 않은 상태로 진행 중 화면만 남는 문제를 피한다.

### 3.5 내 코스와 실행

`내 코스`는 비어 있어도 항상 접근 가능하며, 저장 코스 목록을 보여준다.

- 목록의 코스를 선택하면 코스 요약과 `길찾기 시작`을 확인할 수 있다.
- 길찾기 시작 후에는 `내 코스 목록` 위에 `코스 진행` 화면을 쌓는다. 진행 화면의 뒤로가기는 내 코스 목록으로 돌아간다.
- 구간별 `카카오맵으로 길찾기`는 현재 위치를 출발지로 사용하고, 다음 목적지만 카카오맵에 전달한다.
- 앱을 떠났다가 돌아온 경우에도 진행 상태와 저장 코스가 유지되어야 한다.
- 저장 코스를 삭제하면 관련 출발 알림도 함께 취소한다.

### 3.6 완료와 평가

마지막 장소 또는 약속 장소에 도착하면 코스를 완료한다.

- 간단한 만족도와 장소별 평가를 받는다.
- 첫 단계에서는 기기 저장소에 보관하고, Supabase 도입 뒤 사용자·코스·장소 단위로 동기화한다.
- 평가는 다음 추천의 장소 매력도와 사용자 취향 신호로 사용한다. 평가를 건너뛰어도 코스 완료는 가능해야 한다.

## 4. 현재 구현과의 차이

| 항목 | 현재 | 개편 방향 |
| --- | --- | --- |
| 메인 | 남은 시간, 테스트 시각 등을 바로 입력 | 별도 메인과 `새 코스 만들기` 진입점 |
| 시간 | 분 단위 남은 시간 입력 | 시작·종료 시각 선택 후 자동 계산 |
| 지도 | 상단 약 45%, 하단 고정 목록 | 전체 지도와 드래그 가능한 하단 시트 |
| 코스 화면 | 장바구니와 상세가 분리 | 편집·검토·순서 조정을 한 화면에 통합 |
| 저장 후 이동 | 저장하면 내 코스 목록으로 이동 | 저장 확인 후 코스 만들기 유지 |
| 진행 진입 | 상세 화면에서 실행 화면으로 이동 | 자동 저장 후 내 코스 목록 위에 실행 화면 표시 |
| 저장 데이터 | 앱 메모리에만 있어 재시작 시 사라짐 | AsyncStorage 우선 영속화, 이후 Supabase 동기화 |
| 권한 | 앱 시작 시 알림 권한 요청 가능 | 설명 후 기능을 처음 사용할 때 각각 요청 |

## 5. E2E에서 깨지기 쉬운 지점

### 제품 흐름 위험

1. 권한을 거절했을 때 현재 위치와 알림 기능이 없어도 코스 만들기가 끝까지 가능해야 한다.
2. 시간 입력은 종료 시각이 시작보다 빠른 경우, 240분 초과, 자정 넘김, 약속 장소 미입력(왕복)을 명확히 처리해야 한다.
3. 지도는 SDK·네트워크 실패 시에도 후보 목록과 장바구니가 작동해야 한다. 지도 실패가 추천 실패가 되어서는 안 된다.
4. 하단 시트의 드래그와 목록 스크롤이 충돌하지 않아야 하며, 지도 조작 중에는 시트가 의도치 않게 닫히지 않아야 한다.
5. 카카오맵 외부 전환 뒤 앱으로 돌아오면 현재 선택 장소, 장바구니, 진행 구간이 보존되어야 한다.
6. `길찾기 시작`을 여러 번 눌러도 동일 코스가 중복 저장되거나 알림이 중복 예약되면 안 된다.
7. 코스 삭제·완료·취소 때 알림이 모두 취소되어야 하며, 이미 지난 시각에는 알림을 예약하지 않아야 한다.
8. 저장한 코스와 진행 중 코스가 앱 재시작 후 사라지면 내 코스 탭의 약속이 깨진다. 영속화가 선행돼야 한다.
9. 화면 전환은 현재처럼 탭을 누를 때 스택을 모두 초기화하지 않도록 재설계해야 한다. 특히 `코스 진행`의 뒤로가기는 내 코스 목록으로 정확히 돌아가야 한다.

### 자동화 기반 위험

현재 프로젝트에는 모바일 E2E 도구와 화면 식별자(`testID`)가 거의 없다. UI 개편과 함께 다음을 준비해야 한다.

1. 모든 주요 버튼, 시간 선택값, 장소 목록, 장바구니 수, 저장 토스트에 안정적인 `testID`와 접근성 라벨을 부여한다.
2. 실제 현재 시각, GPS, TMAP·ODSAY·카카오 API 응답을 테스트에서 주입 가능한 인터페이스로 분리한다. 외부 API 결과에 의존하면 같은 테스트가 매번 달라진다.
3. 테스트 모드는 내 정보에 숨기되, E2E에서는 고정 시각·고정 위치·고정 경로 응답을 사용한다.
4. iOS 시스템 권한 팝업과 카카오맵 외부 앱은 앱 내부 E2E로 완전히 제어하기 어렵다. 앱에서는 권한 허용·거절 뒤 상태와 딥링크 복귀 처리를 검증하고, 실제 팝업·카카오맵은 실기기 수동 시나리오로 별도 확인한다.
5. 우선순위 시나리오는 `첫 실행/권한 거절`, `시간 검증`, `장바구니 0·1·3곳`, `저장 후 원래 편집 화면 복귀`, `저장 코스 재시작`, `외부 길찾기 복귀`, `삭제·완료 시 알림 취소`, `앱 재시작 뒤 복원`이다.

## 6. 구현 전에 결정할 질문

1. 종료 시각은 항상 약속 도착 시각인가, 약속 장소가 없는 왕복 코스의 종료 시각도 같은 방식으로 입력하는가?
2. 메인 화면의 첫 화면에는 무엇을 가장 크게 둘 것인가? 권장안은 `새 코스 만들기`와, 진행 중 코스가 있을 때만 `진행 중인 코스 계속하기` 두 가지다.
3. 첫 실행 온보딩에서 위치와 알림을 모두 설명하되, 실제 시스템 권한 요청은 기능 진입 시점으로 분리하는 데 동의하는가?
4. `길찾기 시작` 시 저장하지 않은 코스를 자동 저장하는 정책으로 확정하는가?
5. 코스는 기기 재시작 뒤에도 보존해야 하므로, 다음 구현 단계에서 AsyncStorage 영속화를 먼저 적용해도 되는가?
6. 시간 휠 선택은 5분 단위로 제한할 것인가, 1분 단위까지 열어둘 것인가? 공모전 시연과 사용성을 고려하면 5분 단위가 적절하다.

## 7. 구현 순서

1. 코스·진행 상태의 영속화와 내 코스/실행 화면의 스택 규칙을 먼저 정리한다.
2. 시간 입력 모델을 `시작/종료`로 바꾸고 테스트 시각을 내 정보로 옮긴다.
3. 별도 메인 화면과 첫 실행 온보딩을 만든다.
4. 후보 화면을 전체 지도 + 하단 시트로 바꾼다.
5. 장바구니와 상세를 하나의 코스 만들기 화면으로 통합한다.
6. `testID`, 고정 시각·위치 주입, 모바일 E2E 기반을 추가한다.
7. 후기와 Supabase 동기화는 계정·DB 설계 이후 연결한다.
