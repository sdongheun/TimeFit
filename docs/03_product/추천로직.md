## 1. 확정 원칙 (2026-08-08)

### 1.1 결과와 우선순위

- 결과의 기본 단위는 **완성 코스가 아닌 장바구니에 담을 장소 후보**다.
- **1순위 하드 조건**: 선택한 이동수단으로 이동하고 최소 체류시간을 확보한 뒤, 안전 여유시간을 남기고 약속 장소에 도착하거나 출발지로 복귀할 수 있어야 한다.
- **2순위 랭킹 조건(현행)**: 1순위를 통과한 후보 안에서 체류 여유, 이동 대비 체류, 시간대 적합도, AIHub 매칭 신뢰도, 장소 간 밀집도와 카테고리 다양성을 반영한다.
- 음식점·카페와 관광 활동 장소는 동일 후보 풀에서 다룬다. 다만 시간대 적합도·이동·운영시간·시설형 체류 조건에 따라 순위는 달라질 수 있다.
- 장소 매력은 사용 후 후기 만족도로 만들 계획이며, 현재는 **랭킹 점수에 반영하지 않는다.** 로컬 후기 수집만 구현돼 있다.

### 1.2 후보 데이터 범위

| 등급 | 현재 추천 사용 | 체류시간 근거 | 비고 |
|---|---|---|---|
| 직접 매칭 85개 | 사용 | 독립 장소의 이름+좌표 AIHub 체류시간 중앙값 | 개별 장소 체류시간 근거가 가장 강함 |
| 포괄 매칭 42개 | 사용 | 시장·공원·거리 등 지역 맥락의 AIHub 체류시간 중앙값 | 내부 상점에 상속하지 않음 |
| 카테고리 폴백 797개 | 사용 | AIHub 카테고리 중앙값 | TourAPI 또는 부산시 공식 명소·쇼핑·맛집 데이터의 유효 장소 |
| 보류 231개 | 미사용 | 없음 | 포괄 장소 내부·동명 지점·미분류·복수 장소 표기 후보 |

### 1.3 이동수단과 지도 UX

- 사용자는 추천 전에 `도보`, `차량`, `대중교통` 중 한 가지를 선택한다. 선택 수단만 추천 가능 여부와 순위의 기준이 된다.
- 후보 화면은 상단 지도와 하단 플로팅 시트로 구성한다. 지도에는 현재 위치·약속 장소·후보 마커와 이름을, 시트에는 스크롤 가능한 장소 목록과 상세 설명을 표시한다.
- 카테고리 필터는 구현됐다. 마커 클러스터링은 아직 구현하지 않았으며, 후보 수가 늘어난 뒤 별도 UX 작업으로 진행한다. 지도에 보이는 후보는 모두 강한 자동 추천이 아니라, 시간 조건을 통과한 선택 가능 후보다.
- 추천 가능한 모든 장소에는 정확한 카카오맵 상세 링크를 제공한다. 카카오 검색에서 확인되지 않은 장소는 추천에서 제외한다. 사용자는 메뉴·가격·사진·후기·운영시간을 카카오맵에서 확인한 뒤 TimeFit 장바구니로 돌아와 선택한다.
- 사용자가 첫 장소를 담으면 `현재 위치 -> 담은 장소들 -> 약속 장소` 기준으로 즉시 시간을 다시 계산한다. 기존 후보는 계속 보이되, 추가할 수 없는 장소는 `시간 초과` 상태와 부족 사유를 표시하고 장바구니 추가를 막는다.
- 코스 장소 수는 1~2곳으로 고정하지 않는다. 시간 조건을 통과하는 동안 3곳 이상도 담을 수 있다.
- 초기 방문 순서는 앱이 이동시간이 가장 짧은 순서로 자동 정렬한다. 사용자는 장바구니에서 1·2·3번 순서를 직접 바꿀 수 있고, 변경 즉시 시간 적합성을 다시 계산한다.
- 같은 조건에서 같은 장소가 재표시되는 것은 허용한다. 기본 점수 차이가 작은 후보만 약하게 순환할 수 있으며, 지도 탐색·필터·장바구니 상태로 선택지를 탐색하게 한다.

### 1.4 시간 예산 규칙

```text
buffer = 이동수단별 고정 안전 여유시간
budget = 남은시간 - buffer
```

| 이동수단 | 안전 여유시간 | 추천 예산 |
|---:|---:|---:|
| 도보 | 15분 | 남은시간 - 15분 |
| 대중교통 | 20분 | 남은시간 - 20분 |
| 차량 | 10분 | 남은시간 - 10분 |

이 예산 안에서 `현재 위치 -> 담은 장소들 -> 약속 장소`(약속이 없으면 출발지 복귀)의 이동시간과 체류시간을 계산한다. 최소 체류시간과 이동 대비 체류 규칙은 [2-1. 시간 안전·체류 정책](#2-1-시간-안전체류-정책)을 단일 기준으로 사용한다.

### 1.5 운영시간 확인과 카카오맵 상세 연결

- **현행 데이터**: TourAPI 원본 ID가 있는 장소는 `detailIntro2`에서 운영시간 문자열을 파싱해 게이트를 적용한다. 부산시 공식 데이터 단독 장소는 제공된 운영시간 문구를 안내하며 자동 영업 판정은 하지 않는다.
- **확정 정책**: 운영시간 미확인 장소를 일괄 제외하지 않는다. 추천 장소 전체에 카카오맵 상세 링크를 제공해 사용자가 메뉴·가격·사진·후기·운영시간을 직접 확인하도록 한다.
- **표현 원칙**: 앱은 운영시간을 확인하지 못한 장소에 대해 `현재 영업 중` 또는 `이용 가능`이라고 단정하지 않는다. 장소 상세 확인은 카카오맵, 시간 예산·장바구니·약속 도착 가능성 계산은 TimeFit이 담당한다.
- **구현 작업**: 카카오 검색에서 확인된 장소에는 Kakao Place ID와 `place_url`을 저장한다. `not_found`는 보관만 하고 추천 엔진에서 제외한다.

## 2. 현행 파이프라인 (7단계)

```
입력: 현재위치 · 약속(장소·시각)|없음 · 남은시간 · 이동수단 · 요일/시간대
  │
  ▼
[0] 예산       이동수단별 안전 여유시간(도보 15 / 대중교통 20 / 차량 10) → budget = 남은시간 − buffer
               target = 약속장소 (없으면 현재위치=왕복)
  │
  ▼
[1] 후보 수집   앱 번들 `busan_poi_catalog.json`의 정제 후보 924개를 선택 수단·남은시간별 반경으로 탐색
               도보: 1,000m(≤120분), 1,500m(>120분)
               차량: 2,000m(≤60분), 4,000m(≤120분), 8,000m(>120분)
               대중교통: 1,500m(≤60분), 3,000m(≤120분), 6,000m(>120분)
               → matched 127개: 독립 장소는 이름+좌표 AI-Hub 매칭, 포괄 장소는 지역 맥락 체류시간
               → unmatched 797개: categoryDwell 카테고리 중앙값 폴백
               → 포괄 장소 내부·동명 지점·미분류·복수 표기 231개와 제외 6개는 후보에서 제외
  │
  ▼
[2] 1차 컷     선택 수단 기준 최소 체류시간과 방향성(우회율)을 충족하면 통과
               진단: 원시 후보 수 → 시간·방향 통과 후보 수를 기록
  │
  ▼
```

## 2-1. 시간 안전·체류 정책 (2026-08-08 확정)

### 안전 여유시간

약속 지연 위험이 수단마다 다르므로, 입력한 남은 시간에서 아래 시간을 먼저 확보한다. 이전의 `남은 시간 12%` 계산은 사용하지 않는다.

| 이동수단 | 안전 여유시간 | 이유 |
|---|---:|---|
| 도보 | 15분 | 신호·보행 속도 차이 대응 |
| 대중교통 | 20분 | 접근 도보·환승·배차 변동 대응 |
| 차량 | 10분 | 교통 상황은 있으나 경로 재탐색이 쉬움 |

### 최소 체류시간

- 기본값은 장소당 `30분`이다.
- 자연관광지와 거리·골목·광장·시장 성격의 상업지구만 접근 이동시간에 따라 예외를 둔다.
  - 접근 `10분 이하`: `15분`
  - 접근 `11~15분`: `20분`
  - 접근 `16분 이상`: `30분`
- 카페·식당·문화시설·레저/스포츠와 개별상점·아울렛은 시설형·유료 성격으로 본다.

### 이동 대비 체류

약속지까지 원래 가야 하는 시간 자체는 불이익으로 계산하지 않는다. 대신 `경유 장소를 넣어 추가된 이동시간`과 체류시간을 비교한다.

- 시설형·유료 성격: 배정 체류시간이 추가 이동시간보다 짧으면 추천 및 장바구니 추가에서 제외한다.
- 자연·거리·광장 등 가볍게 구경 가능한 장소: 시간 예산과 최소 체류시간을 충족하면 표시한다. 추가 이동시간이 체류시간보다 길면 **제외하지 않고 낮은 순위**로 둔다.
- 장바구니에서 장소를 추가할 때도 같은 정책을 즉시 재계산한다.

운영시간이 확인되지 않은 장소는 추천에서 제거하지 않는다. 모든 후보의 카카오맵 상세 링크를 제공해 사용자가 영업 여부·메뉴·후기를 확인한다.

## 3. 랭킹 v1 상세 (결정적·설명가능)

```
기본 점수 = 0.30 · min(1, 체류 가능 시간 / 60)
          + 0.20 · 체류시간 / (이동시간 + 체류시간)
          + 0.20 · 시간대 적합도
          + 0.15 · AIHub 매칭 신뢰도
          + 0.15 · 장소 간 밀집도
          + 전략·짧은 시간·지하철 보너스
          − 카테고리 폴백·운영시간 신뢰도·지도 검증·우회·대중교통 폴백 등 감점

그리디 선택 시: − 0.15 × 이미 뽑힌 동일 카테고리 수
점수 차이 0.035 이내 후보만 약하게 순환
```

`시간활용 = (이동시간 + 체류시간) / budget`은 현재 계산만 하며 최종 점수에는 반영하지 않는다. 시간 활용 가중치 조정은 별도 추천 로직 고도화 작업으로 남긴다.

**시간대 적합표** (미기재 카테고리 = 0.6):

| | 카페 | 식당 | 자연 | 문화 | 상업 | 레저 | 축제 |
|---|---|---|---|---|---|---|---|
| 아침 | **1.0** | 0.4 | 0.9 | 0.6 | 0.6 | 0.7 | 0.6 |
| 점심 | 0.7 | **1.0** | 0.6 | 0.6 | 0.6 | 0.6 | 0.6 |
| 오후 | 0.8 | 0.4 | **1.0** | **1.0** | 0.9 | 0.9 | 0.9 |
| 저녁 | 0.8 | **1.0** | 0.6 | 0.6 | 0.8 | 0.6 | 0.9 |
| 야간 | 0.8 | 0.7 | 0.6 | 0.6 | 0.8 | 0.6 | 0.8 |

**설명가능성**: 각 코스에 `why = "체류 85% · 오후 적합 100%"` 부착 → 결과 카드에 표시. "왜 이게 1위냐"에 점수 내역으로 답한다.

**검증 기록**: 2026-07-05의 장소 예시는 이후 카탈로그 정제·운영시간·이동수단 정책이 바뀌었으므로 현재 추천 결과의 기준으로 사용하지 않는다. 현재 후보 품질은 `docs/reports/recommendation_audit*.html`과 자동진단 기준으로 확인한다.
