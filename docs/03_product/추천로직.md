## 1. 현행 파이프라인 (7단계)

```
입력: 현재위치 · 약속(장소·시각)|없음 · 남은시간 · 이동수단 · 요일/시간대
  │
  ▼
[0] 예산       buffer = max(10분, 남은시간×12%) → budget = 남은시간 − buffer
               target = 약속장소 (없으면 현재위치=왕복)
  │
  ▼
[1] 후보 수집   TourAPI locationBasedList2 — 반경 1,500m 고정 · 최대 60건
               → 카테고리 매핑 → 체류시간: POI실측(표본≥5) → 카테고리 중앙값
                 × 혼잡배수(완화: 원배수 영향 50%, 0.9~1.2 클램프, 5분 반올림)
  │
  ▼
[2] 1차 컷     haversine 왕복추정 + 체류 ≤ budget · 가까운 순
  │
  ▼
[3] 게이트     가까운 순 상위 16개만 detailIntro2
               운영시간 내? + 축제(15)는 행사기간(eventstart~end) 내?
  │
  ▼
[4] 조립       (haversine만, TMAP 0건)
               단일: 통과 전부 · 미니코스 2곳: 상위 8 풀, 카테고리 상이, 예산 60~100%
  │
  ▼
[5] 랭킹 v1 ⭐  score = 0.4·체류비율 + 0.3·시간활용 + 0.3·시간대적합 + 0.05·(스팟수−1)
               → 그리디 선택: 이미 뽑힌 카테고리 −0.15/회 (다양성)
               → 상위 24개 대기열
  │
  ▼
[6] 지연 정밀화  첫 5개: 구간만 TMAP(시간+실경로) → 예산 재검증 → 확정
               나머지 = pending → [🔄 다른 코스 보기]가 다음 5개 소비
  │
  ▼
출력: 코스 5개(why 포함) + 대기열 · 새로고침 배치당 ~10건 호출
```

## 2. 랭킹 v1 상세 (결정적·설명가능)

```
score(코스) = 0.4 · 체류비율    (Σ체류/총소요 — 이동 낭비 벌점)
            + 0.3 · 시간활용    (총소요/budget — 알차게)
            + 0.3 · 시간대적합  (스팟 카테고리 × 시간대 표, 평균)
            + 0.05 · (스팟수−1) (미니코스 소폭 가점)
선택 시:    − 0.15 × 이미 뽑힌 동일 카테고리 수 (그리디 다양성)
```

**시간대 적합표** (미기재 카테고리 = 0.6):

| | 카페 | 식당 | 자연 | 문화 | 상업 | 레저 | 축제 |
|---|---|---|---|---|---|---|---|
| 아침 | **1.0** | 0.4 | 0.9 | 0.6 | 0.6 | 0.7 | 0.6 |
| 점심 | 0.7 | **1.0** | 0.6 | 0.6 | 0.6 | 0.6 | 0.6 |
| 오후 | 0.8 | 0.4 | **1.0** | **1.0** | 0.9 | 0.9 | 0.9 |
| 저녁 | 0.8 | **1.0** | 0.6 | 0.6 | 0.8 | 0.6 | 0.9 |
| 야간 | 0.8 | 0.7 | 0.6 | 0.6 | 0.8 | 0.6 | 0.8 |

**설명가능성**: 각 코스에 `why = "체류 85% · 오후 적합 100%"` 부착 → 결과 카드에 표시. "왜 이게 1위냐"에 점수 내역으로 답한다.

**검증 결과 (2026-07-05 라이브)**: 오후 도보 120분 → 놀이마루(문화)·그런고로(자연)·부전마켓타운(상업)·희와제과(카페)·전포공구길 — 식당은 적합 40%로 하위권. 20/20 어서션 통과.

## 5. 원칙 (불변)

- **ML 없음** — 가중치는 손으로 정하고, 근거를 문서에 남긴다 (데이터 해상도·설명가능성, `AI허브_체류시간데이터.md` 참조)
- **모든 코스는 why를 가진다** — 점수 내역으로 설명 못 하는 랭킹 변경 금지
- **TMAP 호출 상한 의식** — 랭킹/후보 변경이 추천당 호출 수를 늘리면 안 됨 (현행 ~10건/배치)
- **이 문서와 코드는 항상 일치** — planner.ts 수정 커밋에 본 문서 갱신 포함
