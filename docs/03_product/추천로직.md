## 1. 확정 원칙 (2026-08-08)

### 1.1 결과와 우선순위

- 결과의 기본 단위는 **완성 코스가 아닌 장바구니에 담을 장소 후보**다.
- **1순위 하드 조건**: 선택한 이동수단으로 이동하고 최소 체류시간을 확보한 뒤, 안전 여유시간을 남기고 약속 장소에 도착하거나 출발지로 복귀할 수 있어야 한다.
- **2순위 랭킹 조건(현행)**: 1순위를 통과한 후보 안에서 체류 여유, 이동 대비 체류, 시간대 적합도, AIHub 매칭 신뢰도, 장소 간 밀집도와 카테고리 다양성을 반영한다.
- 음식점·카페와 관광 활동 장소는 동일 후보 풀에서 다룬다. 다만 시간대 적합도·이동·운영시간·시설형 체류 조건에 따라 순위는 달라질 수 있다.
- 장소 매력은 사용 후 후기 만족도로 만들 계획이며, 현재는 **랭킹 점수에 반영하지 않는다.** 로컬 후기 수집만 구현돼 있다.

### 1.3 이동수단과 지도 UX

- 사용자는 추천 전에 `도보`, `차량`, `대중교통` 중 한 가지를 선택한다. 선택 수단만 추천 가능 여부와 순위의 기준이 된다.
- 후보 화면은 상단 지도와 하단 플로팅 시트로 구성한다. 지도에는 현재 위치·약속 장소·후보 마커와 이름을, 시트에는 스크롤 가능한 장소 목록과 상세 설명을 표시한다.
- 카테고리 필터는 구현됐다. 마커 클러스터링은 아직 구현하지 않았으며, 후보 수가 늘어난 뒤 별도 UX 작업으로 진행한다. 지도에 보이는 후보는 모두 강한 자동 추천이 아니라, 시간 조건을 통과한 선택 가능 후보다.
- 추천 가능한 모든 장소에는 정확한 카카오맵 상세 링크를 제공한다. 카카오 검색에서 확인되지 않은 장소는 추천에서 제외한다. 사용자는 메뉴·가격·사진·후기·운영시간을 카카오맵에서 확인한 뒤 TimeFit 장바구니로 돌아와 선택한다.
- 사용자가 첫 장소를 담으면 `현재 위치 -> 담은 장소들 -> 약속 장소` 기준으로 즉시 시간을 다시 계산한다. 기존 후보는 계속 보이되, 추가할 수 없는 장소는 `시간 초과` 상태와 부족 사유를 표시하고 장바구니 추가를 막는다.
- 코스 장소 수는 1~2곳으로 고정하지 않는다. 시간 조건을 통과하는 동안 3곳 이상도 담을 수 있다.
- 같은 `siteGroupId`의 포괄 장소와 내부 시설은 각각 후보로 보일 수 있으나, 사용자가 둘을 같은 장바구니에 담거나 엔진이 둘을 한 미니코스로 조합하지 않는다.
- 초기 방문 순서는 앱이 이동시간이 가장 짧은 순서로 자동 정렬한다. 사용자는 장바구니에서 1·2·3번 순서를 직접 바꿀 수 있고, 변경 즉시 시간 적합성을 다시 계산한다.
- 같은 조건에서 같은 장소가 재표시되는 것은 허용한다. 기본 점수 차이가 작은 후보만 약하게 순환할 수 있으며, 지도 탐색·필터·장바구니 상태로 선택지를 탐색하게 한다.

### 1.4 시간 예산 규칙

```text
buffer = 이동수단별 고정 안전 여유시간
budget = 남은시간 - buffer
```

| 이동수단 | 안전 여유시간 | 추천 예산 |
|---:|---:|---:|
| 도보 | 15분 | 남은시간 - 15분 |
| 대중교통 | 20분 | 남은시간 - 20분 |
| 차량 | 10분 | 남은시간 - 10분 |

이 예산 안에서 `현재 위치 -> 담은 장소들 -> 약속 장소`(약속이 없으면 출발지 복귀)의 이동시간과 체류시간을 계산한다. 최소 체류시간과 이동 대비 체류 규칙은 [2-1. 시간 안전·체류 정책](#2-1-시간-안전체류-정책)을 단일 기준으로 사용한다.

### 1.5 운영시간 확인과 카카오맵 상세 연결

- **현행 데이터**: TourAPI 원본 ID가 있는 장소는 `detailIntro2`에서 운영시간 문자열을 파싱해 게이트를 적용한다. 부산시 공식 데이터 단독 장소는 제공된 운영시간 문구를 안내하며 자동 영업 판정은 하지 않는다.
- **2단계 운영시간 검증(확정)**: 후보 목록에서는 선택한 이동수단의 직선거리 근사 이동시간에 `10분` 보수 여유를 더해 운영시간을 1차 판단한다. 장바구니에서 코스를 확정할 때는 선택한 구간만 TMAP(도보·차량) 또는 ODsay(대중교통) 정밀 경로로 다시 계산하고, 실제 도착부터 체류 종료까지 운영시간 안인지 재검증한다. 정밀 경로를 받지 못한 코스는 확정하지 않는다.
- **개별 시설 정책(확정)**: 카페·식당·백화점·쇼핑몰·전시관·체험시설·케이블카 등 핵심 활동이 시설 이용인 장소는 실제 운영시간이 확인될 때만 자동 추천한다.
- **권역형 장소 정책(정제 진행 중)**: 시장·거리·골목·문화마을은 모든 점포의 영업시간을 임의로 추정하지 않는다. 공식 관광·구청·상인회·대표 안내시설의 근거로 **추천 가능 시간대**를 별도 관리한다. 이는 전체 점포의 영업시간이 아니라, 사용자가 기대한 시장·쇼핑·관람 경험을 할 수 있는 보수적 시간대다.
- **TourAPI 재검증 현황(2026-08-13)**: 우선순위 권역형 후보 40건의 `detailIntro2` 원문을 재조회했다. `시간범위확인` 14건은 `src/data/area_availability_policy.json`에 공식 시간대 정책으로 등록해 통과 여부를 판단한다. `시간범위+조건부` 4건은 점포별 상이 문구를 함께 보여 별도 검토하고, `조건부안내` 또는 `시간범위미확인` 22건은 공식 시간대가 확정될 때까지 자동 추천에서 제외한다.
- **원본 ID 없는 권역형 장소(2026-08-13)**: 광안종합시장 등 16건은 TourAPI `searchKeyword2`로 재탐색했지만, 이름 완전 일치와 250m 이내 좌표를 동시에 만족한 후보가 없었다. 이 목록은 `data/processed/review/권역형장소_TourAPI키워드재탐색_검토.json`에서 유지하며, 유사명 결과를 체류시간·운영시간 근거로 상속하지 않는다.
- **전포공구길(2026-08-15)**: 실제 골목 전체를 대표하는 장소를 AIHub 개별 상점 `오브젝트 에디트`의 체류시간으로 매칭했던 사례다. `상업지구 / 거리·골목` 포괄 장소·카테고리 체류시간으로 재분류했으며, TourAPI의 `매장별 상이` 운영시간은 권역 추천 가능 시간대로 사용하지 않는다.
- **추천 가능 성격 프로필(2026-08-15)**: 오분류가 확인된 장소에는 `facility`(운영시간 필수), `area`(공식 권역 시간대 필수), `outdoor`(검토된 야외 접근형), `hold`(자동 추천 보류)를 명시한다. 카테고리만으로 운영시간을 우회하지 않도록 이 프로필을 우선 적용한다.
- **야외 상시형 정책(확정)**: 해변·공원·산책로 중 별도 검토로 상시 접근이 확인된 장소만 운영시간 없이 추천할 수 있다. 자연관광지라는 카테고리만으로 시설형 장소를 상시 허용하지 않는다. 아직 프로필이 없는 기존 자연관광지 전체는 후속 전수 정제 대상이다.
- **근거 미확인 처리(확정)**: 상권 의존형 권역과 시설형 장소는 근거가 없으면 장소를 삭제하지 않되 자동 추천 대상에서 보류한다. 카카오맵 링크는 메뉴·사진·후기 탐색용 보조 수단이며, 운영시간 확인 책임을 사용자에게 넘기는 근거로 쓰지 않는다.
- **구현 작업**: 카카오 검색에서 확인된 장소에는 Kakao Place ID와 `place_url`을 저장한다. `not_found`는 보관만 하고 추천 엔진에서 제외한다.

## 2-1. 시간 안전·체류 정책 (2026-08-08 확정)

### 안전 여유시간

약속 지연 위험이 수단마다 다르므로, 입력한 남은 시간에서 아래 시간을 먼저 확보한다. 이전의 `남은 시간 12%` 계산은 사용하지 않는다.

| 이동수단 | 안전 여유시간 | 이유 |
|---|---:|---|
| 도보 | 15분 | 신호·보행 속도 차이 대응 |
| 대중교통 | 20분 | 접근 도보·환승·배차 변동 대응 |
| 차량 | 10분 | 교통 상황은 있으나 경로 재탐색이 쉬움 |

### 최소 체류시간

- 기본값은 장소당 `30분`이다.
- 자연관광지와 거리·골목·광장·시장 성격의 상업지구만 접근 이동시간에 따라 예외를 둔다.
  - 접근 `10분 이하`: `15분`
  - 접근 `11~15분`: `20분`
  - 접근 `16분 이상`: `30분`
- 카페·식당·문화시설·레저/스포츠와 개별상점·아울렛·쇼핑복합공간은 시설형·유료 성격으로 본다.

### 이동 대비 체류

약속지까지 원래 가야 하는 시간 자체는 불이익으로 계산하지 않는다. 대신 `경유 장소를 넣어 추가된 이동시간`과 체류시간을 비교한다.

- 시설형·유료 성격: 배정 체류시간이 추가 이동시간보다 짧으면 추천 및 장바구니 추가에서 제외한다.
- 자연·거리·광장 등 가볍게 구경 가능한 장소: 시간 예산과 최소 체류시간을 충족하면 표시한다. 추가 이동시간이 체류시간보다 길면 **제외하지 않고 낮은 순위**로 둔다.
- 장바구니에서 장소를 추가할 때도 같은 정책을 즉시 재계산한다.

운영시간 또는 권역 추천 가능 시간대가 확인되지 않은 시설형·상권 의존형 장소는 자동 추천에서 보류한다. 카카오맵 상세 링크는 사용자가 메뉴·사진·후기를 추가 탐색하는 보조 기능이다.

## 3. 랭킹 v1 상세 (결정적·설명가능)

```
기본 점수 = 0.30 · min(1, 체류 가능 시간 / 60)
          + 0.20 · 체류시간 / (이동시간 + 체류시간)
          + 0.20 · 시간대 적합도
          + 0.15 · AIHub 매칭 신뢰도
          + 0.15 · 장소 간 밀집도
          + 전략·짧은 시간·지하철 보너스
          − 카테고리 폴백·운영시간 신뢰도·지도 검증·우회·대중교통 폴백 등 감점

그리디 선택 시: − 0.15 × 이미 뽑힌 동일 카테고리 수
점수 차이 0.035 이내 후보만 약하게 순환
```

`시간활용 = (이동시간 + 체류시간) / budget`은 현재 계산만 하며 최종 점수에는 반영하지 않는다. 시간 활용 가중치 조정은 별도 추천 로직 고도화 작업으로 남긴다.

## 6. 원칙 (불변)

- **ML 없음** — 가중치는 손으로 정하고, 근거를 문서에 남긴다 (데이터 해상도·설명가능성, `AI허브_체류시간데이터.md` 참조)
- **모든 코스는 why를 가진다** — 점수 내역으로 설명 못 하는 랭킹 변경 금지
- **TMAP 호출 상한 의식** — 추천 목록 단계는 도보·차량 TMAP 0건을 유지하고, 선택 코스의 상세 확인에서만 정밀 경로를 계산한다.
- **이 문서와 코드는 항상 일치** — 추천 후보·필터·조합·랭킹·시간 게이트를 수정하는 모든 작업은 같은 변경 단위에서 본 문서와 자동검증 수치를 함께 갱신한다.
- **지도 후보와 자동 추천을 구분** — 지도에 표시하는 시간 적합 후보를 모두 강한 추천으로 표현하지 않는다
