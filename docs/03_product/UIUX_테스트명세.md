# TimeFit UIUX 테스트 명세

> 목적: 사용자 검토 과정에서 발견한 UIUX 문제를 재발하지 않도록 요구사항 ID, 화면 상태, 자동화 조건으로 관리한다. 이 문서는 이후 Maestro 또는 Detox E2E 테스트의 시나리오 원본이다.

## 사용 규칙

- 새 UIUX 피드백은 기존 ID와 `동일`, `보완`, `충돌` 여부를 먼저 판단한다.
- 충돌이면 기존 요구사항을 임의로 덮어쓰지 않고 사용자 결정 뒤 상태를 `대체됨`으로 바꾼다.
- `자동화 전제`의 `testID`와 고정 위치·시각·API 응답 주입이 준비되기 전에는 수동 시나리오로 확인한다.
- 자동화가 추가되면 이 문서의 상태와 [테스트 현황](../테스트.md)을 함께 갱신한다.

## 자동화 순서

1. 고정 시각·위치·후보 데이터를 주입하는 테스트 모드와 핵심 `testID`를 만든다.
2. UXV-04, UXV-05, UXV-20, UXV-21, UXV-29, UXV-39를 먼저 E2E로 자동화한다. 위치 입력과 시간 설정, 1~3곳 대표 코스, 조건부 후보 확인은 새 핵심 코스 작성 흐름이다.
3. UXV-10, UXV-11, UXV-13은 WebView 지도 이벤트를 테스트용으로 노출한 뒤 자동화한다.
4. UXV-01, UXV-14, UXV-21, UXV-26은 iPhone 기종별 스크린샷 회귀 테스트를 추가한다.
