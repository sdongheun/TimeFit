## 0. 레이어 한눈에

```
[앱 RN/TS]  화면(입력·추천·상세·실행·피드백) + 지도표시 + GPS + 로컬 알림
     │ 번들: category_dwell / congestion_matrix / poi_dwell .json (정적 파라미터)
     ▼
[시간-적합 엔진 · 순수 TS]  ← 핵심, 결정적. Node(스파이크)·RN 공용
     │ 런타임 호출
     ├─ TourAPI (후보·운영시간)        REST
     ├─ TMAP (보행/자차/대중교통 소요)   REST
     └─ (선택) 서버 프록시 → Claude API (코스 설명·큐레이션)
```

| 항목 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | ⭐ **Expo (기본)** ✅ | 네이티브 설정 최소·EAS Build로 TestFlight 빠름. (Apple Maps라 dev client 불필요, Kakao 전환 시 dev client로) |
| 플랫폼 | ⭐ **iOS 우선** ✅ | 컴셉도 iOS 기반. 안드로이드는 후에 |
| 언어 | **TypeScript** | 엔진을 Node↔RN 공용으로 쓰려면 필수 |
| 내비게이션 | **@react-navigation/native-stack** ✅ | 라이프사이클 화면(입력·추천·상세·실행·피드백) 스택 |

| 위치(GPS) | **expo-location** | 현재위치 |
| **로컬 알림** | ⭐ **expo-notifications** | ④실행 단계 — 코스 수락 시 출발예정시각 기반 로컬 알림 예약(서버 불필요) |
| 지도 표시 | ⭐ **MVP: react-native-maps(Apple Maps)** ✅ → **추후 카카오맵** | MVP는 키 불필요·빠른 검증. **`<MapView>` 얇은 래퍼로 감싸** 카카오 교체 싸게. 경로는 TMAP REST |
| UI | RN 코어 + 최소 컴포넌트 | 디자인 과투자 금지 |

> 지도: *경로 계산은 TMAP API(REST)*, *지도는 표시용*. MVP는 Apple Maps로 빠르게 → 래퍼 뒤에서 카카오맵으로 전환.

## 2. 데이터 레이어 (번들 정적)

- `data/processed/*.json`을 **앱 에셋으로 번들**(빌드타임). 런타임 호출 없음.
- 출처표시 문구 앱 내 고지(AI-Hub/NIA·데이터웨이·한국관광공사).

## 3. 외부 API (런타임)

| API | 용도 | 인증 | 비용 |
|---|---|---|---|
| **TourAPI** KorService2 | 후보(`locationBasedList2`)·운영시간(`detailIntro2`) | serviceKey | 무료 |
| **TMAP** | 보행/자동차/대중교통 경로·소요시간 | appKey | 1000콜/일/모드 무료 |
| (선택)집중률 15128555 | 실시간 혼잡 override | serviceKey(활용신청) | post-MVP |

- **비용 가드:** 반경 축소 → haversine 휴리스틱 가지치기 → 상위 구간만 TMAP → 좌표쌍 캐시.

## 4. 시간-적합 엔진 (핵심·결정적)

- **순수 TypeScript 모듈**(플랫폼 무관). 입력(위치·시간·목적지·필터) → TourAPI 후보 → 체류(JSON)+이동(TMAP)+운영시간 게이트 → 제약만족 → 시간적응형 코스 후보.
- **Node에서 스파이크 → 같은 TS를 RN에 이식**(코드 재사용).
- 이동: TMAP + haversine 폴백. 혼잡: congestion_matrix 배수.

## 6. 키 보안 & 백엔드 (단계별)

**키 보안 (확정):**
- **MVP:** TourAPI·TMAP 키는 **앱 `.env`로** (무료·레이트리밋 공공키라 위험 낮음, 빠른 검증). ⚠️ 단 앱 `.env`는 빌드 시 바이너리에 박혀 추출 가능 → *보안이 아닌 편의*.
- **추후:** Claude 키(돈 위험)는 **반드시 서버 프록시**. 앱엔 안 들어감.

**백엔드 (단계별):**
```
MVP    : 추천(①②)은 백엔드 0 · 익명·stateless — 로그인 없이 동작
         수락 이후(③~⑤: 알림·완료 피드백) 데이터는 기기 로컬(AsyncStorage/expo-sqlite)
         → 로컬 알림도 서버 불필요(expo-notifications)
Phase2 : ⭐ Supabase 1개로 통합 → 로그인(Auth) + DB(Postgres+RLS) + Edge Function(=LLM 프록시)
         · 피드백 축적·개인화·기기간 동기화가 필요해질 때 도입
         · 직접 서버 구축/운영 불필요(BaaS 관리형), Auth+RLS가 '서버 역할' 대신
         · Claude 키는 Edge Function 서버측에 보관
```
> **로그인은 추천의 전제조건이 아니다** — ①②는 게스트로 작동. 로그인은 ③수락 이후(알림·완료 피드백·개인화)에만 유도. MVP는 로컬 저장으로 충분, 계정 동기화가 필요해지면 Supabase.

## 9. 단계별 도입 순서

```
Phase 0: 엔진 스파이크 (Node, LLM·RN 없이) — 결정적 엔진이 실데이터로 유효 코스 산출 검증   ✅
Phase 1: Expo RN 셋업 + 엔진 이식 + 입력·추천·상세 화면 + 지도 + 번들 JSON  → 동작하는 앱   ✅
Phase 1.5: 약속 입력(시각+장소) + destination 경유 경로 + 실행 화면 + 로컬 알림             ← 다음
Phase 2: 로그인(Supabase) + 완료 피드백 저장 + 서버 프록시 + Claude 설명/큐레이션
Phase 3: 강화(집중률 실시간·전국 union·피드백 기반 개인화)
```
