# TimeFit UIUX 와이어프레임 계획 v2

> 상태: **핵심 화면 구현됨 - 고정 fixture E2E 및 iOS 수동 확인 필요**
> 상위 결정: `REC-17` 대표 1~3곳 코스, `REC-18` 도착 여유, `REC-19` 차량 추천 제외, `REC-20` 체류 범위, `REC-24` 부산 발견성
> 관련 기준: [추천로직](추천로직.md), [UIUX 공통 규칙](UIUX_공통규칙.md), [UIUX 테스트 명세](UIUX_테스트명세.md), [테스트 현황](../테스트.md)

## 1. 이번 와이어프레임의 목적

TimeFit이 일반 근처 추천이나 관광지 목록 앱으로 보이지 않게 한다. 시간에 맞는 부산 발견 서비스라는 인상과 시간 신뢰를 함께 전달한다. 사용자가 처음부터 다음을 이해해야 한다.

> **다음 일정 전, 부산을 한 곳 더 만나볼까요?**

와이어프레임에서는 색상, 사진 품질, 지도 마커 장식보다 다음을 먼저 검증한다.

1. 한 화면에 핵심 행동이 하나인가.
2. 사용자가 추가 설명을 읽지 않아도 시간 제약과 다음 행동을 이해하는가.
3. 추천의 이유가 장소 이름보다 먼저 보이는가.
4. 후보가 없을 때도 TimeFit 추천과 외부 주변 탐색을 혼동하지 않는가.

## 2. 사용자 요구와 설계 판단

| 사용자 요구 | 반영 방식 | 설계 판단 |
|---|---|---|
| 현재 시간 기준으로만 사용 | 시작 시각은 자동으로 현재 시각을 사용하고 개발·E2E에서만 고정 시각을 주입한다 | 미래 코스 입력은 출시 UI에서 제외한다. 목적이 지금 비는 시간을 쓰는 것이기 때문이다. |
| 종료 시각·종료 장소·여유시간 입력 | 한 화면에서 `도착지/복귀`, `도착 시각`, `도착 전 여유`를 입력한다 | 종료 장소는 선택 입력이다. 비우면 현재 위치 복귀로 계산한다. |
| 자투리 시간은 최대 3시간 | 종료 시각은 현재 시각부터 최대 180분까지만 선택한다 | 이전 120분 상한은 철회했다. |
| 대표 코스는 1~3개 장소 | 엔진이 시간·공간·운영시간을 통과한 코스 1개를 먼저 제안한다 | 자유 장바구니 조립은 재도입하지 않는다. |
| 계산 중이라는 신뢰감 | 실제 후보 수집·시간 계산·운영 상태 판정에 맞춘 짧은 진행 상태를 표시한다 | 결과가 준비됐는데도 인위적으로 기다리게 하는 `생각 중` 연출은 금지한다. 캐시 적중 시 즉시 결과로 전환한다. |
| 논리적으로 설명하며 추천 | 장소 카드에 `이동 → 권장 체류 → 도착 전 여유`의 구조화된 근거를 표시한다 | 추천 숫자와 운영 상태는 결정론적 엔진이 만든다. 문장만 친숙하게 바꾼다. |
| 사용자화용 기록 UI | 코스 종료 뒤 1회 짧은 후기 시트를 보여 주고, 독립 `기록` 탭에서 완료 활동을 확인한다 | 코스 진행 중 추가 입력을 요구하지 않는다. 후기 건너뛰기를 허용한다. |
| E2E 핵심 흐름 | 로그인 → 시간 입력 → 장소 추천 → 카카오맵 길찾기 → 리뷰 | 로그인은 첫 진입 게이트이고, 이후 세션에서는 반복 요청하지 않는다. |

## 3. 철회한 UI 흐름

| 이전 방식 | 관찰된 문제 | 새 방식 | 상태 |
|---|---|---|---|
| 전체 지도에 다수 후보 마커를 먼저 보여 주고, 사용자가 이동수단·장소·장바구니 순서를 조립 | 장소 자체가 먼저 보여 일반 지도 추천처럼 보이고, 차량 전용 먼 후보와 구간별 수단 선택이 혼란을 만들었다 | 시간 예산과 도착 여유를 먼저 보여 준 뒤, 엔진이 조립한 1~3곳 대표 코스 1개를 카드로 제안한다. 지도는 세부 확인과 직접 탐색의 보조 수단이다 | 현행. 자유 장바구니·수단 선택은 철회 |
| 일반 카페를 후보 부족 시 추천 목록에 섞음 | 자투리 활동 추천의 근거와 일반 근처 카페 검색의 경계가 사라진다 | 검증 후보가 없으면 외부 카카오맵 탐색 행동을 별도로 제공한다 | 구현됨. 카카오맵 외부 탐색은 TimeFit 추천 카드와 분리 |
| 정적인 `생각 중...` 지연 | 실제 계산과 무관하면 신뢰를 만들기보다 연출로 보이고, 빠른 결과를 늦춘다 | 실제 단계 상태를 짧게 보여 주되 캐시 결과는 즉시 표시한다 | 구현됨. 위치·경로 기준선·후보 계산 완료 시에만 다음 단계로 이동 |
| 장소 카드의 긴 추천 문장, 세로 타임라인, `최소/권장/여유` 숫자 박스를 각각 표시 | 같은 시간 예산을 서로 다른 문장으로 반복해 사용자가 읽어야 했고, 일반 추천 카드처럼 보였다 | `출발 → 이동 → 활동 → 이동 → 도착 전 여유`를 하나의 시간 비율 막대로 표시한다. 파랑은 이동, 주황은 활동, 초록은 도착 전 여유로 고정한다 | 구현 중. 2026-08-22 결과·상세·확인 화면에 공통 `TimeJourney` 적용 |

## 4. 정보 구조와 화면 흐름

```text
로그인
  → 메인
  → 자투리 시간 설정
  → 계산 진행 상태
  → 추천 결과
      ├─ 코스 상세/선택
      │   → 1~3곳 코스 확인
      │   → 카카오맵 길찾기
      │   → 코스 진행
      │   → 완료 후기
      ├─ 지도에서 직접 보기
      └─ 후보 없음: 범위 확장 / 카카오맵 주변 탐색

하단 탭: 메인 / 내 코스 / 기록 / 내 정보
```

탭은 최상위 영역만 바꾼다. `시간 설정 → 결과 → 상세 → 1~3곳 코스 확인 → 진행`은 메인 탭 안의 한 세션이며, 뒤로가기는 직전 판단 단계로만 돌아간다.

### 4-1. 위치 입력과 배포 제약 반영 (2026-08-21)

| 이전 방식 | 문제/관찰 | 교체 방식 | 이유 | 상태 |
|---|---|---|---|---|
| 설정 행에서 현재 위치와 도착지가 바로 채워진 것처럼 보임 | 권한 거절, GPS 실패, 위치 정정의 사용자 흐름이 없었다 | 두 행은 각각 선택 화면으로 이동한다. 현재 위치는 `내 위치 사용` 또는 지도 직접 선택, 도착지는 `현재 위치로 복귀` 또는 지도 직접 선택이다 | 권한 거절 뒤에도 핵심 추천 흐름을 보장하고, 시스템 권한은 사용자가 `내 위치 사용`을 누른 시점에만 요청하기 위함 | 구현됨. 거절·GPS 실패 E2E는 미구현 |
| 도착 시각을 텍스트 토글로만 시연 | 분 단위 설정과 iOS 알람형 조작을 검토할 수 없었다 | 오전/오후·시·분을 독립 선택하는 알람형 시연 화면을 둔다 | 시간 입력 의미와 최대 180분 정책을 화면에서도 분명하게 하기 위함 | 구현됨. 경계값 E2E는 미구현 |
| 대표 후보 외의 탐색 흐름이 불명확 | 결과 반복과 지도 탐색이 같은 역할로 보일 위험이 있었다 | 대표 코스 1개, 새 추천, 지도에서 더 보기를 분리한다. 지도는 확인 후보의 추천/빠듯/불가와 조건부 후보의 운영시간 확인 필요 상태를 유지한다 | 대표 코스 약속을 지키면서 탐색 권한을 남기기 위함 | 구현 전환 필요 |

### 4-2. 배포 전 출시 게이트

1. 위치 권한은 첫 실행이나 로그인 직후가 아니라 `내 위치 사용` 직전에 목적을 설명하고 요청한다. 거절·GPS 실패 시 지도 직접 선택을 제공한다.
2. 앱 내부 `내 정보`와 App Store Connect에는 실제 수집 항목(이메일, 생년월일, 정밀 위치, 저장 코스, 후기, 제3자 SDK), 이용 목적, 보관·삭제 정책을 일치시킨 개인정보 처리방침 링크를 둔다.
3. 위치·경로·후기 원문은 기능상 필요한 최소 범위만 전송·저장한다. 개인화에 필요 없는 원본 위치 이력은 저장하지 않는다.
4. 위치정보법상 위치기반서비스사업 신고·약관 공개·개인위치정보 처리 의무는 출시 주체와 실제 데이터 흐름이 확정된 뒤 전문가 또는 관할 행정 창구에 확인한다. 이 문서는 법률 자문이 아니다.
5. 카카오·TMAP·TourAPI 등 제3자 데이터의 표시, 캐싱, 사진·지도 사용, 외부 길안내 전환은 출시 시점 약관을 다시 확인한다.

## 5. 화면별 저해상도 와이어프레임

### W-01. 로그인

**목적:** 추천·저장·후기를 하나의 사용자 데이터로 연결한다.

```text
[TimeFit]
다음 일정 전, 부산을 한 곳 더 만나볼까요?

[ 이메일 ]
[ 비밀번호 ]
[ 로그인 ]

회원가입
```

- 성공 후 메인으로 이동한다.
- 인증 실패는 입력 영역 아래에 짧게 표시한다.
- 로그인 이유를 긴 설명문으로 늘어놓지 않는다.

### W-02. 메인

**목적:** 첫 행동을 하나로 제한한다.

```text
안녕하세요, {닉네임 또는 사용자}

다음 일정 전, 부산을 한 곳 더 만나볼까요?
[ 자투리 시간 설정하기 ]

(진행 중 코스가 있을 때만)
[ 진행 중인 코스 계속하기 ]

────────────────────────
 메인          내 코스          기록          내 정보
```

- 추천 장소 캐러셀, 카테고리 목록, 지도는 메인에 두지 않는다.
- 진행 중 코스가 없으면 두 번째 CTA는 보이지 않는다.

### W-03. 자투리 시간 설정

**목적:** 세 번의 입력으로 시간 제약을 확정한다.

```text
<  자투리 시간 설정

현재 위치                 [ 현재 위치 ]
도착지/복귀               [ 현재 위치로 돌아오기 > ]
도착 시각                 [ 오늘 14:00 > ]

약속 전 남길 시간                 10분
──────────────●──────────────
빠듯하게                         여유롭게

[ 이 시간에 할 일 찾기 ]
```

- 도착지 기본값은 `현재 위치로 돌아오기`다. 사용자가 장소를 고르면 약속·집·역 등으로 바뀐다.
- 도착 시각은 `현재 시각 + 1분`부터 `현재 시각 + 180분`까지만 선택한다.
- 여유 슬라이더는 0분을 제공하지 않는다. 최소값·간격은 추천 엔진 구현 시 확정하되 기본값은 10분이다.
- 개발/테스트 시각·좌표 입력은 이 화면에 노출하지 않고 내 정보의 개발 전용 메뉴에 격리한다.

### W-04. 실제 계산 진행 상태

**목적:** 사용자가 기다리는 이유를 실제 계산 단계로 전달한다.

```text
14:00까지 계산 중

● 현재 위치와 도착지 확인
○ 이동 가능한 범위 계산
○ 짧게 들를 장소 찾기
○ 운영 상태 확인
```

- 단계는 실제 비동기 작업과 연결한다. 실패하면 해당 단계에서 재시도·직접 탐색 상태로 전환한다.
- 캐시로 결과가 즉시 준비되면 이 화면을 강제로 유지하지 않는다.
- `AI가 생각 중이에요`처럼 사실과 다른 표현은 사용하지 않는다.

### W-05. 추천 결과

**목적:** 장소 목록보다 시간 판단과 행동 제안을 먼저 보여 준다.

```text
<  14:00까지 85분
   도착 전 10분 남기기

오늘 동선에서 만나는 부산

[ 12:35 ━ 파랑 이동 ━ 주황 활동 ━ 파랑 이동 ━ 초록 여유 ━ 14:00 ]

┌────────────────────────┐
│ 전포의 거리 산책 (1곳 코스)│
│ 전포 · 쇼핑·거리          │
│ 도보·대중교통 18분      │
│ 권장 25분 둘러보기      │
│ 13:48 도착 예상 · 12분 여유 │
│                     [ > ]│
└────────────────────────┘

짧게 가능 2곳                 지도에서 직접 보기
```

- 첫 화면은 상위 `추천` **코스 1개(1~3곳)**만 보여 준다. 새 추천은 다음 유효 코스로 바꾸며, 지도에서 더 보기는 보조 탐색이다.
- 결과 카피는 지역·활동처럼 검증 가능한 사실만 사용한다. 앱 안의 완료 기록이 없는 한 `처음 가보는`, `숨은`, `인기` 같은 표현을 붙이지 않는다.
- 시간 막대는 읽는 순서가 아닌 길이 비율로 이동·활동·여유의 관계를 보여 준다. 카드의 출발·도착 시각은 이 막대의 계산값을 재사용한다.
- `짧게 가능`과 `불가능`은 지도 보조 탐색에서만 구분해 보여 준다.
- `운영시간 확인 필요`는 대표 코스 카드와 섞지 않는다. 더보기에서만 확인 행동을 제공하며, 확인 뒤에도 조건부 수동 포함 상태를 유지한다.
- 지도 직접 보기는 사용자가 더 탐색하고 싶을 때만 연다.

### W-06. 코스 상세와 1~3곳 코스 확인

**목적:** 1~3곳 대표 코스를 선택하기 전에 시간 근거를 한눈에 확인한다.

아래는 1곳 코스 예시다. 2~3곳 코스에서는 같은 시간 막대 안에 장소별 활동과 그 사이 이동 구간을 순서대로 추가하고, 코스 확인에서는 모든 장소 순서를 펼쳐 보인다.

```text
<  전포의 거리 산책
전포 · 쇼핑·거리
[ 코스 첫 장소 사진 또는 활동 유형 이미지 ]

[ 12:35 ━ 파랑 이동 ━ 주황 활동 ━ 파랑 이동 ━ 초록 여유 ━ 14:00 ]
          18분          25분           22분          12분

13:18에 출발하면 13:40 도착

[ 카카오맵에서 장소 확인 ]
[ 이 코스 확인하기 ]
```

- 대표 결과·새 추천·상세의 도보·대중교통 구간은 실제 경로값만 표시한다. 근사값은 내부 후보 선별에만 쓰며, 실제 경로 실패 시 대표 추천으로 승격하지 않는다.
- 상세와 코스 확인은 결과와 같은 실제 경로 시간 여정 모델을 쓴다. 화면마다 체류·여유를 별도로 계산하지 않는다.
- 운영시간 미확인 후보는 CTA 위에 `운영시간 확인 필요`를 표시하고 카카오맵 확인을 우선 행동으로 둔다. 이 상태는 TimeFit이 시간 내 이용을 보장하지 않는다.
- `이 코스 확인하기` 뒤에는 다중 장바구니가 아니라 엔진이 조립한 1~3곳 코스 확인으로 간다.

### W-07. 코스 진행과 후기

**목적:** 외부 길찾기 뒤 앱 복귀 없이도 다음 행동과 기록을 최소 조작으로 처리한다.

```text
지금 이동할 곳
전포 산책길
도보 7분 → 지하철 11분

[ 카카오맵으로 길찾기 ]
[ 코스 변경 ]

완료 후
이번 자투리 시간은 어땠나요?
[ 1 ] [ 2 ] [ 3 ] [ 4 ] [ 5 ]
실제 머문 시간  짧았어요 / 적당했어요 / 길었어요
[ 건너뛰기 ]                         [ 기록하기 ]
```

- 후기에는 만족도와 체류 체감만 기본으로 받는다. 자유 의견은 선택 입력이다.
- 이 기록은 장소 매력·개인 체류시간 보정의 미래 입력이며, 초기 추천의 근거를 대체하지 않는다.
- 카카오맵 복귀 뒤 현재 시각을 다시 읽어 코스 상태를 갱신한다.

### W-08. 후보 없음

**목적:** 빈 결과를 실패처럼 끝내지 않되, 근거 없는 카페 추천도 하지 않는다.

```text
이 조건에서 확신 있게 추천할 장소를 찾지 못했어요.

[ 탐색 범위 넓히기 ]
[ 도착지 주변 보기 ]
[ 카카오맵에서 주변 카페 찾기 ]
```

- 세 행동은 TimeFit 추천 결과와 시각적으로 분리한다.
- 날씨 API가 연결되기 전에는 날씨를 원인으로 말하지 않는다.

## 6. AI API 사용 원칙

### 결론

AI API는 **추천 가능 여부, 이동시간, 운영시간, 체류시간을 결정하면 안 된다.** 이 값들은 결정론적 추천 엔진과 공공 데이터·경로 API가 책임진다. AI가 숫자를 판단하면 설명은 자연스러워져도 시간 신뢰도가 낮아진다.

### 사용할 수 있는 보조 역할

| 위치 | 입력 | 출력 | 안전장치 |
|---|---|---|---|
| 추천 결과 설명 | 구조화된 사실: 활동 유형, 이동·체류·도착 여유, 운영 상태 | `지금 들르면 약속 전 12분을 남길 수 있어요` 같은 한두 문장 | 숫자·장소명은 모델이 새로 만들지 않고 입력 값만 사용한다. 실패 시 템플릿 문구로 폴백한다. |
| 후보 없음 안내 | 빈 결과 원인 코드: 시간 부족, 운영시간 미확인, 경로 실패 | 비난하지 않는 짧은 안내 문장 | 날씨·인기·영업 여부처럼 입력에 없는 이유를 추측하지 않는다. |
| 후기 자유 의견 요약 | 사용자가 동의한 후기 텍스트 | 개인화에 쓰기 전 운영·대기·분위기 같은 태그 초안 | 원문은 보존하고, 자동 태그는 검토 가능한 보조 데이터로만 쓴다. |

### 구현 조건

- API 키는 Expo 클라이언트에 넣지 않는다. Supabase Edge Function 또는 별도 서버에서 호출한다.
- 정확한 GPS 좌표, 이메일, 코스 전체 기록을 프롬프트에 보내지 않는다. 문장 생성에는 익명화한 시간·활동 유형·상태만 보낸다.
- AI 호출 실패·지연이 추천 결과와 길찾기를 막으면 안 된다. 기본 템플릿을 항상 제공한다.
- 첫 와이어프레임과 추천 엔진 전환에서는 AI API를 구현하지 않는다. UI가 AI 문장 없이도 이해되는지 먼저 검증한 뒤, 문장 보조로만 추가한다.

## 7. 와이어프레임 제작 순서와 승인 기준

1. W-02~W-06만 흑백·저해상도로 먼저 만든다.
2. 한 화면당 하나의 CTA가 명확한지, 뒤로가기와 빈 결과 흐름이 끊기지 않는지 검토한다.
3. 고정 fixture로 `왕복`, `도착지 있음`, `짧게 가능`, `운영시간 확인 필요`, `후보 없음` 다섯 상태를 화면에 주입한다.
4. 화면 흐름을 확정한 뒤 W-07 후기·내 코스·내 정보까지 확장한다.
5. 승인된 W-02~W-06은 React Native 화면으로 구현했다. 다음 단계는 고정 fixture E2E와 iOS 수동 확인이다.

승인 기준:

- 처음 보는 사람이 10초 안에 `도착 시각`, `도착 전 여유`, `다음 행동`을 찾을 수 있다.
- 장소 카드만 보아도 왜 추천됐는지 이동·체류·도착 여유로 이해할 수 있다.
- 후보가 없을 때 TimeFit이 카페를 보장한 것으로 오해하지 않는다.
- 로그인 → 시간 입력 → 추천 → 카카오맵 길찾기 → 후기의 E2E 흐름이 화면 이동 없이 막히지 않는다.
