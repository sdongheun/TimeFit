## UX-COLOR-01 — 텍스트 가독성과 파란 강조 분리 (2026-09-08)

상태: 사용자 확정·구현/검증 전. UX-31 다크·파란 테마의 보완이며 앱 전체 공통 기준이다.

- 검정/짙은 배경 위 활성 버튼·텍스트 행동·탭 라벨은 흰색 계열로 표시한다. 파란 배경의 주요 버튼도 텍스트는 흰색 계열이다. 파란색 글자로만 행동/선택 상태를 강조하지 않는다.
- 파란색은 아이콘, 선택 배경, 테두리, 인디케이터 등 비텍스트 강조에 사용한다. 모든 비텍스트 요소를 파란색으로 바꾸라는 뜻은 아니다.
- 본문 주요 정보는 흰색 계열, 보조 정보는 읽을 수 있는 회색 계열로 위계를 유지한다. 비활성·오류·경고·성공의 의미 구분은 보존하며, 색상만으로 상태를 전달하지 않는다. 링크도 명칭·배치·필요시 밑줄로 행동임을 알린다.
- 주변 둘러보기부터 적용하고 다른 화면도 같은 기준으로 점검한다. 공용 색상 상수의 일괄 치환으로 지도 경로·상태색·비활성 상태까지 바꾸지 않는다. 화면별 적용/미적용·검증 상태를 인수인계에 남긴다.

이력: 짙은 버튼 위 파란 텍스트 사용 → 주변 화면에서 글자가 선명하지 않다는 사용자 관찰 → 텍스트는 흰색 계열, 파란색은 비텍스트 강조로 분리 → 다크 정체성을 유지하면서 읽기 쉬운 행동 표시 → 현행 규칙·구현 전. 과거 파란 행동 텍스트 방식은 이 범위에서 철회하며 복원하지 않는다. 추천·거리 계산·저장·개인화 정책은 변경하지 않는다.

## DEC-LIVE-ACTION-HANDOFF-01 — 잠금화면 동작 확장 (2026-09-06)

상태: **사용자 확정·구현/검증 전**, COURSE-13·UX-19 보완. 이 절과 충돌하는 과거 출발 확인만 기록하는 흐름은 철회이며 나머지 로컬 우선 계약은 유지한다.

- 도착 확인은 잠금화면에서 한 번만 한다. native 저장과 Activity의 즉시 머무는 중 전환, 앱 복귀 시 다음 단계 복구를 연결한다. 예정 시각 전 확인도 허용한다.
- 이제 출발해요는 명시 출발과 다음 길찾기 요청을 함께 만든다. 필요한 잠금 해제 → TimeFit 활성화 → 기존 adapter로 다음 구간 카카오맵 자동 실행이며 앱에서 재탭을 요구하지 않는다. 확정 snapshot 순서의 다음 방문 장소 또는 최종 목적지를 사용한다.
- 이 명시 출발의 최초 확인 시각과 handoff 성공은 별개다. 외부 실행 실패/재시도는 departedAt을 바꾸지 않으며 성공 전 routeOpened로 표시하지 않는다. 앱의 일반 길찾기만 누른 경우는 기존대로 handoff 성공 때 출발로 기록한다.
- 잠금 해제 취소/활성화 실패/외부 전환 실패 때 성공을 합성하지 않는다. 요청 중복 소비·stale run/stop/revision·완료 코스 재실행을 차단한다. 외부 앱 실행과 로컬 저장은 원자적이지 않으므로 중단으로 성공 여부가 불명확하면 자동 반복 대신 앱에서 명시 재시도를 제공한다.
- 로컬 단계의 서버 표본/업로드 큐/개인화 적용0, GPS/원격 push 미사용, exact cleanup을 유지한다. 알림 발화 정책 변경은 이번 범위가 아니다.

이력: 출발 기록 후 앱 길찾기 재탭 → 사용자 중복 조작 및 잠금화면 도착 무반응 관찰 → 도착 동기화 복구와 명시 출발/단일 길찾기 요청 연결 → 잠금 해제 이후 추가 조작 감소. 테스트는 cold/warm start, 잠금 해제 취소, 중복 이벤트, 외부 실패/불명확 결과, 실제 1/2곳 순서와 cleanup을 포함한다. 상세 실행 기준: docs/work/uiux/live-activity-dwell-progress.md의 “잠금화면 도착 복구·출발 자동 길찾기” 명령.


이 문서는 화면을 추가하거나 수정할 때 반드시 지켜야 하는 UIUX 규칙이다.

## 0. 기본 원칙

- UI는 간단하고 깔끔하게 유지한다. 한 화면에는 사용자가 바로 수행할 핵심 행동 하나만 우선순위로 둔다.
- 처음 사용하는 사람도 설명을 읽지 않고 다음 행동을 알 수 있게, 행동의 결과를 버튼 위치·아이콘·상태 변화로 보여 준다.
- 기능 설명, 반복 안내, 내부 계산 근거처럼 행동에 필요하지 않은 텍스트는 화면에 상시 노출하지 않는다. 시간·장소·이동수단·남은 시간처럼 결정에 필요한 정보만 남긴다.
- 화면 안에서 선택을 끝낼 수 있으면 별도 상세 화면을 추가하지 않는다. 새 화면은 입력, 비교, 확정, 진행처럼 목적이 명확히 달라질 때만 사용한다.

### 0-1. 시간 적합형 부산 발견 정체성 (2026-08-24, 현행·구현 전)

| 이전 방식 | 문제/관찰 | 교체 방식 | 이유 | 상태 |
|---|---|---|---|---|
| 남는 시간에 할 일을 찾는 범용 유틸리티로만 표현 | 시간 계산의 신뢰는 전달되지만 부산 관광·지역 발견 서비스라는 인상이 약하고, 일반 근처 추천과 구별하기 어려웠다 | 첫 메인 문구를 **`다음 일정 전, 부산을 한 곳 더 만나볼까요?`**로 통일하고, 결과에는 지역과 활동을 사실 기반으로 함께 표시한다 | 관광객과 부산 생활권 사용자 모두에게 계획 밖의 장소를 발견하는 이유를 짧고 명확하게 전달하기 위함 | 현행 규칙, 구현 전 |
| 지역 활성·소비 효과를 전면 약속하거나 `처음 가보는`·`숨은`·`인기` 같은 편집 문구를 사용 | 소비·방문 이력·인기도를 현재 데이터만으로 보장할 수 없고, 시간 적합성보다 마케팅 문구가 앞설 위험이 있다 | 소비와 지역 활성은 사용 결과로 가능한 부수 효과로만 둔다. 완료 기록이 있는 경우에만 앱 안의 완료 이력으로 지역·활동의 미경험을 표현하며, 근거 없는 새로움·인기도 주장은 쓰지 않는다 | 사용자에게 보장할 수 있는 가치는 `시간 안에 안전하게 발견할 기회`이기 때문 | 현행 규칙, 구현 전 |

- TimeFit은 **다음 일정 전 남는 시간에, 실제 경로·운영시간 조건 안에서 부산의 계획 밖 장소와 활동을 발견하게 하는 서비스**다. 관광객과 지역 사용자 모두 같은 흐름을 쓴다.
- 데이터의 `representative_core / representative_standard / conditional_more / hold` 분류는 추천 신뢰를 위한 내부 계약이다. 화면은 사용자에게 등급 자체를 노출하지 않고, 운영시간 상태·실제 이동·활동 근거처럼 행동에 필요한 사실만 표시한다.
- 홈은 시간 입력 CTA 하나를 중심으로 유지하되, 결과 카드에는 `지역명 + 활동 유형`처럼 사실 확인 가능한 맥락을 한 줄 추가한다. 추천 캐러셀·관광지 피드·과도한 배지는 홈에 추가하지 않는다.
- 앱이 보유한 완료 기록만으로 `아직 완료하지 않은 지역/활동`을 보조 순위에 활용할 수 있다. GPS 방문 이력, 외부 소비 이력, 일반적 첫 방문 여부를 추정하거나 표시하지 않는다.
- 시간·운영시간·실제 경로의 하드 조건은 발견성보다 항상 우선한다. 발견성은 동등하게 가능한 후보 사이의 보조 순위일 뿐이다.

### 0-2. 출시 핵심 화면의 시각 밀도 (2026-09-04, 현행·구현 전)

| 이전 방식 | 문제/관찰 | 교체 방식 | 이유 | 상태 |
| --- | --- | --- | --- | --- |
| 큰 사진·넓은 카드, 본문과 같은 좌우 여백 안의 코스 지도, 테두리 있는 빈 header placeholder | 한 화면에서 대안을 비교하기 어렵고 코스 전체 범위를 작게 보며, 행동 없는 네모가 버튼처럼 보인다 | 카드 필수 정보는 유지하며 높이를 줄이고, 코스 지도만 safe area 아래 좌우 full-bleed로 확장하며, 우측 정렬은 비시각 spacer로 처리한다 | 추천 비교와 전체 이동 경로 파악을 빠르게 하면서 잘못된 행동 affordance를 제거하기 위함 | U-RELEASE-VISUAL-01 구현 전 |
| 같은 tick의 정적 loading 단계와 장식 진행 연출 후보 | 실제 계산과 관계없는 단계가 신뢰를 낮추거나 결과를 불필요하게 늦출 수 있다 | 입력 확인·경로 연결·후보/시간 검증·결과 준비의 실제 runtime event만 표시하고 현재 단계만 pulse한다 | 기다림을 꾸미는 대신 실제 상태를 설명하기 위함 | U-RELEASE-VISUAL-01 구현 전 |

- 테마는 다크 배경과 파란 주요 행동을 유지하고, 초록은 완료/여유, 주황은 활동 의미로 제한한다.
- Home의 주요 CTA와 진행/빈 상태는 최소 24px의 그룹 간격으로 분리한다.
- 대표·대안 카드의 사진, 장소명, 활동, 코스 시간과 전체 카드 tap/접근성은 밀도 조정 뒤에도 유지한다.
- 코스 확인 지도는 헤더 safe area를 침범하지 않으며 route geometry·marker·오류 상태를 축소하거나 근사하지 않는다.
- loading 완료 표시를 위해 100ms 이상의 고정 지연이나 실제 작업과 무관한 자동 단계 timer를 추가하지 않는다.

## 1. 안전 영역

- iPhone의 상태 표시 영역(시간, Dynamic Island 또는 노치, 네트워크, 배터리)과 앱의 텍스트·버튼·지도 컨트롤은 절대 겹치면 안 된다.
- 자체 헤더, 지도 위 컨트롤, 전체 페이지의 첫 콘텐츠는 `useSafeAreaInsets().top`을 기준으로 배치한다.
- 네이티브 스택 헤더를 사용하는 화면은 iOS가 제공하는 안전 영역을 사용한다. 커스텀 헤더로 바꾸면 직접 safe-area inset을 적용한다.
- 하단 플로팅 바와 고정 CTA는 홈 인디케이터를 피하도록 `useSafeAreaInsets().bottom`을 반영한다.
- 고정 `paddingTop` 또는 `bottom` 값만으로 상태 표시 영역을 피하지 않는다.

## 2. 화면 전환과 뒤로가기

| 이전 방식 | 문제/관찰 | 교체 방식 | 이유 | 상태 |
|---|---|---|---|---|
| 모든 Stack 화면에 `250ms fade`를 일괄 적용 | 앞으로 들어가는 이동과 뒤로 돌아가는 이동이 같은 모습이라 화면 계층을 알기 어렵고, iOS의 되돌리기 제스처와도 시각 방향이 맞지 않았다 | 계층형 화면은 iOS native stack의 기본 push/pop 전환을 사용하고, 임시 작업은 아래에서 올라오는 modal/sheet, 같은 화면의 상태 변화는 해당 영역만 짧게 전환한다 | 사용자가 새 단계 진입·임시 작업·현재 화면 갱신을 애니메이션 방향만으로 구분하게 하기 위함 | 현행 결정·구현 전 |

- 메인 흐름의 새 목적 화면(`시간 설정 → 추천 결과 → 장소 상세/코스`)은 iOS native stack 기본 전환을 사용한다. 앞으로 갈 때는 오른쪽에서 들어오고 뒤로갈 때는 반대 방향으로 돌아가며, 지원 화면에서는 interactive edge-swipe back을 유지한다. 코스의 `review→active`는 같은 화면 상태 전환이므로 새 push를 만들지 않는다. 전역 `fade`와 임의 `animationDuration`으로 네이티브 타이밍을 덮어쓰지 않는다.
- 위치 검색, 지도 선택, CAPTCHA처럼 현재 흐름 위에서 잠시 완료하고 닫는 작업은 아래에서 올라오는 modal/sheet로 표현하고 닫을 때 아래로 되돌린다. 배경은 dim 처리하되 원래 화면의 맥락을 지우지 않는다.
- 추천 결과의 A 선택, B 후보 로딩·선택, 더보기처럼 화면 목적과 navigation stack이 바뀌지 않는 상태 변화는 전체 화면을 전환하지 않는다. 기존 영역을 유지하고 바뀌는 영역만 `opacity + 8~12px` 이동 또는 skeleton 교체로 `160~220ms` 안에 전환한다. 네트워크 대기 시간을 맞추기 위한 인위적 지연은 넣지 않는다.
- 최상위 탭 전환은 좌우 push로 표현하지 않는다. 스택을 새로 쌓지 않고 즉시 전환하거나 `150ms` 이하의 약한 cross-fade만 허용한다.
- 같은 사용자 행동에 화면 push와 본문 slide/fade를 동시에 중첩하지 않는다. 한 번의 행동에는 계층을 설명하는 주 전환 하나만 사용한다.
- iOS의 `Reduce Motion`이 활성화되면 큰 이동·scale을 제거하고 즉시 상태 변경 또는 짧은 opacity 변화만 사용한다. 전환 중에도 뒤로가기·취소·접근성 focus가 사라지지 않아야 한다.
- 사용자가 진입한 화면에는 이전 단계로 돌아가거나 취소할 수 있는 명확한 경로가 있어야 한다.
- 뒤로가기는 텍스트가 아닌 왼쪽 화살표 아이콘 버튼으로 통일하고 접근성 레이블을 제공한다. 터치 영역은 최소 `42px`로 유지한다.
- 지도 위·콘텐츠 위 커스텀 헤더의 뒤로가기는 `42px`, 모서리 반경 `12px`, `C.panel2` 배경과 `C.line` 테두리를 사용한다. 네이티브 스택 헤더에서는 화살표만 표시하고 외곽 배경·테두리·타원을 만들지 않는다. `Home`, `상세` 같은 프레임워크 기본 뒤로가기 레이블은 노출하지 않는다.
- **이전 진행 이탈 방식(철회):** 코스 진행 화면의 뒤로가기를 `내 코스` 최상위 탭으로 보내고 미래 코스를 저장하는 방식은 현재 시각 기준 추천·Home 진행 카드 방식과 맞지 않아 사용하지 않는다.
- **현행 진행 이탈 방식:** active 코스 화면을 닫으면 메인으로 돌아가며 활성 코스는 취소되지 않는다. Home의 `진행 중인 코스` 카드로 같은 `courseRunId`·마지막 확정 단계에 재진입한다. 명시 취소·완료만 활성 상태를 제거한다.
- 하단 탭은 현재 메인, 내 코스, 기록, 내정보를 전환한다. `내 코스 → 주변 둘러보기` 전환은 사용자 방향만 합의됐고 추천·운영시간·빈 상태 계약이 아직 미확정이므로 별도 작업 전까지 현 탭 구현을 임의 변경하지 않는다. 기록은 독립 탭이며 완료 활동의 누적 결과만 보여 준다. 탭 전환 때문에 이전 화면 스택이 계속 쌓이면 안 된다.
- 메인에서 시작한 입력 흐름은 `자투리 시간 설정 → 코스 만들기 → 코스 확인` 순서로 유지한다. `코스 만들기`의 뒤로가기는 메인이 아니라 입력값을 유지한 `자투리 시간 설정`으로 돌아간다.
- 코스 확인의 뒤로가기는 같은 추천 세션의 `코스 만들기`로 돌아간다. 사용자가 입력을 버리지 않고 대표 코스를 다시 요청할 수 있어야 한다.
- **이전 저장 중심 방식(철회·DB-1 구현 전)**: 코스 확정 뒤 저장 후 바로 코스 진행 화면으로 연결하고, 즉시 진행하지 않는 미래 시간 코스는 `내 코스`에 저장한다. 현재 V1에는 검증 코스 저장·복원 기능이 없어서 이 규칙을 적용하면 저장된 것처럼 보이거나 구현되지 않은 내 코스로 이동하는 문제가 있었다.
- **V1 진행 방식(현행·자동/실기기 검증 완료)**: 이전에는 `코스 확인 → 코스 시작하기 → V1 진행`을 화면 로컬 state로만 연결해 메인으로 이동하면 진행 진입점과 단계가 사라졌다. `U-PROGRESS-RESUME-01`에서 로그인 여부와 무관하게 같은 앱 프로세스의 AppFlow에 V1 활성 코스 한 건과 마지막 확정 단계를 보존하고, Home의 `진행 중인 코스`에서 같은 snapshot으로 이어가도록 교체했다. 카카오맵 전환·background/foreground·앱 안 navigation 이탈은 취소가 아니며 완료·명시 취소만 활성 상태를 제거한다. 추천/API/DB 재호출은 없다. 자동 fixture와 `QA-PROGRESS-RESUME-01` 비로그인 실기기를 통과했다. 이 runtime 이어가기는 영속 저장을 뜻하지 않으며, 강제 종료·OS eviction·재부팅 뒤 복구와 안정적인 `courseRunId`는 `U-LIVE-ACTIVITY-01`의 App Group 계약이 구현되기 전까지 제공하거나 암시하지 않는다. 다른 활성 V1이 있는 상태의 새 코스 시작은 현재 silent replace이므로, 사용자가 기존 코스를 종료할지 선택하는 확인 UX를 후속으로 추가한다.

## 3. 주요 버튼

- 화면을 진행시키는 주요 CTA는 다음 규격을 사용한다: 높이 `52px`, 모서리 반경 `12px`, `C.accent` 배경, `C.onAccent` 텍스트, `16px` 굵은 글자.
- 저장, 삭제, 필터, 순서 변경, 뒤로가기처럼 보조 행동은 주요 CTA와 구분되는 보조 버튼 형태를 사용한다.
- 아이콘만 있는 버튼은 접근성 레이블을 제공한다.
- 모든 실제 버튼·탭 가능한 카드·칩은 손가락이 닿은 즉시 눌린 상태를 보여 주고, 떼거나 취소하면 원상태로 복귀한다. 기본 눌림은 layout을 바꾸지 않는 `scale 0.97~0.98 + opacity 0.90~0.94`, press-in `80ms` 이하, release `140~200ms`의 짧은 easing/spring 범위로 통일한다. 작은 아이콘 버튼은 동일 원칙에서 `scale 0.94~0.96`까지 허용한다.
- 눌림 애니메이션은 `onPress` 실행 성공을 뜻하지 않는다. 로딩·중복 요청 방지 lock·disabled 상태는 별도이며, 같은 탭이 API·navigation을 두 번 실행하지 않게 기존 동기 lock을 유지한다.
- 이번 출시에서 일반 버튼·탭 가능한 카드·칩·뒤로가기·더보기·tray 삭제에는 햅틱을 넣지 않는다. 이 요소들은 위 scale/opacity 눌림 애니메이션만으로 반응을 전달한다. 햅틱은 아래 시간 wheel처럼 연속 값을 한 칸씩 넘기며 촉각 구분이 필요한 제어에만 명시적으로 허용하고, 공용 animated pressable이 자체적으로 햅틱을 발생시키면 안 된다.
- disabled 버튼은 눌림 애니메이션을 실행하지 않는다. 화면을 떠나는 중이거나 비동기 요청이 진행 중인 버튼도 시각적으로 disabled/busy 상태를 제공한다.
- 버튼마다 임의 구현을 복제하지 않고 UIUX 소유의 공용 animated pressable 경계를 사용한다. 단, 지도 WebView 내부처럼 네이티브/외부 제어가 소유한 버튼에는 앱 애니메이션을 겹치지 않는다.
- `Reduce Motion`에서는 scale을 제거하고 opacity 또는 색 변화만 남긴다. 애니메이션 때문에 최소 터치 영역, VoiceOver label/state, focus 순서가 달라지면 안 된다.

## 3-1. 위치·도착 시각 입력과 배포 경계

| 이전 방식 | 문제/관찰 | 교체 방식 | 이유 | 상태 |
|---|---|---|---|---|
| 시간 설정 화면에서 현재 위치·도착지가 이미 채워진 행처럼 보임 | 위치 권한 거절, GPS 실패, 잘못 잡힌 위치를 고치는 흐름이 없었다 | `현재 위치`, `도착지/복귀` 행은 전용 선택 화면으로 이동한다. 현재 위치는 `내 위치 사용`과 지도 직접 선택, 도착지는 `현재 위치 복귀`와 지도 직접 선택을 제공한다 | 권한을 강제하지 않고도 핵심 추천 흐름을 유지하기 위함 | 현행 규칙, 구현 전 |
| 도착 시각을 단순 텍스트 토글로 표현 | 분 단위 입력과 알람 앱에 가까운 시간 선택 요구를 검토할 수 없었다 | 오전/오후·시·분을 독립 선택하는 iOS 시계형 wheel picker를 사용한다 | 시간 제약을 빠르고 명확하게 설정하기 위함 | 현행 규칙·검증 완료 |
| custom wheel이 drag 종료와 동시에 외부 index를 확정 | 빠른 스와이프의 momentum 중 prop 갱신·`scrollTo`가 개입해 여러 칸 이동을 끊을 수 있고, 항목 경계를 지나도 촉각 피드백이 없었다 | 스크롤 중 내부 선택 행과 햅틱만 갱신하고 momentum 종료 때 최종 값을 확정한다. 외부 값 동기화가 아닌 매 행 변경마다 programmatic `scrollTo`하지 않는다 | iOS 시계 앱처럼 빠른 탐색과 한 칸 단위의 선택 감각을 함께 제공하기 위함 | 현행 결정·검증 완료 |
| 시간 wheel에만 햅틱을 허용하고 도착 여유 slider는 값만 변경 | 사용자가 5분 단위 경계를 넘었는지 화면을 보지 않으면 알기 어렵고, 실제 관찰에서 두 시간 제어 모두 촉각이 확인되지 않았다 | 햅틱 허용 범위를 도착/테스트 시각 wheel과 도착 여유 slider의 5분 단위 사용자 변경으로 제한한다 | 일반 버튼까지 진동을 확장하지 않으면서 시간 제어의 불연속 단위를 촉각으로 구분하기 위함 | 현행 결정·검증 완료 |

- 시스템 위치 권한은 첫 실행·로그인 직후에 요청하지 않는다. 사용자가 `내 위치 사용`을 누른 뒤, 추천 계산에 쓰는 목적을 짧게 설명하고 요청한다.
- 위치 권한 거절, GPS 불가, 부산 밖 좌표에도 지도 탭 또는 장소 검색으로 출발지·도착지를 직접 정할 수 있어야 한다.
- 출발지·도착지 변경은 별도 지도 버튼·검색 모달로 나누지 않고 하나의 위치 선택 화면에서 처리한다. 초기 화면은 `현위치`, `지도에서 선택`, 검색 입력을 제공하며, 출발지는 권한 허용 시 현위치를 자동 적용하고 도착지는 비워 둔다. 지도에서 선택은 앱 내부 지도에서 핀/중심 좌표를 고른 뒤 명시 확정하며, 지도 이동 중 역지오코딩을 반복하지 않고 확정 때만 1회 조회한다.
- 검색 입력은 장소명과 주소를 함께 받되, 두 제공사를 동시에 호출하지 않는다. 주소 형식(숫자·도로명·번지·동/리 등)은 카카오 주소 검색을 우선하고, 그 밖에는 카카오 키워드 장소 검색을 우선한다. 우선 검색이 0건일 때만 같은 카카오의 반대 검색을 1회 fallback한다. TMAP은 위치 선택 검색과 현행 자동 추천 경로 검증에 사용하지 않는다.
- 자동 제안은 한글 2글자 또는 숫자 입력 뒤 400ms debounce로 시작할 수 있다. 정규화한 `검색어 + 모드` 결과는 기기 메모리에서 10분 TTL로만 재사용하고, 동일 진행 요청은 합친다. 검색어·정밀 위치·선택 이력을 서버 장기 저장하지 않는다. 입력 변경 뒤에는 이전 검색의 선택·결과를 확정에 재사용하지 않고, 사용자가 결과 하나를 명시 선택해야 한다.
- 장소명 제안은 완전한 글자열 일치 하나로 끝내지 않는다. `사상역`을 검색하면 정확한 장소뿐 아니라 이름이 `사상역`으로 시작·포함되는 제공사 POI(역·출구·관련 장소)를 관련성 순으로 보여 준다. `사상역 2호선`처럼 고유 장소명과 교통 수식어를 함께 입력하면 제공사 표기 `사상역 부산2호선`처럼 도시명·공백·순서가 달라도 두 의미 토큰이 모두 일치하는 결과를 먼저 보이고, 원문 결과가 부족할 때는 고유 장소명으로 한 번 더 조회한 같은 역의 교통 POI를 보조 제안으로 보인다. 제공사가 노선명을 주지 않으면 UI는 `2호선`을 합성하지 않고 실제 장소명만 표시한다. 고유 장소명 없이 `2호선`처럼 수식어만 입력한 결과를 모든 역으로 넓히거나, 주소·무관 상호를 이 규칙으로 통과시키지 않는다.
- 2026-08-23의 최대 180분 방식은 1~3곳 조립 정책과 함께 이번 출시 경로에서 보류한다. 출시 UI는 현재 시각부터 최대 **120분**의 도착 시각만 선택하게 한다. 고정 시간·좌표 입력은 내 정보의 개발 전용 메뉴에만 둔다.
- 도착 시각과 개발 전용 테스트 시각은 같은 wheel picker 계약을 사용한다. 오전/오후·시·분 열은 선택 band에 한 행씩 snap하고, 빠르게 스와이프하면 관성으로 여러 행을 통과할 수 있어야 한다. `disableIntervalMomentum`처럼 한 번의 제스처를 한 칸으로 제한하는 설정은 사용하지 않는다.
- 이번 출시의 햅틱 적용 범위는 도착 시각·개발 테스트 시각 wheel과 `도착 전 남길 시간` slider로 한정한다. wheel은 실제 사용자 스크롤로 새 행 경계를 통과할 때, slider는 사용자가 실제 drag하여 새로운 5분 단위 값에 진입할 때 iOS selection haptic을 한 번만 발생시킨다. slider event가 여러 step을 건너뛰어도 누락 step 수만큼 진동을 합성하지 않고 실제 보고된 새 값에 한 번만 낸다. 최초 mount, 외부 prop 동기화, 같은 값의 중복 event, 최종 snap/complete 재확정에는 햅틱을 반복하지 않는다. 햅틱 사용 불가·시뮬레이터·시스템 제한은 조용히 무시하고 시간 선택을 막지 않는다. 이 두 시간 제어 외의 일반 CTA·카드·칩·뒤로가기·더보기·tray 삭제에는 추가하지 않는다.
- 빠른 momentum 중에도 햅틱 호출이 렌더나 스크롤을 막지 않도록 마지막 행 index를 ref로 중복 제거한다. 화면 상태에 반영할 최종 시각은 momentum 종료 시 한 번 확정하고, momentum이 생기지 않은 짧은 drag/tap은 drag 종료에서 확정한다.
- wheel은 VoiceOver에서 현재 값을 읽고 증가/감소 adjustable action으로 한 단계씩 조절할 수 있어야 한다. 접근성 조절에도 값은 바뀌지만 과도한 연속 햅틱은 만들지 않는다.
- 내 정보에는 개인정보 처리방침과 위치정보 관련 약관 진입점을 둔다. 링크의 문구와 App Store Connect의 개인정보 공개는 실제 수집·저장 동작과 항상 일치해야 한다.

## 3-2. 카카오맵식 단일 경로 설정 (2026-08-26, 현행·구현 전)

| 이전 방식 | 문제/관찰 | 교체 방식 | 이유 | 상태 |
|---|---|---|---|---|
| 시간 설정 화면의 `현재 위치`, `도착지/복귀` 두 행에서 각각 별도 선택 화면으로 이동 | 출발·도착 관계가 한눈에 보이지 않고, 검색을 누른 뒤에도 현위치·지도 선택이 중복되어 카카오맵 길찾기와 다른 탐색 흐름이 됐다 | 두 행을 `경로 설정하기` 하나로 교체한다. 누르면 출발지·도착지 필드를 함께 가진 단일 경로 설정 화면을 연다 | 사용자가 어느 필드를 바꾸는지, 도착지를 비우면 복귀인지 한 화면에서 이해하게 하기 위함 | 현행 규칙, 구현 전 |

- 경로 설정 화면의 출발지 필드는 위치 권한이 이미 허용된 경우에만 현재 GPS 좌표를 자동 적용하고, 지도 이동과 무관한 1회 위치 라벨 조회로 provider 주소(없으면 provider 행정구역)를 표시한다. 권한이 없거나 GPS를 읽지 못하면 권한을 자동 요청하지 않고 `출발지 선택` 상태로 둔다. 주소 조회가 실패해도 출발지를 지우지 않고 `현재 위치`로 남기며, 앱 실행 중 메모리 cache만 재사용한다.
- 출발지 또는 도착지 필드를 탭하면 **같은 위치 선택 화면**을 연다. 상단은 장소명·주소 공통 검색 입력이고, 빈 입력 아래에는 `현재 위치`, `지도에서 선택`을 둔다. 검색은 2글자/400ms·Kakao 단일 adapter 계약을 그대로 사용한다.
- `현재 위치`는 선택 중인 필드에 GPS 좌표를 후보로 올리고, 사용자는 `이 위치로 확정`으로 적용한다. 도착지에도 사용할 수 있으며, 도착지 필드를 비우고 `경로 적용`하면 출발지 복귀로 계산한다.
- `지도에서 선택`은 앱 내부 전체 지도에서 기기 위치(없으면 부산 중심)를 최초 중심으로 잡고, 화면 정중앙의 **물방울형 마커 핀**은 움직이지 않으며 지도만 이동한다. 핀 확정 전에는 역지오코딩하지 않는다. `이 위치로 선택` 때 위치 라벨 adapter가 도로명/지번 1회, 성공했지만 주소가 없을 때만 행정구역 1회를 호출한다. provider 행정구역은 `○○ 인근`처럼 주소와 구분해 표시하고, 둘 다 없거나 오류여도 좌표 선택·검색 대안을 유지한다.
- 경로 설정 화면의 `경로 적용`은 출발지가 명시 확정됐을 때만 활성화한다. 도착지는 선택하지 않아도 된다. 적용 뒤 시간 설정 화면에는 `출발지 → 도착지` 또는 `출발지로 돌아오기`의 간결한 요약만 표시한다.
- 이전 `origin-choice`, `destination-choice`, `location-permission`처럼 같은 선택 수단을 여러 화면에 나누는 진입 흐름은 철회한다. 위치 권한 설명은 위치 선택 화면에서 `현재 위치`를 누른 때에만 sheet/상태로 제공한다.

## 4. 코스 만들기 지도와 장소 시트

- 지도 상단 컨트롤은 safe-area 아래 한 줄에 둔다: 뒤로가기, 코스 만들기, 남은 자투리, 코스 확인.
- **출시 기본 경험**: 첫 결과는 지도 전체 후보가 아니라 `종료 시각까지 N분 · 도착 전 여유 M분`과 상단 `시간의 추천` **1곳**을 먼저 보여 준다. 그 아래에는 같은 세션에서 실제 경로 검증을 통과한 서로 다른 **1곳** 대안을 최대 3개까지 보인다. 지도는 보조 탐색이다.
- 상단 `이 시간의 추천`과 대안은 `출발 → 한 장소 → 도착/복귀`의 실제 경로·접근시간·구조화 운영시간·최소 체류·도착 여유를 검증한 결과다. 과거 mixed 2·3곳 자동 코스와 다장소 이어보기는 이번 출시 화면에 노출하지 않는다. 사용자가 검증 A에서 명시적으로 시작하는 pair-only 2곳만 아래 `최대 2곳 제한 조립`의 자동 게이트를 통과해 예외로 활성화한다.

- 두 번째 후보는 기본 3개 목표, 부족 허용, 더보기 포함 누적 최대 6개다. 36회 session 예산 중 명시 확장 12회는 첫 장소 목록과 두 번째 장소 목록의 더보기가 공유하므로, 남은 예산이 없으면 버튼을 반복 실행하지 않고 현재 결과와 중립적인 소진 안내를 남긴다. A 선택 즉시 tray·one-stop CTA·검증 중인 B 영역을 보여 주되, 검증되지 않은 B를 선택 가능하게 만들지는 않는다. B 첫 결과 지연을 줄이기 전에는 원격 운영 활성화로 진행하지 않는다.
- B 후보 카드의 시간은 A까지 포함한 2곳 전체 합계를 B 자체 시간처럼 `약 N분 코스`로 표시하지 않는다. 같은 입력의 exact snapshot에서 `(pair 이동+체류) - (선택 A one-stop 이동+체류)`로 계산한 **추가 소요시간**을 `함께 가면 약 N분 추가`로 표시한다. 도착 여유는 양쪽 계산에서 제외하고 실제 pair 방문 순서가 B→A여도 같은 차이를 사용한다. 차이가 0 이하이거나 snapshot이 불일치하면 임의 보정하지 않고 `선택 시 전체 약 N분`으로 명확히 표시한다. B 단독 `출발→B→도착` 시간처럼 표현하거나 이를 얻기 위한 새 route 호출은 하지 않는다.
- 같은 추천 세션에서 exact로 확인한 두 장소 집합은 첫 선택 장소를 바꿔도 같은 조합이다. `A 선택→B 확인→A 취소→B 선택`에서는 이미 검증된 A를 신규 route 0회로 우선 표시하고 실제 방문 순서는 기존 exact snapshot을 유지한다. 이는 새 추천 세션의 모든 미검증 조합을 대칭으로 보장하는 규칙이 아니며, 아직 검증하지 않은 후보는 기존 목표 3·호출 예산·더보기를 따른다. provider/store/continuation terminal partial은 pair store에 승격하지 않고, attempt-limit 전에 이미 exact로 확인된 partial은 유지한다. 상태: **현행 결정·U-TWO-STOP-04·QA-TWO-STOP-02 자동 수락·실기기 체감 1회 남음**.
- 지도 경로 범례는 오른쪽 하단에 둔다. 지도 상단 컨트롤이나 상태 표시 영역과 겹치면 안 된다.
- 장소 시트는 세 단계로 동작한다: 지도 중심 접힘, 지도·목록 기본 보기, 장소 중심 90% 확장.
- 시트 최상단 헤더 영역에서만 스와이프로 높이를 전환한다. 장소 카드 영역의 스와이프는 목록 스크롤만 수행한다.
- **이전 상세 시트 방식(철회):** 카드 선택 전의 기본·90% 시트 높이를 유지한 상세는 현재 위치와 장소의 공간 관계가 작게 보여 새 선택 흐름에서 사용하지 않는다.
- **전체 지도형 장소 상세(현행 결정·구현 전):** 장소 카드를 누르면 계층형 상세 화면을 열어 safe-area 아래의 전체 지도를 주 화면으로 사용한다. 지도에는 후보 장소와 이미 허용된 실제 현재 위치를 함께 보이고, 설정 출발지가 다르면 지점을 구분한다. 상세 진입만으로 새 위치 권한 prompt를 띄우지 않으며 권한 거절·미결정/GPS 실패는 진입을 막지 않고 설정 출발지를 fallback으로 표시한다. 상단 닫기 control과 하단 floating sheet에는 사진·장소명·category/subCategory·근거 있는 설명·운영시간 상태·주소·카카오맵 장소 보기·명시 `선택하기`를 제공한다. 설명/운영시간이 없으면 합성하지 않고 `상세 설명 없음`/`운영시간 확인 필요`로 표시한다. 상세 진입 live Kakao/TourAPI/Route Proxy 호출은 0회다.
- 상세 시트의 사진은 고정 영역 안에서 `cover`로 표시하고 둥근 모서리를 적용한다. 사진이 없으면 카테고리 기반 대체 화면을 표시한다.
- 모든 상세 장소에는 카카오맵 확인 링크를 제공한다. 검증된 카카오 장소 URL을 우선 사용하고, 없으면 카탈로그 주소 검색을 사용한다. 주소가 없거나 지나치게 넓으면 좌표 지도 보기 fallback을 쓰되 장소명과 좌표를 하나의 검색어로 만들지 않는다.
- 기본·접힘 시트에서 목록 마지막 카드가 하단 바나 보이지 않는 시트 영역에 가려지면 안 된다. 시트 상태별 숨김 높이를 목록 끝 여백에 반영한다.
- 지도 마커와 장소 카드는 양방향으로 같은 장소에 포커스된다. 지도 중심은 현재 시트의 실제 가시 영역 중심을 기준으로 계산한다.
- 뒤로가기·남은 시간·코스 확인은 기본·접힘 시트에서 지도 상단에 고정한다. 90% 확장 시트는 이 컨트롤보다 높은 레이어에서 지도 영역을 덮고, 동일한 기능을 시트 내부 헤더에 중복하지 않는다. 이 규칙은 이전의 `확장 시 시트 내부 헤더 표시` 규칙을 대체한다.
- 코스 확인은 지도와 분리된 전체 페이지이므로, 콘텐츠 첫 영역도 safe-area 아래에서 시작해야 한다.
- 코스 화면의 검토 상태는 선택된 1곳 또는 2곳, 왕복 또는 도착지까지의 각 실제 구간 이동, 선택 체류, 도착 전 여유와 운영시간 상태를 최종 검토한다. 2곳은 사용자의 선택 순서가 아니라 엔진이 `O→A→B→D`와 `O→B→A→D`를 exact 비교해 선택한 최소 이동 유효 순서로 지도 번호·세로 카드를 정렬한다. 지도 아래에는 `출발지 → 이동 → 장소 → 이동 → [장소 → 이동 →] 도착지/복귀 → 도착 여유`를 표시한다.
- 코스 확인 상단 지도는 우선 추천 검증 snapshot의 WGS84 geometry로 `설정 출발지 → 추천 장소 → 설정 목적지/복귀`를 즉시 그린다. transit geometry의 시작점 또는 하차 종점이 실제 leg endpoint와 50m를 초과해 끊기면, **장소 선택 후 `코스 보기`로 최종 CourseConfirm에 진입했을 때만** 누락 endpoint↔기존 transit 선 끝의 실제 Kakao 도보 geometry를 1곳(2 legs)은 최대 4개, 2곳(3 legs)은 최대 6개 보충한다. 기존 선은 즉시 보이고, 보충 중에도 상세·CTA를 막지 않는다. 보충 walk의 분 수는 기존 추천 시간에 더하거나 순위를 바꾸지 않는다. 실시간 GPS 재계산·직선 연결·transit 재조회는 금지한다. 보충 실패 또는 세션 부재시 부분 선만 표시하고 `일부 도보 경로선을 표시하지 못했어요`를 한 번 안내하며 마커·세로 시간표·코스 시작을 유지한다. 도보·대중교통은 구분되는 선과 범례로 표시하고, 왕복의 같은 좌표는 `출발·복귀` 마커 하나로 표현한다.
- 코스 화면에서는 후보 수·운영시간 집계·안내 배너처럼 경로 검토와 중복되는 설명을 제거한다. 검토 상태의 `코스 시작하기` 뒤 별도 중복 진행 화면을 push하지 않고 동일 snapshot·지도·세로 순서를 유지한 채 진행 상태로 바꾼다. 진행 상태는 완료/현재/미래 구간을 표시하며 현재 다음 구간의 카카오 길찾기만 활성화한다.

- V1 진행은 `RecommendationSession + VerifiedCourseV1`의 직렬화 가능한 snapshot만 사용한다. 2곳은 엔진이 exact 비교한 최적 방문 순서와 검증 legs를 그대로 사용하며, UI가 선택 순서·직선거리로 다시 정렬하거나 stop의 `stayMin`/`stayState`·예정 시각·도착 여유를 수정하지 않는다.
- 코스 확인의 대중교통 leg는 leg 전체를 하나의 주황선으로 단순화하지 않는다. provider가 명시한 하위 구간은 그 mode를 그대로 쓰고, provider가 빠뜨린 시작·종점 도보만 50m 초과 gap에서 선택 후 조회로 보충한다. 즉 `도보 → 대중교통 → 필요한 환승 구간 → 마지막 도보`의 실제 형상을 순서대로 표시한다. 직선·endpoint 강제 삽입·분 수 합산은 하지 않는다.
- 검토 상태에서는 `코스 시작하기`만 primary다. 진행 상태에서는 최적 순서의 현재 이동만 `카카오맵에서 길찾기`, 각 체류 뒤에는 현재 다음 구간의 `다음 장소 길찾기`, 마지막 travel을 연 뒤에는 `도착 후 코스 마치기`가 유일한 primary CTA다. 미래 구간의 길찾기는 순서를 건너뛰지 못하도록 비활성화한다. 길찾기 실행만으로 도착·체류·완료를 자동 기록하거나 추정하지 않는다.
- 같은 구간의 진행 중 중복 탭은 한 번만 실행한다. 숫자·범위가 잘못된 출발/도착 좌표는 외부 URL을 만들지 않고 fail-closed하며, app→HTTPS→browser가 모두 실패하면 현재 단계와 재시도 CTA를 유지하고 비밀 없는 일반 오류만 보인다. production 화면·로그에는 URL·좌표·raw provider 오류를 보이지 않는다.
- 외부 카카오맵 foreground 복귀는 화면 메모리의 현재 단계와 CTA를 유지한다. 이 문장은 `U-PROGRESS-01`까지 구현된 기준선이며, 강제 종료 복원·Live Activity·사용자 확인 체류 저장은 아래 `4-1-1`의 구현으로 교체한다. GPS·자동 도착·백그라운드 위치 추적을 시작하지 않는 규칙은 계속 유지한다.

- 길찾기 handoff가 실제 성공해야 `traveling`과 Live Activity를 시작한다. 화면을 열거나 버튼을 눌렀다는 이유만으로 시작하지 않는다.
- 도착 알림 행동은 `도착했어요`, `5분 뒤 다시 알림`이다. 다시 알림은 1회이며, 무시하거나 응답하지 않아도 Live Activity를 종료하지 않는다. 사용자는 알림 전에도 도착을 확인할 수 있다.
- 알림 권한은 첫 실행에 요청하지 않는다. 첫 `카카오맵에서 길찾기` handoff 직전에 도착·출발 알림 목적을 한 번 설명하고 요청하며, 거절해도 길찾기와 앱 진행을 계속한다.
- `latestSafeDepartureAt = 최종 도착/복귀 시각 - 사용자 도착 여유 - 남은 검증 snapshot 이동 합 - 이후 선택 장소 체류 합`이며, 5분 전에 출발을 알린다. 이동 합은 GPS 실측이 아니라 추천 때 실제 경로로 검증한 분 수다. 도착 확인이 늦어도 약속 시각을 뒤로 미루지 않는다.
- 다음 장소·목적지·복귀 길찾기 handoff 성공 또는 앱 안 `둘러보기 완료`가 직전 장소 출발을 확정한다. handoff 실패는 출발이나 체류 종료가 아니다.
- 도착 미확인과 도착 후 출발 미확인은 개인화 표본이 아니다. 예상 시각으로 사용자의 행동을 합성하지 않는다.
- 비로그인과 Route Proxy anonymous Auth에서도 로컬 진행은 가능하지만 서버 개인화 저장은 하지 않는다. 일반 로그인과 `맞춤 추천을 위한 체류 기록` 동의를 모두 만족해야 저장한다.
- 내 정보에서 앱이 직접 바꾸는 토글은 체류 기록 동의뿐이다. 알림·위치·Live Activity는 시스템 상태와 `설정에서 변경` 행동으로 표시한다. 거절 후에도 다시 켤 수 있고 활성화 전 기록은 소급 수집하지 않는다.
- GPS 자동 도착/이탈, 연속 좌표, 이동 polyline 저장, `Always` 위치 권한, background location mode는 이번 배포에서 사용하지 않는다.

상세 상태·시각·저장 계약은 [DEC-LIVE-DWELL-01](../work/integration-decision/live-activity-dwell-personalization.md)을 따른다.

## 6. 자투리 기록

- `기록` 탭은 이번 달 **완료 확인된** 활동만 집계한다. 장소 선택·저장·카카오맵 열기만으로 완료 장소 수나 활용 시간을 올리지 않는다.
- 완료 확인의 근거는 진행 화면의 명시 `코스 마치기`다. 후기는 만족도·메모를 위한 선택 행동이며 완료 기록 생성의 조건이나 대체물이 아니다.
- 같은 활성 코스의 완료 연타·재시도·앱 복구는 안정적인 `courseRunId`로 한 건만 기록한다. 길찾기 실행이나 외부 지도 복귀만으로 완료를 추정하지 않는다.
- 사용자 확인 도착·출발이 없어 실제 체류시간을 측정하지 못했다면 장소 수·카테고리 활동에는 포함하지만 활동 시간과 개인화 표본에는 포함하지 않는다. 계획 체류를 실제 체류로 대체하거나 `0분 활동`으로 단정하지 않는다.
- 기록 화면은 활동 카테고리 비율 원그래프, 측정된 완료 활동 시간, 완료 장소 수, 활동 유형 수만 우선 보여 준다. "앱이 없었으면 낭비했을 시간"처럼 검증할 수 없는 비교·평가는 표시하지 않는다.
- 완료 기록이 없으면 시간·장소 수를 0으로 과장하지 않고, 기록이 쌓이는 조건만 간결하게 안내한다.
