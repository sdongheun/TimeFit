# TimeFit UIUX 공통 규칙

이 문서는 화면을 추가하거나 수정할 때 반드시 지켜야 하는 UIUX 규칙이다.

## 0. 기본 원칙

- UI는 간단하고 깔끔하게 유지한다. 한 화면에는 사용자가 바로 수행할 핵심 행동 하나만 우선순위로 둔다.
- 처음 사용하는 사람도 설명을 읽지 않고 다음 행동을 알 수 있게, 행동의 결과를 버튼 위치·아이콘·상태 변화로 보여 준다.
- 기능 설명, 반복 안내, 내부 계산 근거처럼 행동에 필요하지 않은 텍스트는 화면에 상시 노출하지 않는다. 시간·장소·이동수단·남은 시간처럼 결정에 필요한 정보만 남긴다.
- 화면 안에서 선택을 끝낼 수 있으면 별도 상세 화면을 추가하지 않는다. 새 화면은 입력, 비교, 확정, 진행처럼 목적이 명확히 달라질 때만 사용한다.

## 1. 안전 영역

- iPhone의 상태 표시 영역(시간, Dynamic Island 또는 노치, 네트워크, 배터리)과 앱의 텍스트·버튼·지도 컨트롤은 절대 겹치면 안 된다.
- 자체 헤더, 지도 위 컨트롤, 전체 페이지의 첫 콘텐츠는 `useSafeAreaInsets().top`을 기준으로 배치한다.
- 네이티브 스택 헤더를 사용하는 화면은 iOS가 제공하는 안전 영역을 사용한다. 커스텀 헤더로 바꾸면 직접 safe-area inset을 적용한다.
- 하단 플로팅 바와 고정 CTA는 홈 인디케이터를 피하도록 `useSafeAreaInsets().bottom`을 반영한다.
- 고정 `paddingTop` 또는 `bottom` 값만으로 상태 표시 영역을 피하지 않는다.

## 2. 화면 전환과 뒤로가기

- 화면 전환은 `250ms` 페이드 전환을 사용한다.
- 사용자가 진입한 화면에는 이전 단계로 돌아가거나 취소할 수 있는 명확한 경로가 있어야 한다.
- 뒤로가기는 텍스트가 아닌 왼쪽 화살표 아이콘 버튼으로 통일하고 접근성 레이블을 제공한다. 터치 영역은 최소 `42px`로 유지한다.
- 지도 위·콘텐츠 위 커스텀 헤더의 뒤로가기는 `42px`, 모서리 반경 `12px`, `C.panel2` 배경과 `C.line` 테두리를 사용한다. 네이티브 스택 헤더에서는 화살표만 표시하고 외곽 배경·테두리·타원을 만들지 않는다. `Home`, `상세` 같은 프레임워크 기본 뒤로가기 레이블은 노출하지 않는다.
- 코스 진행 화면의 뒤로가기는 이전 화면 스택이 아니라 `내 코스` 최상위 탭으로 이동한다.
- 하단 탭은 메인, 내 코스, 내정보의 최상위 영역을 전환한다. 탭 전환 때문에 이전 화면 스택이 계속 쌓이면 안 된다.
- 메인에서 시작한 입력 흐름은 `자투리 시간 설정 → 코스 만들기 → 장바구니` 순서로 유지한다. `코스 만들기`의 뒤로가기는 메인이 아니라 입력값을 유지한 `자투리 시간 설정`으로 돌아간다.
- 장바구니의 뒤로가기는 같은 추천 세션의 `코스 만들기`로 돌아간다. 사용자가 입력·선택을 버리지 않고 수정할 수 있어야 한다.
- 코스 확정 뒤에는 별도 상세 확인 화면을 거치지 않는다. 저장 후 바로 코스 진행 화면으로 연결한다. 미래 시간 코스처럼 즉시 진행하지 않는 경우에만 `내 코스`에 저장해 둔다.

## 3. 주요 버튼

- 화면을 진행시키는 주요 CTA는 다음 규격을 사용한다: 높이 `52px`, 모서리 반경 `12px`, `C.accent` 배경, `C.onAccent` 텍스트, `16px` 굵은 글자.
- 저장, 삭제, 필터, 순서 변경, 뒤로가기처럼 보조 행동은 주요 CTA와 구분되는 보조 버튼 형태를 사용한다.
- 아이콘만 있는 버튼은 접근성 레이블을 제공한다.

## 4. 코스 만들기 지도와 장소 시트

- 지도 상단 컨트롤은 safe-area 아래 한 줄에 둔다: 뒤로가기, 코스 만들기, 남은 자투리, 장바구니.
- 후보 지도는 도보·대중교통·차량 중 하나라도 시간 안에 성립하는 장소를 보여 준다. 장소 카드에는 세 수단의 가능 상태를 아이콘으로 먼저 보여 주되, 코스 전체 이동수단을 고정하지 않는다.
- `여유 있음`, `짧게 가능`, `빠듯함`, `시간 초과`의 의미를 색상과 짧은 텍스트로 일관되게 구분한다.
- 후보 카테고리는 분위기·활동의 조합 필터가 아니라 하나의 가로 스크롤 칩으로 제공한다. 화면에는 `전체`, `음식점`, `카페`, `자연관광`, `문화`, `쇼핑·거리`, `레저`처럼 데이터 카테고리를 바로 이해할 수 있는 이름을 쓴다.
- `장소 후보 n`은 기본·90% 확장 시트에서 공통으로 보이게 한다. 지도만 보는 접힘 상태와 장소 상세 상태에서는 중복 표기를 피한다.
- 장소 카드의 상세 확장 화살표는 오른쪽 보조 영역이 아니라 카드 하단 중앙에 둔다. 제목·상태 정보와 분리해 확장 가능함을 짧게 알린다.
- 장바구니는 아이콘과 수량 배지로 표시하며, 장소를 담거나 빼면 수량이 즉시 반영된다.
- 지도 경로 범례는 오른쪽 하단에 둔다. 지도 상단 컨트롤이나 상태 표시 영역과 겹치면 안 된다.
- 장소 시트는 세 단계로 동작한다: 지도 중심 접힘, 지도·목록 기본 보기, 장소 중심 90% 확장.
- 시트 최상단 헤더 영역에서만 스와이프로 높이를 전환한다. 장소 카드 영역의 스와이프는 목록 스크롤만 수행한다.
- 장소 카드를 누르면 별도 모달을 열지 않는다. 카드 선택 전의 기본·90% 확장 시트 높이를 유지한 채 해당 장소의 사진, 이동·체류·남는 시간, 이동수단 선택, 장바구니 담기를 한 흐름으로 보여 준다.
- 상세 시트는 아래에서 올라오고 닫을 때 아래로 내려가는 짧은 전환을 사용한다. 목록으로 돌아가는 아이콘은 아래 방향 화살표로 표시한다.
- 상세 시트의 사진은 고정 영역 안에서 `cover`로 표시하고 둥근 모서리를 적용한다. 사진이 없으면 카테고리 기반 대체 화면을 표시한다.
- 모든 상세 장소에는 카카오맵 확인 링크를 제공한다. 검증된 카카오 장소 URL을 우선 사용하고, 없으면 장소명과 좌표 기반 지도 링크를 사용한다.
- 기본·접힘 시트에서 목록 마지막 카드가 하단 바나 보이지 않는 시트 영역에 가려지면 안 된다. 시트 상태별 숨김 높이를 목록 끝 여백에 반영한다.
- 지도 마커와 장소 카드는 양방향으로 같은 장소에 포커스된다. 지도 중심은 현재 시트의 실제 가시 영역 중심을 기준으로 계산한다.
- 뒤로가기·남은 시간·장바구니는 기본·접힘 시트에서 지도 상단에 고정한다. 90% 확장 시트는 이 컨트롤보다 높은 레이어에서 지도 영역을 덮고, 동일한 기능을 시트 내부 헤더에 중복하지 않는다. 이 규칙은 이전의 `확장 시 시트 내부 헤더 표시` 규칙을 대체한다.
- 장바구니는 지도와 분리된 전체 페이지이므로, 콘텐츠 첫 영역도 safe-area 아래에서 시작해야 한다.
- 장바구니는 선택 장소의 편집과 최종 검토를 함께 맡는다. 별도 코스 상세 페이지를 두지 않으며, 확정 버튼은 코스를 저장한 뒤 바로 진행 화면으로 연결한다.
- 장바구니 상단 약 `30%`는 선택 순서의 경로 지도에 사용한다. 지도 위에는 뒤로가기 아이콘만 둔다.
- 장바구니에서는 후보 수·운영시간 집계·안내 배너처럼 경로 검토와 중복되는 설명을 제거한다. 장소 목록, 이동·체류·여유시간, 구간 시간, 확정 CTA만 유지한다.

## 5. 상태와 오류

- 로딩 중에는 같은 요청을 중복 실행할 수 없게 한다.
- 빈 목록, 저장 실패, 네트워크 실패, 로그인 상태 확인 중처럼 데이터 상태가 다른 경우를 화면에 명확히 표시한다.
- 테스트용 시간·위치 입력 흐름은 검증이 끝날 때까지 접근 가능하게 유지한다.
