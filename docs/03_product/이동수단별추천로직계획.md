# 이동수단별 추천 로직 계획

> 작성: 2026-07-25  
> 목적: 추천 전 이동수단을 선택하게 하고, 도보·대중교통·차량별로 다른 기준으로 코스를 생성한다.

## 1. 결정 사항

기존 방향은 "장소를 먼저 추천하고 상세에서 도보/자동차 시간을 비교"였다. 실제 테스트에서 도보 사용자가 자동차로만 가능한 코스를 받을 수 있고, 남은 시간이 길어도 단일 장소가 상위에 고정되는 문제가 확인됐다.

따라서 추천 전 사용자가 이동수단을 선택한다.

```text
도보
대중교통
차량
```

추천 가능 여부, 후보 반경, 코스 조합, 랭킹은 선택한 이동수단 기준으로 판단한다. 상세 화면에서는 보조 정보로 다른 수단의 시간도 보여줄 수 있지만, 추천 포함 여부를 결정하지 않는다.

이 서비스의 차별점은 길찾기 자체가 아니다. 경로 계산과 시간 계산은 TMAP, ODsay, TAGO, 부산도시철도 API를 활용하고, 실제 길찾기 실행은 카카오맵으로 위임한다. TimeFit은 API 결과와 자체 데이터를 조합해 "남는 시간에 무엇을 하면 좋은가"를 판단하는 추천 알고리즘을 만든다.

차별화 요소:

```text
날씨
이동거리/이동시간
운영시간
체류시간
사용자 취향
다음 일정
시간대
카테고리 적합도
```

기존 길찾기 앱은 목적지까지 가는 방법을 잘 알려준다. TimeFit은 그 전에 "지금 가진 시간과 상황에서 들를 만한 장소와 코스"를 계산한다.

## 2. 공통 입력

```text
현재 위치: 직접 입력 또는 GPS
약속 장소: TMAP 장소/주소 검색
남은 시간: 최대 240분
이동수단: 도보 / 대중교통 / 차량
테스트 시간: 현재 시각 또는 수동 시각
취향: 활동/분위기/카테고리 선호
```

공통 계산:

```text
buffer = max(10분, 남은시간 * 0.12)
budget = 남은시간 - buffer
최소 체류 가능 시간 = 30분
```

약속 장소가 있으면:

```text
현재 위치 -> 추천 장소 1 -> 추천 장소 2 -> 약속 장소
```

약속 장소가 없으면:

```text
현재 위치 -> 추천 장소 1 -> 추천 장소 2 -> 현재 위치
```

## 3. 공통 후보 전략

약속 장소가 있을 때는 최소 세 가지 전략을 만든다.

| 전략 | 의미 | 예시 |
|---|---|---|
| 출발지 근처 | 현재 위치 근처에서 시간을 쓰고 약속 장소로 이동 | 서면에서 출발해 사상역 약속 |
| 약속지 근처 | 약속 장소로 먼저 이동한 뒤 주변에서 시간 사용 | 사상역 근처에서 둘러보기 |
| 가는 길 중간 | 이동 경로 중간 근처에서 하차/경유 | 서면-사상 사이 중간 지역 |

약속 장소가 없으면 출발지 근처 왕복 전략만 사용한다.

## 4. 코스 구성 원칙

2곳 코스는 "두 장소가 무조건 가까워야 한다"는 뜻이 아니다. 자투리 시간 앱에서 중요한 것은 남은 시간을 어떻게 자연스럽게 쓰는가다.

예를 들어 사용자가 120분을 입력했을 때:

```text
장소 A: 이동 20분 + 권장 체류 80분 + 약속장소 이동 15분 = 115분
→ 단일 장소 추천이 적합

장소 B: 이동 15분 + 권장 체류 30분 + 약속장소 이동 15분 = 60분
→ 시간이 많이 남으므로 짧은 체류 장소 C를 추가할 수 있음
```

따라서 2곳 코스 생성 기준은 거리만이 아니라 다음 조건을 함께 본다.

| 기준 | 의미 |
|---|---|
| 시간 활용 | 단일 장소 추천 후 시간이 많이 남는가 |
| 체류시간 보완 | 첫 장소의 체류시간이 짧아 다른 짧은 장소를 붙이는 것이 자연스러운가 |
| 동선 효율 | 추가 장소 때문에 약속 장소와 반대 방향으로 크게 우회하지 않는가 |
| 이동수단 적합성 | 선택한 이동수단으로 장소 간 이동이 부담스럽지 않은가 |
| 카테고리 조합 | 같은 경험을 반복하지 않는가 |
| 운영시간 | 두 장소 모두 머무는 시간에 열려 있는가 |

### 단일/2곳 판단

```text
singleTotal = 출발 -> 장소A 이동 + 장소A 권장 체류 + 장소A -> 약속장소 이동
singleSlack = budget - singleTotal
```

단일 장소가 충분한 경우:

```text
singleSlack < 35분
또는 장소A 권장 체류시간이 60분 이상
또는 추가 장소를 넣으면 우회율이 과도함
```

2곳을 적극 검토하는 경우:

```text
singleSlack >= 35분
그리고 장소A 권장 체류시간이 짧거나 중간 정도
그리고 장소B를 추가해도 최소 체류 20~30분 이상 가능
그리고 전체 코스가 budget 안에 들어옴
```

### 2곳 코스의 형태

| 형태 | 설명 | 예시 |
|---|---|---|
| 가까운 2곳 | 서로 가까운 장소를 연속 방문 | 전시관 + 근처 산책지 |
| 짧은 체류 보완 | 첫 장소가 짧아 다른 짧은 장소를 추가 | 카페 30분 + 근처 서점 25분 |
| 약속지 이동 후 2곳 | 약속 장소 근처에서 짧게 2곳 | 사상역 근처 시장 + 카페 |
| 가는 길 경유 2곳 | 중간 지역에서 둘러보고 약속지로 이동 | 서면-사상 중간 경유 |

즉, "2곳 = 붙어 있는 장소"가 아니라 "시간을 더 잘 쓰는 조합"이다. 가까움은 중요한 가점이지만 절대 조건은 아니다.

## 5. 도보 추천 규칙

도보는 "가까움"이 핵심이다. 오래 걷는 코스는 자투리 시간 앱의 사용성과 맞지 않는다.

### 후보 반경

| 남은 시간 | 후보 반경 |
|---|---|
| 60분 이하 | 700m |
| 61~120분 | 1,000m |
| 121~240분 | 1,500m |

약속 장소가 있으면 출발지/약속지/중간점 각각 위 반경을 적용한다.

### 추천 가능 조건

```text
도보 총 이동시간 + 체류시간 <= budget
도보 기준 남은 체류 가능 시간 >= 30분
```

도보 선택 시 자동차로만 가능한 코스는 제외한다.

### 2곳 코스 조건

| 조건 | 기준 |
|---|---|
| 장소 간 도보 이동 | 가까울수록 가점 |
| 기본 허용 범위 | 12분 이하 우선 |
| 시간 보완형 예외 | 남는 시간이 충분하고 우회가 작으면 18분까지 허용 |
| 단일 장소 여유시간 | `singleSlack >= 35분`이면 2곳 후보 적극 검토 |
| 식당+식당 | 제외 |
| 카페+카페 | 제외 |
| 같은 장소 중복 | 제외 |

남은 시간이 120분 이상이면 미니코스 1개 이상을 상위 추천에 포함하도록 시도한다. 단, 억지 조합이 되면 단일 코스를 유지한다.

## 6. 차량 추천 규칙

차량은 자차와 택시를 같은 이동 모델로 묶는다. 주차 관련 판단은 MVP에서 제외한다. 주차 가능 여부, 주차장 위치, 주차비, 주차 대기까지 고려하면 범위가 지나치게 커지므로 차량 이동시간만 본다.

### 후보 반경

| 남은 시간 | 후보 반경 |
|---|---|
| 60분 이하 | 2km |
| 61~120분 | 4km |
| 121~240분 | 8km |

약속 장소가 있으면 출발지/약속지/중간점 후보를 모두 사용한다.

### 추천 가능 조건

```text
차량 총 이동시간 + 체류시간 <= budget
차량 기준 남은 체류 가능 시간 >= 30분
```

차량 선택 시 도보로 힘든 코스도 추천될 수 있다. 대신 결과 카드에 "차량 기준"임을 명확히 표시한다.

### 2곳 코스 조건

| 조건 | 기준 |
|---|---|
| 장소 간 차량 이동 | 짧을수록 가점 |
| 기본 허용 범위 | 15분 이하 우선 |
| 시간 보완형 예외 | 남는 시간이 충분하고 우회가 작으면 25분까지 허용 |
| 단일 장소 여유시간 | `singleSlack >= 35분`이면 2곳 후보 적극 검토 |
| 우회율 | 직접 이동 대비 1.8배 이상 제외 |
| 식당+식당 | 제외 |
| 카페+카페 | 제외 |

실제 길찾기와 내비게이션은 카카오맵으로 이동해 위임한다. TimeFit은 "차량 기준으로 이 코스를 넣을 수 있는가"와 "남은 시간에 적합한가"만 판단한다.

## 7. 대중교통 추천 규칙

대중교통은 버스와 지하철을 함께 고려한다. ODsay를 기본 경로 탐색 API로 사용하고, 실시간성은 후속 API로 보강한다.

추천 결과에서는 가장 효율적인 대중교통 경로를 최대 3가지 정도 보여준다.

```text
1순위: 최단 시간
2순위: 환승 적음
3순위: 도보 접근 부담 적음 또는 요금/편의 균형
```

버스만, 지하철만, 버스+지하철 조합을 따로 고정하지 않는다. API가 반환한 경로 중 사용자의 남은 시간과 다음 일정에 가장 맞는 경로를 선택한다.

### 사용할 API

| 역할 | API | 사용 시점 |
|---|---|---|
| 대중교통 경로/총 소요시간 | ODsay `searchPubTransPathT` | 상위 후보 또는 상세 진입 |
| 주변 정류장/역 검색 | ODsay `pointSearch`, `searchStation` | 정류장/역 매칭 |
| 버스 실시간 도착 | TAGO 버스도착정보 | 선택 경로 보강 |
| 지하철 시각표 | 부산도시철도 열차시각표 조회 서비스 | 선택 경로 보강 |

ODsay에서 얻을 수 있는 값:

```text
총 소요시간
요금
환승 횟수
버스/지하철 경로 수
승차 정류장/역
하차 정류장/역
구간별 수단
구간별 소요시간
도보 접근 거리
```

### 추천 가능 조건

```text
대중교통 총 이동시간 + 체류시간 <= budget
대중교통 기준 남은 체류 가능 시간 >= 30분
```

ODsay 호출량 보호를 위해 모든 후보에 바로 호출하지 않는다.

1. haversine으로 1차 후보를 줄인다.
2. 상위 후보만 ODsay로 정밀 계산한다.
3. 추천 목록에서는 ODsay 호출 수를 제한한다.
4. 상세 진입 시 선택 코스의 경로를 정밀 보강한다.

### 2곳 코스 조건

| 조건 | 기준 |
|---|---|
| 장소 간 대중교통 이동 | 짧을수록 가점 |
| 기본 허용 범위 | 20분 이하 우선 |
| 시간 보완형 예외 | 남는 시간이 충분하고 환승 부담이 작으면 완화 |
| 단일 장소 여유시간 | `singleSlack >= 35분`이면 2곳 후보 적극 검토 |
| 환승 수 | 과도한 환승 감점 |
| 첫 승차까지 도보 | 12분 초과 감점 |
| 마지막 하차 후 도보 | 12분 초과 감점 |
| 식당+식당 | 제외 |
| 카페+카페 | 제외 |

대중교통은 "중간 하차" 전략이 가장 자연스럽다. 출발지 근처, 약속지 근처 외에 ODsay 경로의 주요 환승/정류장 주변 후보를 후속 단계에서 추가할 수 있다.

실제 길찾기는 카카오맵으로 위임한다. TimeFit은 대중교통 경로 후보와 추천 장소를 계산하고, 사용자가 실행을 선택하면 카카오맵 길찾기로 넘긴다.

## 8. 추천 알고리즘 방향

TimeFit의 핵심은 단순한 "근처 관광지 추천"이 아니라 상황 기반 추천 점수다.

추천 점수는 다음 요소를 조합한다.

| 요소 | 반영 방식 |
|---|---|
| 시간 적합성 | budget 안에 들어오는가, 체류 가능 시간이 충분한가 |
| 이동 효율 | 선택 이동수단 기준 이동시간과 우회율 |
| 체류시간 | AIHub 직접 매칭 또는 카테고리 중앙값 |
| 운영시간 | TourAPI 운영시간/행사기간 게이트 |
| 날씨 | 야외/실내 카테고리 가중치 조정 |
| 사용자 취향 | 활동/분위기/카테고리 선호 가중치 |
| 다음 일정 | 약속장소 도착 여유, 약속지 근처 전략 가중 |
| 카테고리 조합 | 같은 경험 반복 감점 |
| 장소 신뢰도 | AIHub 직접 매칭 우선, 카테고리 폴백은 보수적 가중 |

예시:

```text
비 오는 날 + 도보 + 90분
→ 야외 자연관광지 감점, 실내 문화시설/카페 가점

약속장소가 사상역 + 남은 시간 120분
→ 사상역 근처 또는 가는 길 중간 전략 가점

사용자가 문화/조용한 분위기 선호
→ 문화시설, 서점, 전시 계열 가점
```

이 점수는 ML 모델이 아니라 설명 가능한 규칙 기반으로 시작한다. 각 추천 카드에는 왜 가능한지, 왜 추천했는지를 보여준다.

```text
예: 비가 와서 실내 장소 위주 · 약속지까지 18분 · 약 45분 머물 수 있음
```

## 9. API 호출량 정책

경로 API는 추천 품질보다 먼저 사용량을 통제해야 한다.

| 단계 | 도보/차량 | 대중교통 |
|---|---|---|
| 후보 수집 | TourAPI + haversine | TourAPI + haversine |
| 추천 목록 | 10개 추천, TMAP 경로 API 호출 0건 유지 | 10개 추천, ODsay 호출 최소화, 상위 후보 제한 |
| 상세 진입 | 선택 코스 1개만 TMAP 정밀 계산 | 선택 코스 1개만 ODsay/TAGO/지하철 보강 |
| 캐시 | 좌표쌍 24시간 TTL | OD 쌍/정류장 매칭 24시간 TTL |

현재 TMAP 경로 API 카운터는 AsyncStorage에 저장해 앱/Metro 재시작 후에도 같은 날짜 기준으로 이어서 측정한다.

## 10. 구현 순서

1. 홈 화면에 이동수단 선택 버튼 추가
2. `PlanInput.mode`를 추천 기준으로 사용
3. 도보 선택 시 차량-only 코스 제외
4. 차량 선택 시 차량 기준 반경/랭킹 적용
5. 단일 장소 여유시간 기반 2곳 코스 생성
6. 미니코스가 자연스러운 경우 상위 추천에 최소 1개 노출 시도
7. ODsay 래퍼 추가 ✅ 1차
8. 대중교통 선택 시 ODsay 총 소요시간 기반 추천 ✅ 1차
9. 대중교통 경로 최대 3가지 표시
10. TAGO 버스 도착정보 보강
11. 부산도시철도 열차시각표 보강
12. 날씨/취향/다음 일정 기반 추천 점수 확장
13. 이동수단별 자동진단 기준 분리
