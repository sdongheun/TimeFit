# TimeFit 추천 로직: 현재 흐름과 남은 과제

> 최종 갱신: 2026-08-10
> 이 문서는 현재 구현을 빠르게 이해하기 위한 요약이다. 수치·함수·변경 이력의 단일 기준은 [추천로직.md](추천로직.md)다.

## 1. 서비스가 해결하는 문제

TimeFit은 부산을 방문한 출장자나 약속 전 시간이 남은 사람이, `남은 시간 안에 들렀다가 다음 일정에 늦지 않을 수 있는 장소`를 찾도록 돕는 앱이다.

단순한 관광지 인기순 추천이나 길찾기 앱이 아니다.

```text
현재 위치 + 약속 장소 + 남은 시간 + 이동수단
        ↓
이동시간 + 체류시간 + 약속 전 안전 여유시간을 함께 계산
        ↓
시간 안에 가능한 부산 장소 후보를 지도와 장바구니로 제시
```

목표는 사용자가 한 번의 추천을 그대로 따르게 하는 것이 아니라, 근거가 있는 후보 중에서 직접 장소를 담아 자신의 자투리 코스를 완성하게 하는 것이다.

## 2. 현재 사용자 흐름

```text
1. 현재 위치를 GPS로 찾거나 직접 입력
2. 약속 장소를 카카오 장소·주소 검색으로 입력하거나 생략
3. 남은 시간(최대 240분), 현재/테스트 시각, 이동수단 선택
4. 추천 실행
5. 지도 마커 + 하단 후보 목록에서 장소 확인
6. 카카오맵 상세로 메뉴·가격·사진·후기·운영시간 확인 가능
7. 장소를 장바구니에 담으면 이동·체류·여유시간을 즉시 재계산
8. 장바구니에서 방문 순서, 장소별 이동·체류시간, 전체 구간 시간과 약속 도착 여유를 최종 확인
9. `코스 저장 후 길찾기 시작`을 누르면 코스를 자동 저장하고 바로 진행 화면에서 구간별 길찾기를 카카오맵으로 위임
```

약속 장소가 없으면 출발지로 돌아오는 왕복 기준으로 계산한다. 장바구니는 1~2곳에 고정되지 않으며, 시간 조건을 지키는 동안 3곳 이상도 담을 수 있다.

## 3. 현재 추천 흐름

```text
로컬 부산 정제 카탈로그 좌표 반경 후보 수집
  ↓
직접 매칭 85개 + 포괄 매칭 42개 + 카테고리 폴백 797개 사용
  ↓
AIHub 체류시간 또는 카테고리 체류시간 연결
  ↓
선택 이동수단 기준 시간·방향성 1차 필터
  ↓
우선순위 상위 후보의 TourAPI 운영시간 확인
  ↓
단일 장소·2곳 미니코스 생성 및 랭킹
  ↓
중복을 제거한 장소 후보를 지도와 목록으로 표시
  ↓
사용자가 장바구니에서 다장소 코스를 완성
```

### 장소 데이터와 체류시간 근거

| 후보 | 현재 사용 | 체류시간 근거 |
|---|---|---|
| 직접 매칭 | 사용 | 독립 장소의 이름+좌표 AIHub 체류시간 중앙값 |
| 포괄 매칭 | 사용 | 시장·공원·거리 등의 지역 맥락 AIHub 체류시간 중앙값 |
| 카테고리 폴백 | 사용 | TourAPI 또는 부산시 공식 데이터 장소의 같은 카테고리 AIHub 체류시간 중앙값 |
| 보류 | 미사용 | 포괄 장소 내부·동명 지점·미분류로 개별 추천 근거가 부족 |

명백한 오매칭, 카카오에서 찾을 수 없는 장소, 숙박성 장소는 후보에서 제외한다. 현재 사용 카테고리는 자연관광지, 상업지구, 레저/스포츠, 문화시설, 식당, 카페다.

## 4. 시간 판단 기준

### 안전 여유시간

| 이동수단 | 안전 여유시간 |
|---|---:|
| 도보 | 15분 |
| 대중교통 | 20분 |
| 차량 | 10분 |

```text
추천 예산 = 사용자가 입력한 남은 시간 - 이동수단별 안전 여유시간
```

이 예산 안에 `현재 위치 -> 선택 장소들 -> 약속 장소`의 이동과 체류가 들어와야 한다.

### 최소 체류와 이동 대비 체류

- 기본 최소 체류시간은 장소당 30분이다.
- 자연관광지, 거리·골목·광장·시장 성격의 상업지구는 접근 이동시간이 짧을 때만 15~20분 체류를 허용한다.
- 카페·식당·문화시설·레저/스포츠, 개별상점·아울렛은 시설형·유료 성격으로 본다.
- 시설형·유료 성격 장소는 해당 경유 때문에 추가된 이동시간보다 배정 체류시간이 짧으면 추천과 장바구니 추가에서 제외한다.
- 무료로 가볍게 구경 가능한 장소는 이동이 더 길어도 시간 예산 안이면 표시하되 순위를 낮춘다.

따라서 도보에서 억지로 먼 장소를 추천하지 않는다. 후보가 적은 상황을 최소 체류시간을 무작정 낮춰 해결하지 않는 것이 현재 원칙이다.

## 5. 이동수단별 계산과 길안내

| 수단 | 추천 단계 | 상세 단계 | 현재 한계 |
|---|---|---|---|
| 도보 | 캐시 또는 haversine 추정 | 선택 코스만 TMAP 보행 경로 정밀화 | 추천 목록의 시간은 근사값일 수 있음 |
| 차량 | 캐시 또는 haversine 추정 | 선택 코스만 TMAP 차량 경로 정밀화 | 주차는 고려하지 않음 |
| 대중교통 | 근사 후보 생성 후 상위 18개 ODsay 정밀화 | ODsay 총 소요시간·환승 요약 | 지도 선형은 역·정류장 연결 수준 |

ODsay의 정상 응답 `totalTime`에는 접근·환승 도보가 포함된다. 아주 가까운 대중교통 구간은 별도 ODsay 호출 없이 도보로 처리한다. ODsay가 실패하면 근사값으로 표시하고 순위를 감점한다.

실제 길찾기와 실시간 버스·지하철 정보는 카카오맵으로 전환해 사용자가 확인한다. TimeFit은 길안내를 대체하기보다, 길안내 전에 들를 만한 장소와 시간 여유를 계산하는 역할을 맡는다.

## 6. 현재 랭킹 기준

추천은 규칙 기반이며, 현재 순위에는 아래 요소가 반영된다.

```text
체류 여유
+ 이동 대비 체류 비율
+ 시간대 적합도
+ AIHub 매칭 신뢰도
+ 장소 간 밀집도
+ 전략·짧은 시간·지하철 보너스
- 카테고리 폴백·운영시간 신뢰도·지도 검증·우회·대중교통 폴백 감점
```

동일 카테고리가 상단을 독점하지 않도록 그리디 다양성 감점을 적용한다. 점수가 거의 같은 후보는 약하게 순환할 수 있으므로, 같은 조건으로 다시 추천해도 일부 순서가 바뀔 수 있다.

현재 `시간 활용` 값은 계산하지만 순위에는 아직 넣지 않는다. 후기 만족도도 기기 로컬에 수집만 하며, 랭킹에는 반영하지 않는다.

## 7. 현재 보장 범위와 비보장 범위

### 보장하려는 것

- 선택한 이동수단 기준으로 약속 또는 복귀까지의 시간 예산을 계산한다.
- 정제된 직접·포괄 매칭과 카테고리 폴백 후보만 사용한다.
- TourAPI 원본 ID가 있는 장소는 운영시간을 파싱해 체류 구간을 확인한다.
- 운영시간을 확인하지 못한 장소는 이를 숨기지 않고 카카오맵 상세 확인으로 넘긴다.
- 장바구니에서 코스를 바꾸면 시간 적합성을 즉시 다시 계산한다.

### 아직 보장하지 않는 것

- 실제 체류시간이 AIHub 중앙값과 정확히 일치한다는 것
- 카페·식당의 웨이팅, 주차, 혼잡도
- 모든 장소의 운영시간 정확성
- 대중교통 지도 선형이 실제 도로·선로와 일치한다는 것
- 장소의 인기, 만족도, 개인 취향에 따른 품질 순위

사용자에게는 TimeFit의 시간 계산과 카카오맵의 장소 상세·길안내를 분리해 보여주는 이유가 여기에 있다.

## 8. 자동진단과 현재 부족한 점

`scripts/audit_recommendations.ts`는 주요 부산 시나리오에서 아래 단계를 기록한다.

```text
로컬 카탈로그 반경 후보
-> 시간·방향 통과 후보
-> 운영시간 확인 후보
-> 최종 표시 후보
```

이를 통해 후보 부족이 데이터 부족인지, 시간·방향 제약인지, 운영시간 게이트 때문인지 분리해서 확인한다. 자세한 기준과 실행 방법은 [추천자동진단기준.md](추천자동진단기준.md)를 따른다.

현재 우선순위가 높은 부족한 점은 아래와 같다.

1. **장소 매력 근거 미반영**: 후기 수집은 있지만 DB와 표본 보정이 없어 추천 순위에 반영하지 못한다.
2. **후보 다양성의 지역 편차**: 공식 데이터 통합 후에도 다대포처럼 후보가 적은 지역은 시간 조건을 완화하지 않고, 별도 선별 기준으로 데이터 보강이 필요하다.
3. **시간 활용 점수의 미반영**: 사용자가 남은 시간을 얼마나 알차게 쓰는지를 랭킹에 넣을지 자동진단 결과로 판단해야 한다.
4. **운영시간 신뢰도 한계**: TourAPI에 운영시간이 없거나 파싱하지 못하는 시설형 장소가 있어 카카오맵 확인 흐름에 의존한다.
5. **지도 마커 밀집**: 현재는 개별 마커를 모두 표시하므로 후보 수가 늘면 클러스터링이 필요하다.
6. **대중교통 지도 완성도**: ODsay는 소요시간에는 유효하지만 선형 지도는 간이 표시다.
