# TimeFit MVP 시나리오

> 갱신: 2026-07-04 · **기획 재정리 v2** — 약속기반 라이프사이클(추천→실행→피드백)로 확장, 타겟 **부산 전용**.
> 이전(v1, 2026-06-15): 3화면 단발 추천. 이 문서가 최신.
> 선행: `docs/01_concept/앱컨셉.md`(컨셉), `docs/02_data/`(데이터·엔진).

---

## 0. 한 줄 정의

> **약속 전까지 비는 시간에, `(가는 시간 + 체류 시간 + 약속장소까지 이동) ≤ 비는 시간` 을 만족하는 *진짜 가능한* 미니코스를 추천하고, 수락하면 경로·알림으로 끝까지 안내한 뒤, 피드백으로 점점 맞춤화한다.**

단순 근처 추천이 아니라 **현재 ↔ 다음 약속 사이 빈 시간에 끼울 수 있는가**의 계산. 타겟 지역 = **부산**.

## 1. 전체 라이프사이클 플로우차트 ⭐

```
1. 입력   (게스트 OK — 로그인 불필요)
          • 다음 약속: [시각] + [장소]  ← 선택
              - 있으면 → "약속 경유" 모드
              - 없으면 → "남은시간 직접입력 + 현재위치 왕복" 모드
          • 현재 위치(GPS) · 이동수단 · 핵심필터 1~2개
   │
   ▼  시간-적합 계산 엔진(planTimeFit)
2. 추천   여러 코스 후보(시간 적응형) — 모든 사용자 동일 로직(개인화 없음)
          • 카드: 코스명 · [이동+체류+복귀 분해] · "왜 가능한지" · 지도썸네일
          • 점진 필터칩 [예산][활동][분위기] → 즉시 재필터
   │
   ▼  카드 선택 → 상세 확인 → [이 코스로 갈래요]
3. 수락   여기서 로그인·설문 유도 (알림/개인화 위해)
   │
   ▼
4. 실행   • 경로: 현재 → 장소1 → (장소2) → 약속장소  (지도 + 구간별 소요)
          • 로컬 알림(시각 기반): "14:40 다음 장소 이동" / "15:10 약속장소로 출발"
   │
   ▼  코스 종료
5. 피드백  완료 설문(만족도·실제 체류·재방문 의향) → 축적 → **개인화는 여기서만** 이뤄짐
          (누적된 피드백이 다음 추천을 점점 맞춤화. 입력/추천 단계엔 개인화 없음)
```

**설계 원칙 — 즉시성 우선:** ①②는 **로그인 없이** 작동한다. 로그인·설문은 ③ 수락 이후(알림·개인화가 필요한 시점)에 유도한다. 추천의 전제조건이 로그인이 되어선 안 된다.

## 2. 확정된 MVP 결정

| 항목 | 결정 | 비고 |
|---|---|---|
| **타겟 지역** | **부산 전용** | 동부권 AI-Hub 데이터와 정합. 전국/타지역은 post-MVP |
| 다음 약속 | **선택 입력**(시각+장소) | 입력 시 *약속장소 경유*, 미입력 시 *현재위치 왕복* |
| 현재위치≠약속장소 | **편도 경유**(현재→코스→약속장소) | 같으면 왕복. "돌아온다"=경로 종점이 약속장소 |
| 시간 파악 | 약속시각 or 남은시간 **수동 입력** | 캘린더 연동 post-MVP |
| 로그인 | **선택 · 추천엔 불필요** | 알림/개인화 위해 ③에서 유도 (게스트 추천 항상 가능) |
| 추천 출력 | **여러 코스 후보**(2~3개) 시간 적응형 | |
| 코스 구성 | ≤60분 1곳 / 60~150분 2곳 / >150분 2~3곳+식사 | |
| 필터 | 핵심(이동수단·예산) 먼저 + 결과칩 점진(활동·분위기) | |
| **알림** | **코스 수락 시 계산된 출발예정시각 기반 로컬 알림** | 실시간 GPS 추적 재계산은 Phase 2 |
| **개인화** | **완료 피드백에서만** — 입력·추천 단계엔 개인화 없음(모두 동일 추천) | 누적 피드백이 다음 추천을 점진 맞춤화 |

## 3. 화면 구성 (4~5 스텝)

```
[입력]   약속(시각+장소, 선택) · 남은시간 · 현재위치(GPS) · 이동수단 · 핵심필터   →[추천받기]
   ↓  planTimeFit (TourAPI 후보 → 체류(JSON)+선택 이동수단 시간+운영시간 게이트)
[추천]   선택 이동수단 기준 코스 후보 카드 + 점진 필터칩[예산][활동][분위기]      →카드 선택
   ↓
[상세]   선택 코스 1개만 정밀 경로 계산 + 장소별(체류·운영시간·이유)            →[이 코스로 갈래요]
   ↓  (로그인·설문 유도)
[실행]   경로 지도 + 구간별 소요 + 출발예정시각 로컬 알림 예약
   ↓  종료
[피드백] 완료 설문 → 개인화 축적
```

## 4. 구체 시나리오 예시 (부산)

### 예시 A — 약속 경유 (서면 카페 약속, 자차)
- **입력:** 현재 부산역 / 다음 약속 **15:00 서면** / 지금 13:00(=120분) / 자차
- **계산:** (부산역→코스 + 체류 + 코스→서면) ≤ 120분 − 버퍼(~15분). *서면 가는 길*에 낄 곳 최적화
- **추천(60~150분 → 2곳):**
  - 후보1: 부산근대역사관(체류 40분) + 광복로 거리(30분), 이동 합 30분 = **100분** ✅ "15:00 서면 도착 여유 5분"
  - 후보2: 단일 — 국제시장 구경(60분), 경유 이동 40분 = 100분 ✅
- **실행:** 부산역→역사관→광복로→서면 경로 + "14:10 광복로 이동", "14:35 서면으로 출발" 알림

### 예시 B — 약속 없음·왕복 (서면, 90분)
- **입력:** 현재 서면 / 약속 미입력 / 남은 90분 직접입력 / 도보
- **계산:** (도보 이동 + 체류 + 도보 복귀) ≤ 90분 − 버퍼
- **추천(왕복, 미니코스 2곳):**
  - 후보1: 전포 카페거리 산책(40분) + 전망카페(30분), 이동 15분 = **85분** ✅
  - 후보2(필터 '무료'): 부산시민공원 산책 70분

> POI·체류시간: `src/data/busan_poi_catalog.json`의 직접 매칭 체류시간 + 카테고리 폴백 체류시간. 이동: 도보/차량은 TMAP+haversine, 대중교통은 ODsay 기반. 운영시간: TourAPI 라이브.

## 5. 시간-적합 계산 (엔진 요약)

```
후보 가능? = 이동시간[TMAP] 이후 최소 30분 이상 체류 가능 + 운영시간게이트[TourAPI]
            + 코스→약속장소 이동 (미입력 시 현재위치로 복귀)
          ≤ (약속시각 − 현재시각)  −  안전버퍼(10~15%)
```
- 운영시간 게이트: "머무는 동안 계속 열려 있나" (TourAPI usetime, 90~100% 실측)
- 데이터 정직성: 체류시간은 자기보고 어림값 → **범위(p25~p75)·버퍼**로 제시, 확정값처럼 쓰지 않음
- 코스 설명·큐레이션: LLM(Claude, 서버 프록시) — Phase 2

## 6. 필터 & 개인화

| 필터 | 값(예) | 단계 |
|---|---|---|
| **이동수단** | 도보 / 대중교통 / 자차 | 핵심(입력) — 계산 직결 |
| **예산** | 무료 / 저렴 / 상관없음 | 핵심 or 결과칩 |
| 활동유형 | 먹기 / 보기 / 걷기 / 체험 / 쉬기 | 결과칩(점진) |
| 분위기 | 자연 / 도심 / 문화 | 결과칩(점진) |

**개인화(MVP):** 입력·추천 단계엔 개인화 없음 — 모든 사용자가 같은 시간-적합 추천을 받는다. 개인화는 **⑤ 완료 피드백에서만** 발생: 만족도·실제체류·재방문 의향을 축적해 다음 추천을 점진적으로 맞춤화한다. 콜드스타트(첫 사용)엔 순수 시간-적합 추천이 그대로 동작.

## 7. MVP 범위

**포함:** 부산 전용 · 약속(선택,시각+장소) 또는 남은시간 수동입력 · GPS 현재위치 · 약속장소 경유/왕복 · TourAPI 후보 · 시간-적합 계산(체류JSON+TMAP+운영시간) · 여러 코스 후보(시간적응형) · 핵심+점진 필터 · 코스 수락 · 경로 안내 · **출발예정시각 로컬 알림** · **완료 피드백 설문(개인화 축적)** · (로그인은 선택)

**제외(post-MVP):** 캘린더 연동 · 실시간 GPS 추적 기반 동적 재계산 · 실시간 혼잡/대기시간 · 전국/타지역 · **입력·추천 단계 개인화(프리셋 포함)** · LLM 코스설명(Phase 2) · 예약/네비 연동

## 8. 현재 구현 상태 대비 (2026-07-04)

| 라이프사이클 | 상태 |
|---|---|
| ① 입력(남은시간·GPS·직접 위치·테스트시각) | ✅ 구현 |
| ① 약속 장소 입력 | ✅ 구현 — TMAP 장소/주소 검색 |
| ① 이동수단 선택 | 🟠 재정리 필요 — 도보/대중교통/차량 버튼과 수단별 추천 분리 예정 |
| ② 추천(코스 후보·점진 필터칩) | ✅ 구현 |
| ③ 수락 · 로그인/설문 | ⬜ 미구현 |
| ④ 실행(경로·알림) | ⬜ 미구현 (지도는 상세에 직선 placeholder) |
| ⑤ 피드백(완료 설문·개인화) | ⬜ 미구현 |
