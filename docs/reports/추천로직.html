핵심 원칙

결과의 기본 단위는 완성 코스가 아니라 장소 후보입니다.
사용자는 후보를 장바구니에 담고, TimeFit은 선택이 바뀔 때마다 이동·체류·약속 도착 여유를 다시 계산합니다.

1순위: 약속 지연 방지

선택한 이동수단으로 이동하고 최소 체류시간을 확보한 뒤, 안전 여유시간을 남기고 약속 장소에 도착하거나 출발지로 복귀할 수 있어야 합니다.

2순위: 설명 가능한 랭킹

체류 여유, 이동 대비 체류, 시간대 적합도, AIHub 매칭 신뢰도, 장소 간 밀집도와 카테고리 다양성을 점수화합니다.

사용자 확인의 역할

운영시간·메뉴·가격·사진·후기는 카카오맵 상세 링크에서 확인합니다. 앱은 이를 확인하지 못했을 때 영업 중이라고 단정하지 않습니다.

운영시간 미확인은 A/B 후보의 일괄 제외 사유가 아닙니다. 운영시간을 파싱할 수 있을 때만 게이트로 사용하고, 그렇지 않으면 카카오맵 상세 확인으로 연결합니다.

최소 체류시간

기본 시설형 장소

카페, 식당, 문화시설, 레저/스포츠, 개별 상점·아울렛은 기본 30분입니다.

가볍게 둘러보는 장소

자연관광지와 거리·골목·광장·시장 성격의 상업지구는 접근 시간이 10분 이하면 15분, 11~15분이면 20분, 16분 이상이면 30분입니다.

이동 대비 체류 판단

  • 약속지까지 원래 가야 하는 이동시간은 불이익으로 계산하지 않습니다.
  • 시설형·유료 성격 장소는 경유로 추가된 이동시간보다 배정 체류시간이 짧으면 추천과 장바구니 추가에서 제외합니다.
  • 자연·거리·광장 등은 최소 체류시간만 충족하면 표시합니다. 추가 이동이 더 길면 제외하지 않고 순위만 낮춥니다.

추천 파이프라인

예산 계산
입력한 남은 시간에서 이동수단별 안전 여유시간을 빼고, 약속 장소 또는 복귀 지점을 목표로 정합니다.
후보 수집
TourAPI locationBasedList2에서 이동수단·남은시간별 반경으로 모읍니다. 중심당 최대 60건이며, 부산 A/B 카탈로그 contentId만 통과합니다.
1차 컷
선택 수단 기준 최소 체류시간과 방향성(우회율)을 만족하는 후보만 통과합니다. 원시 후보 수와 통과 수를 자동진단에 남깁니다.
운영시간·축제 게이트
상위 후보만 TourAPI 상세를 확인합니다. 운영시간을 파싱할 수 있으면 체류 구간을 확인하고, 축제는 행사 기간이 필수입니다.
코스 조립
경로 API를 호출하지 않고 캐시 또는 haversine 근사로 단일 장소와 2곳 미니코스의 이동 부담·우회율·체류 적합성을 판단합니다.
랭킹과 다양성
점수화한 뒤 상위 24개 대기열에서 동일 카테고리가 반복되지 않도록 완만하게 재배치합니다.
지연 정밀화와 출력
도보·차량 추천 목록은 TMAP 0건을 유지합니다. 대중교통은 상위 후보만 ODsay로 정밀화·재랭킹하고, 화면에서는 중복을 제거한 장소 후보를 보여줍니다.

랭킹 v1: 결정적이고 설명 가능한 점수

30%체류 여유
20%이동 대비 체류
20%시간대 적합도
15%AIHub 매칭 신뢰도
15%장소 간 밀집도
기본 점수 = 0.30 × min(1, 체류 가능 시간 / 60) + 0.20 × 체류시간 / (이동시간 + 체류시간) + 0.20 × 시간대 적합도 + 0.15 × AIHub 매칭 신뢰도 + 0.15 × 장소 간 밀집도 + 전략·짧은 시간·지하철 보너스 - 카테고리 폴백·운영시간 신뢰도·지도 검증·우회·대중교통 폴백 감점 그리디 다양성: 이미 선택된 동일 카테고리당 -0.15 약한 순환: 점수 차이 0.035 이내 후보만

시간 활용률 (이동시간 + 체류시간) / budget은 현재 계산만 하며 최종 점수에는 반영하지 않습니다.

지도·장바구니에서의 재계산

후보 지도

현재 위치·약속 장소·시간 조건을 통과한 후보 마커를 표시합니다. 지도에 있는 모든 후보가 강한 자동 추천이라는 뜻은 아닙니다.

장바구니 추가

첫 장소부터 origin → 담은 장소들 → target 전체를 다시 계산합니다. 추가 불가 후보는 시간 초과와 부족 사유를 보이고 추가를 막습니다.

방문 순서

초기 순서는 이동시간이 짧은 순서로 제안합니다. 사용자는 순서를 바꾸거나 최적 순서 정렬을 실행할 수 있으며, 매번 시간 적합성을 다시 확인합니다.

  • 장소 수는 1~2곳으로 고정하지 않습니다. 시간 조건을 통과하는 동안 3곳 이상도 담을 수 있습니다.
  • 같은 입력에서 같은 장소가 재표시될 수 있습니다. 다만 점수가 매우 가까운 후보는 약하게 순환하고, 지도·필터·장바구니로 사용자가 탐색합니다.
  • 실제 길안내와 실시간 버스·지하철 정보는 카카오맵에 위임합니다.

보장 범위와 남은 약점

항목상태현재 의미
수단별 반경·안전 여유시간해결도보·차량·대중교통의 후보 범위와 시간 제약을 분리
약속 반대 방향 후보해결직행 대비 우회율 1.8배 이상은 게이트 전 제외, 그 이하는 부드럽게 감점
카카오맵 상세 연결해결추천 가능 장소의 정확한 Place ID 또는 상세 URL로 연결
3곳 이상 장바구니해결자동·수동 순서 변경과 즉시 재계산 지원
장소 매력수집 기반만 있음로컬 후기 수집은 구현됐으나, 표본 수와 보정 규칙을 정한 뒤에만 랭킹에 반영
취향 칩 랭킹 반영진행 예정현재는 사후 필터 성격이며, 선택 카테고리 가점으로 승격 필요
체류시간 폴백 세분화백로그카테고리 중앙값만으로는 장소 성격 차이를 충분히 설명하기 어려움
정확도 경계
도보·차량 이동시간은 선택 코스 상세에서 TMAP 실경로로 정밀화합니다. 추천 목록 단계는 API 호출을 아끼기 위해 캐시·거리 근사값을 사용합니다. 운영시간이 미확인인 장소의 영업 여부는 사용자가 카카오맵에서 최종 확인합니다.

다음 개선 순서

  1. 시간 활용 점수 반영 여부 결정: 체류 여유 점수만으로 충분한지 자동진단 결과를 기준으로 판단
  2. 후기 기반 장소 매력 반영: DB 도입 후 최소 표본 수와 평점 보정 규칙을 확정한 뒤 2순위 랭킹 요소로 추가
  3. 지도 마커 클러스터링: 후보 데이터가 늘어 마커가 실제로 겹치는 시점에만 추가
