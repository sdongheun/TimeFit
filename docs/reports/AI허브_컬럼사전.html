이 데이터의 성격 — RESIDENCE_TIME_MIN은 여행자가 30분 단위로 자기보고한 추정 체류시간(타임스탬프 계산값 아님). 개별값은 거칠지만, 표본을 모아 중앙값을 내면 장소별 전형적 체류의 신호가 남습니다. 그래서 확정값이 아니라 어림값(+버퍼)으로 씁니다.

1tn_visit_area_info (방문지정보) — 메인 소스

체류시간·카테고리·좌표·POI명이 모두 여기서 나옵니다. 전체 23개 컬럼 중 8개만 사용.

3tn_move_his (이동내역) — 혼잡도 보조

방문지 도착 시각을 얻어 "요일 × 시간대" 혼잡 배수를 만드는 데만 씁니다.

컬럼의미사용예시값어디에 쓰나
TRAVEL_ID + END_VISIT_AREA_ID여행 + 도착 방문지 ✔ 복합키e_e000003 | 2304… 방문지정보와 조인하는 키
END_DT_MIN도착 일시 ✔2023-04-30 14:30 시(hour) 추출 → 시간대 버킷
START_DT_MIN·MVMN_CD_1/2·TRIP_ID 출발시각·이동수단코드 ✘ 미사용— 이동시간은 TMAP이 담당(이 데이터 아님)
복합키 주의 — VISIT_AREA_ID는 여행 내 순번이라 여행자끼리 겹칩니다. 반드시 TRAVEL_ID | VISIT_AREA_ID 복합키로 조인해야 함. (단독 조인 시 도착시각 매핑 1,877건 → 복합키로 30,048건, 테스트가 이 버그를 잡음)

📅 dayType (VISIT_START_YMD)

방문 날짜의 요일 → 평일 / 주말(토·일).
카테고리 × 요일 × 시간대별 도착 빈도 → 혼잡 배수 0.8~1.8로 정규화.

5산출물 — 앱 번들 JSON (data/processed/)

위 컬럼들이 build_dwell.mjs를 거쳐 3개 파일로 집계됩니다. 앱은 원본 CSV가 아니라 이 집계값만 내장.

6데이터 흐름 한눈에

CSV 원본 집계(build_dwell.mjs) 앱 번들 ───────────── ────────────────── ────────── tn_visit_area_info RESIDENCE_TIME_MIN ─┐ VISIT_AREA_TYPE_CD ─┼─▶ 카테고리별 중앙값/분위수 ─▶ 카테고리별_체류시간.json VISIT_AREA_NM ─┤ POI별 중앙값(표본≥5) ─▶ poi_dwell.json X/Y_COORD ─┘ │ 복합키(TRAVEL_ID|VISIT_AREA_ID) ▼ tn_move_his END_DT_MIN ─────▶ 요일×시간대 혼잡 배수 ─▶ congestion_matrix.json 런타임: 유효체류 = 중앙값(POI 우선→카테고리) × 혼잡배수 → 시간-적합 판정
