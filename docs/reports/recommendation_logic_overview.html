TimeFit 추천 로직 현재 흐름과 부족한 점

작성일: 2026-07-26 · 기준 코드: src/engine/planner.ts, src/engine/travel.ts

1. 핵심 요약

TimeFit은 사용자의 현재 위치, 약속 장소, 남은 시간, 이동수단을 받아서 이동시간을 제외하고 자투리 시간에 의미 있게 머물 수 있는 부산 장소 코스를 추천한다.

TourAPI 장소 AI-Hub 체류시간 TMAP 도보/차량 ODsay 대중교통 최대 10개 추천

2. 전체 흐름

입력현재 위치, 약속 장소, 남은 시간, 이동수단을 받는다.
예산 계산남은 시간에서 buffer를 빼 실제 추천에 쓸 budget을 만든다.
후보 수집출발지, 약속지, 중간 지점 주변 TourAPI 장소를 모은다.
데이터 매칭busan_poi_catalog에 있는 부산 장소만 통과시킨다.
체류시간 부여AI-Hub 직접 매칭 또는 카테고리 중앙값을 사용한다.
시간 필터선택 이동수단 기준 카테고리별 최소 체류시간 이상 머물 수 있어야 한다.
코스 조립단일 장소 또는 2곳 미니코스를 만든다.
랭킹체류 가능 시간, 시간대, 신뢰도, 동선 효율 등을 점수화한다.
정밀화대중교통은 ODsay로 상위 후보를 다시 계산하고 재랭킹한다.
출력최종 추천 10개와 대기열을 보여준다.

3. 시간 계산

buffer = max(10분, 남은 시간 * 12%)
budget = 남은 시간 - buffer

추천 가능 조건:
선택 이동수단 기준 체류 가능 시간 >= 카테고리별 최소 체류시간

예를 들어 사용자가 120분을 입력하면 약 14분을 여유 시간으로 빼고, 106분 안에서 이동과 체류가 모두 가능해야 한다.

상황카테고리최소 체류시간
남은 시간 60분 이하카페, 상업지구20분
남은 시간 60분 이하문화시설, 자연관광지25분
남은 시간 90분 이하카페, 상업지구25분
그 외 단일 장소모든 카테고리30분
2곳 미니코스모든 조합30분

4. 숫자로 보는 추천 예시

다른 사람이 봐도 이해하기 쉽도록, 실제 추천이 어떤 계산으로 만들어지는지 예시로 정리하면 아래와 같다.

사용자 입력 현재 위치: 서면역
약속 장소: 사상역
남은 시간: 120분
이동수단: 대중교통
사용 가능 시간 계산 buffer = max(10분, 120분 × 12%) = 14분
budget = 120분 - 14분 = 106분
이동시간 계산 서면역 → 놀이마루: 6분
놀이마루 → 사상역: 22분
총 이동시간: 28분
체류 가능 시간 체류 가능 시간 = budget - 총 이동시간
106분 - 28분 = 78분
따라서 약 78분 머물 수 있음 
AI-Hub 기준 체류시간 = 이 장소를 보통 어느 정도 머무는지에 대한 기준값
체류 가능 시간 = 사용자가 이번 상황에서 실제로 머물 수 있는 시간

예:
놀이마루 AI-Hub 기준 체류시간: 40분
사용자 체류 가능 시간: 78분

판단:
최소 30분 이상 머물 수 있고,
AI-Hub 기준 체류시간도 충분히 소화 가능하므로 추천 가능

중요한 점은 AI-Hub 체류시간을 반드시 정확히 채워야 추천하는 구조가 아니라는 것이다. TimeFit은 사용자가 입력한 시간에서 이동시간을 뺀 뒤, 실제로 머물 수 있는 시간이 충분한지를 먼저 본다. AI-Hub 체류시간은 그 장소가 그 시간 안에 적절한지 판단하는 기준값으로 사용한다.

5. 후보 장소와 체류시간

구분의미체류시간 근거신뢰도
matchedTourAPI 장소와 AI-Hub 장소가 매칭됨해당 장소 AI-Hub 체류시간상대적으로 높음. 단, 좌표 기반 저신뢰 매칭은 제외
unmatchedTourAPI에는 있지만 AI-Hub 직접 매칭 안 됨카테고리 중앙값중간 이하
 
저신뢰 제외 예시:
TourAPI title = 그런고로
AI-Hub name = 포셋 전포점
matchType = coord
matchDistanceM = 97m
dwell count = 3
TourAPI category = 자연관광지
AI-Hub category = 상업지구

현재 추천 후보에는 문화시설, 자연관광지, 상업지구, 레저/스포츠, 식당, 카페, 지역축제/행사가 포함될 수 있다. 레저/스포츠는 예약·장비·장시간 체험 장소를 제외하고 10개만 유지한다.

레저/스포츠 유지장소
matched광안리 해양레포츠센터, 미포정거장, 송도 구름산책로
unmatched구포무장애숲길, 문탠로드, 부산광역시 부산실내빙상장, 삼락강변체육공원인라인스케이트장, 송도해안볼레길, 해안누리길 몰운대길, 회동수원지 둘레길
제외 보관data/processed/부산_제외_레저스포츠.json에 29개 보관

6. 위치 전략

출발지 근처현재 위치 주변에서 시간을 보내고 약속 장소로 이동한다.
약속지 근처먼저 약속 장소 근처로 가서 시간을 보낸다.
가는 길 중간출발지와 약속 장소 사이에서 들를 장소를 찾는다.

9. 현재 강점

시간 계산이 핵심남은 시간에서 이동시간을 빼고 체류 가능 시간을 계산한다.
다음 일정 고려약속 장소가 있으면 최종 도착지로 넣고 판단한다.
이동수단 분리도보, 차량, 대중교통 추천 기준이 분리되어 있다.
대중교통 API 사용상위 후보군은 ODsay로 실제 대중교통 시간을 확인한다.
자동진단추천 결과를 스크립트로 점검할 수 있다.

10. 부족한 점

부족한 점현재 문제개선 방향
장소 품질 점수시간상 가능하면 애매한 장소도 추천될 수 있음AI-Hub 만족도, 재방문 의향, 이미지/소개 유무 반영
사용자 취향사용자마다 거의 같은 추천이 나옴카페, 산책, 쇼핑, 문화 등 취향 칩 반영
음식점/카페 규칙웨이팅, 식사 시간대, 약속 전 적합성 판단이 약함점심/저녁 가점, 약속 직전 식당 감점
지도 검색 존재 검증카카오맵에서 검색되지 않는 장소가 섞이면 신뢰가 떨어짐Kakao Local API로 title+좌표 검증 후 제외/감점
운영시간 신뢰도TourAPI 운영시간이 비거나 복잡한 문구일 수 있음브레이크타임, 요일별 운영, 점포별 상이 문구를 파싱/감점 처리
상업지구 세분화시장, 거리, 백화점, 쇼핑몰이 한 카테고리에 섞임matched 상업지구 18개에 전통시장/전문상가/개별상점/아울렛/백화점·쇼핑몰/거리·골목상권 반영 완료
AI-Hub 매칭 신뢰도좌표 기반 매칭은 실제 장소가 다를 수 있음direct/area_context/category_fallback/bad_match로 분리하고, bad_match만 제외
카테고리 폴백unmatched는 넓은 카테고리 중앙값만 사용세부 카테고리별 체류시간 중앙값으로 개선
경로 전략출발지/약속지/중간 전략 점수가 단순함남은 시간, 수단, 환승역, 우회율 기반 전략 강화
2곳 코스 조합시간과 거리만 보면 조합이 어색할 수 있음카페+산책, 시장+카페, 문화시설+카페 같은 자연 조합 가점
목록 이동시간도보/차량 목록 단계는 haversine 추정값상위 3개 정밀계산 또는 예상값 문구 명확화
날씨/실내외비·폭염·추위가 추천에 반영되지 않음날씨 API와 실내/실외 가중치 적용
후보 부족 대응1시간 이하에서 추천 수가 부족할 수 있음짧은 시간 모드, 카페/상업지구 보강, 최소 체류 기준 단계 완화
대중교통 geometry역/정류장 간이 polyline, 실제 노선 모양은 아님OSM/Overpass 또는 공공 노선 데이터 후속 검토
검증 데이터좋은 추천/나쁜 추천의 기준 샘플이 부족함대표 시나리오 5~10개 수동 검증 세트 구축

11. 매칭 신뢰도 기준

구분의미추천 처리
direct_placeTourAPI와 AI-Hub가 같은 장소로 볼 수 있음감점 없음
area_context시장, 거리, 골목, 상권처럼 같은 생활권 맥락을 빌려 쓰는 매칭추천 허용, 약한 감점
category_fallbackAI-Hub 직접 매칭 없이 카테고리 중앙값을 사용추천 허용, 중간 감점
bad_match좌표만 가까울 뿐 실제로 다른 장소일 가능성이 큼추천 제외
현재 matched 분포direct_place 67개 · area_context 13개 · bad_match 42개
유연한 추천bad_match만 강하게 제외하고, area_context와 category_fallback은 후보로 유지한다.
출처 분리체류시간은 AI-Hub 출처, 운영시간은 TourAPI 장소 출처를 별도로 기록한다.

12. 정확도 개선 백로그

순서작업왜 중요한가완료 기준
1카카오맵 장소 존재 검증검색되지 않는 장소 추천은 신뢰를 크게 떨어뜨림카카오 Local 검색 결과가 없는 POI는 제외 또는 강한 감점
2운영시간 파서 고도화식당/카페/문화시설은 실제로 열려 있는지가 핵심요일별 운영, 브레이크타임, 라스트오더, 시설별 상이 문구 처리
3 상업지구 세부 규칙같은 카테고리 안에서도 자투리 적합성이 크게 다름matched 상업지구 수동 검토와 subCategory 반영 완료
3-1 문화시설·식당·카페 세부 규칙상업지구 외 카테고리도 세부 유형 차이가 큼공연장/전시관, 식사/카페 규칙 분리 필요
4 매칭/폴백 신뢰도 점수화직접 매칭과 카테고리 폴백의 정확도가 다름direct_place, area_context, category_fallback, bad_match 반영
5자연스러운 2곳 코스 조합두 장소가 가능해도 사용자가 보기엔 어색할 수 있음카페+산책, 시장+카페, 문화시설+카페 조합 가점과 부자연 조합 감점
6카페 후보 보강1시간 자투리에서 가장 유용한 카테고리지만 현재 수가 적음서면/해운대/부산역 등 주요 지점에서 짧은 시간 추천 수 확보
7상위 후보 정밀 이동시간 계산목록 단계 추정값과 실제 경로 차이를 줄여야 함호출량 한도 안에서 상위 3개 정도만 정밀계산하거나 상세 전 예상 표시
8날씨/실내외 반영공모전 차별화와 실제 사용성을 높임비/폭염/추위에는 실내 가점, 실외 장거리 도보 감점
9사용자 취향 칩개인화가 없으면 같은 추천만 반복됨카페, 산책, 쇼핑, 전시, 조용한 곳 선호를 점수에 반영
10추천 실패 대응후보가 적으면 앱이 빈약해 보임후보 부족 시 짧은 체류 안내 모드와 완화 규칙 자동 적용

13. 추천 정확도 현재 평가

영역현재 수준이유
시간 안에 가능한지중상이동시간과 체류가능시간을 budget 안에서 계산함
도보/차량 이동시간중목록은 추정, 상세는 TMAP 정밀화 가능
대중교통 이동시간중상ODsay 성공 구간은 신뢰 가능, fallback은 낮음
대중교통 지도 경로중역/정류장 간이 polyline
체류시간중direct_place는 신뢰도가 높고, area_context/category_fallback은 감점해 사용함
운영시간 안정성중direct/area_uncertain/unknown으로 나눠 점수에 반영하지만 파싱은 아직 약함
장소 품질낮음~중만족도, 재방문 의향, 인기도 반영이 약함
개인화낮음사용자 취향 입력이 없음
